# Chunk 585 -- lessons from the authoring agent (fold into GOTCHAS at landing)

- TU-local `static __declspec(noinline)` + a visible same-TU caller at plain /O2 -> VC7.1 gives the static a private register convention (mdct_butterfly_first 0x00C9C1E0: x in edi, points in ecx, T in edx) and it MATCHES without /GL. This contradicts GOTCHAS ("libvorbis statics are LTCG-private ... park as lane gaps on sight", 0x00C8F200); retry those parked libvorbis statics with their real caller in the TU.
- VC7.1 has no NRVO: `return a*h1 + b*h2 + ...;` of a class with a user copy ctor stores x early (267v265); `C3DVector result = ...; return result;` matches (GetSplinePosition 0x00B177C0).
- VC7.1 canonicalises x87 operand order (source `a*b` vs `b*a` is irrelevant), but the declaration order of float locals fixes the load order of the products (SetFromVectorAndAngle 0x00C1D0B0, CalcObjectMatrix 0x00BEBAA0): declare each product local separately, in retail load order.
- STLport `_M_insert_overflow` with plain `inline __fastcall __uninitialized_copy` -> retail's split (the prefix copy inlined, the suffix copy out of line, 0x00BCDB70 -> 0x00BCD8A0). Use same-TU noinline bodies only when retail homes the `__false_type` temporaries on a live argument slot (0x00AF7460).
- STLport `vector::operator=` with the element helpers declared only (no bodies) still homes the empty tags on the dead `__x` slot when `_M_allocate_and_copy` and `__copy_ptrs` are inline (0x00AE7FE0, first grade). The same-TU-noinline-body rule of 0x00AE6690 applies only when `__copy_ptrs` itself is out of line.
- VC7.1 shrink-wraps callee-saved registers: a `pop esi` right after esi's last use, mid-function. Retail 0x00BEBAA0 keeps esi to the epilogue, and no source form tried reproduces that (parked, 255v257).
