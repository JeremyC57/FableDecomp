## Verify and restore

1. Run `python3 verify_handoff.py` from this extracted directory. It checks every included file against SHA256SUMS.
2. For one selected row, run `python3 materialize_headers.py 00a86110 --output include_00a86110`. Substitute the desired address. It combines original hdr/base with the exact selected immutable overlay, verifying every header hash. Use a fresh empty output directory.
3. For an old attempt, add `--attempt 7`. Its candidate lives in history/<address>/attempt_07/candidate.cpp. These are rejected experiments unless independently reselected; some failed to compile or violate rules corrected later. Historical annotations are not new authorization.
4. Compile the selected production source with your own MSVC7.1 RTM cl13.10.3077: `/nologo /c /O2 /Oy /W3`, the exact additional flags in rows/<address>/SELECTED_GRADE.json, and the materialized include directory before the compiler's standard headers. No compiler or Wine installation is supplied. Do not compile against only the current shared hdr tree: a parked row may require its recorded private overlay.
5. Cut the authorized extent from your own Fable.exe, compare the entire target with relocated operands masked, then verify every relocation's one retail address and exact original symbol. Recheck original class keys, access, qualifiers, template identity, CRT scalar/array/free thunks, literal identity and internal jump-table destinations. A matching byte extent alone does not settle a name.
6. Build/run the standalone rows/<address>/<address>_test.cpp under GNU64 C++03/noRTTI and real VC7.1 /GR-. Each prints exactly `<address>_TEST PASS`. Existing behavior_tests histories retain actual build/run logs and hash-bound results. A behavior pass does not establish byte parity. Most fixtures use GNU `-std=c++03 -pedantic-errors -fno-rtti` and VC `/Od /GR-`; row00a68de0 additionally uses GNU `-fpack-struct=1` and VC `/Zp1`, recorded in its result. Check each fixture's own historical options.
