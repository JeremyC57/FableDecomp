# Retry 9 lessons (formulations that turned a DIFFER into a match)

- **Inline `operator==("")` with two returns materialises `sete`** (0048f7c0, 0048f881, 008973a0 -- the chunk 188 gap): retail branches straight off the strcmp intrinsic / block compare because the empty test is written in the caller as two separate tests that `goto` the empty arm (`if (s.PStringData == 0) { if (strcmp("", "") == 0) goto empty; } else if (s.PStringData->Data == "") goto empty;`), with the non-empty arm falling through and the empty arm after a `return`. The default tag passed to a `const CWideString&` parameter is an implicit conversion (`GetTextFromTextTag(s_Default, ...)`), built before the other arguments and re-addressed with `lea`.
- **Base pointer kept across a call instead of a folded field address** (00e24100): when retail copies a global pointer to a callee-saved register before a call and reads `[reg+N]` after it, while the lane emits `lea reg,[eax+N] ; fcomp [reg]`, read the global directly for the pre-call test and declare a block-local copy (`CScriptDef* def = g_pScriptDef;`) INSIDE that test's block for the post-call read; one local covering both reads colours the pair the other way (def edi / parameter ebx).
- **Counted member pointer loaded straight into the dead `this` register** (00a6c900): retail `mov ecx,[ecx+0B4h] ... test ecx,ecx ... call [eax+4]` before a sum's lea chain is a CCountedPointer member read through an inline `IsValid()` and inline `operator->`; a raw pointer member tested with `if (p)` loads into eax after the chain and copies to ecx (the 24a "member pointer used as this through an inline accessor" rule, with the null test also through an accessor).
- **x87 add operand order through an inline member operator vs the body** (00853580): `v += inc` through an inline `C3DVector::operator+=` always loads the `this` member first (`fld pos ; fadd inc`) whatever the spelling inside the operator; writing the three component sums in the caller's body (`LookAtPos.X = LookAtIncrement.X + LookAtPos.X;`, either operand order) gives retail's `fld inc ; fadd pos ; fstp pos`.
- **Keep a run of constant member stores together** (00878ce0): three separate `ZAxis.X = 0; ZAxis.Y = 0; ZAxis.Z = 1;` assignments get scheduled into the following struct copy's stores by VC7.1 (any order, chained, before or after the other statements); an inline `ZAxis.Set(0.0f, 0.0f, 1.0f)` member keeps them as one group ahead of the copy's `lea`.
- **A store through a computed `bool*` cannot be reordered** (00487cf0): clearing a flag through `(bool*)&pad[N]` is a may-alias store, so the lane could not hoist the following World load above it and the store sank below the camera loads; writing it as a real member (`reinterpret_cast<CPlayerRetailFlags*>(this)->InitialPlayerModeSet = false;`) BEFORE the camera expression lets VC7.1 hoist the World load above the byte store, as retail.

## Compiler-build gaps stated precisely (retry 9 probes)
- **Inline expansion count is banded by callee cost, and the band edge differs between retail and the lane.** VC7.1 expands an inline callee at every call site while its post-front-end, pre-DSE cost is below a threshold, exactly once (the block-end site first, the early-return site then calls the out-of-line copy) in the next band, and never above it (0066bd00 probes: +1 null-tested free or a dead member store -> once; +1 element loop -> never; nested inline layers, trait-tag arguments, dead size arguments, a split base dtor, caller size and earlier expansions in the TU change nothing). Retail's ~CScriptThing (00d17090, 00e32200) and vector<CCharString>::~vector (0066bd00) sit in the once band with bodies that are byte-identical to ours, which the lane keeps in the always band: the DDK QFE-4035 inliner's once band starts at a higher cost than the retail RTM compiler's. A dead member store moves a dtor into the once band and reproduces retail's site assignment and length (0066bd00 231v231), but is not faithful to the out-of-line copy.
- **x87 operand rank**: the lane orders a product/sum's loads by how the operand is reached -- a `this`-relative member (also a pointer local that folds back to `this`) is loaded before a parameter or a pointer local kept in a register, and only when both operands are reached the same way does the source order decide (00853580, 00c40590, 00a5d000, 00814ea0). Retail keeps the source order per product (the landed out-of-line SetCrossProduct 0xC40370 shows left-operand-first). Operands written in the caller's body over the same object follow the source order in both compilers, which is the 00853580 fix.
- **Frame-slot reuse of an address-taken block local** (00449d90, 00488620/004886f0 family): retail homes a later temporary in the dead out-parameter word; the lane keeps the word for the whole function whatever the scoping (block, __forceinline helper returning the value, unnamed temporaries) -- the RTM-v-DDK sharing gap of GOTCHA 23d.
