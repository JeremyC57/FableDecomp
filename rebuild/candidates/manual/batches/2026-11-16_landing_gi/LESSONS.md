# w24C lessons (GOTCHAS-ready)

- (w24C, 2026-11-16) **c2's block scheduler works on regions of at most 83 DAG nodes** (81 tuples plus the two end markers); a longer basic block is cut every 81 tuples in IL order and each piece is scheduled alone. An instruction that retail hoists and ours does not (or the reverse) at ~81 tuples from the block start is a region cut, not a priority tie. Tuples that emit nothing count: opcode 0x269, left by a parenthesised float sub-expression and by a float local that stays on the x87 stack. Measure with `w24/C/dag.sh <src> <function> '["<op>",...]'` (agentP6F's sched/t13.py): the `REGION n` lines give each region's size and ops.
- (w24C, 0x00BCF4F0) Tail copy `EndPosition = StartPosition` scheduled `load Y, store Y, load Z` v retail `load Y, load Z, store Y`: the parenthesised default CMatrix3x4::TransformPoint left three 0x269 tuples, which pushed the last three tuples of the block into a second region. `FABLE_RETAIL_CMATRIX3X4_TRANSFORMPOINT_ZYX_SUMS` (same instructions, no no-op tuples) puts the block in one region. Second half: assign the member itself -- through a named reference (`C3DVector& end = WorldPos.EndPosition; end = ...`) c2 adds a store-before-load ordering edge between the destination and the source pointer and the Y store stays ahead of the Z load.
- (w24C, 0x00C44090 / 0x00C44100) Identity: CCodaSource members forwarding to CSalVoice slots 15 / 16 (EAXSet / EAXGet in engine/CSalVoice.h); their only callers 0x00C52A10 / 0x00C4F470 compare the first argument with the EAX 4.0 FXSlot0 property-set GUID (0x012B9468). `mov ecx, offset obj ; push eax ; call` (this loaded BEFORE the argument push) is a cross-jumped tail: the source has two `CODA.SetError(error)` calls (the first followed by `return`), merged by VC7.1. One shared `if (error) SetError(error)` gives `push eax ; mov ecx`.
- (w24C, 0x00989830) Two `lea r,[ebx-1]` where VC7.1 would share one: the two uses have different signedness (`(index - 1) >> 2` unsigned for the pair, `(long)(index - 1) & 3` for the component subscript). Naming both before the address is formed gave retail's order (both leas, then shl/add, then the value load); writing the casts inline in the subscripts hoisted the value load.
- (w24C, 0x0090E3D0 / 0x00BF0740) Two parked "scheduler tie" rows on local models matched on the first compile once ported to the shared headers in the shape of a landed sibling (0x00934E50's template instantiation with /d2inlT107; 0x00BF0B20's setter list). Check for a landed twin before any tie work.
- (w24C, 0x00BF0740) Identity: 0x00BF0740 is SetupOutlineStencilStates (stencil write: colour writes off, ALWAYS / REPLACE, write mask), 0x00BF0B20 is SetupOutlineFillStates (stencil test, colour upload). The landed 0x00BF0B20 row carries the Stencil leaf (already queued land1113fy / land1115ga); landing 0x00BF0740 needs that respelling first or the two rows define one symbol.
- (w24C, 0x00896B60, not matched) VC7.1 block order does not follow source order for `if (c) goto L; A; return; L: B` (B is laid out first) and an `||` of the same test (`if (c || c) { B; return; } A`) sinks B behind A but still before the shared exit. Retail has the exit block directly after A with B behind it carrying its own epilogue; none of 20 shapes reproduces it.
- (w24C, 0x0086BE40, not matched) Loads of `BodyParts[i]`'s begin / end fold `[eax+ebx]` and the element address is formed afterwards only when the loads come before the set's three zero stores in IL; named `first` / `last` pointers before the set declaration give retail's head exactly, but then size() reloads the end (retail reuses it: `mov ecx,edx ; sub ecx,[eax]`) and `last - begin()` rotates the three scratch registers.
- (w24C, 0x008EEC70, not matched) Measured: the block after `if (bounce_impulse < 0) return false` is 81 emitting tuples up to and including `mov eax,esp`; retail's first region holds 80 instructions, so retail has exactly ONE non-emitting tuple there (the cut then falls between `sub esp,8` and `mov eax,esp`). A named float numerator, parentheses round the numerator, named-result C2DVector operators and a named-result Dot do not supply it without changing other code.
- (w24C, 0x00BA50A0, not worked further) Already RELOCATION_MATCH on the shared headers inside acctC's TU (`pending/2026-11-13_acctC_c19a/open_00ba50a0`, lands with 0x00BA2350): the body is the Q6 draft's (failed declared first); what the local-model draft lacks is the same-TU GetDiffuseTexture / GetBumpTexture bodies.
