# Lessons from hand chunk 954 (family pass 5)

GOTCHAS-ready one-liners:

- VC7.1 pads a vfptr to 8 when the class that introduces it is 8-aligned (holds a double): model engine classes that hold a double on a separate vptr-holding base (CTCBase), or every member shifts by 4.
- A tag-dispatch wrapper's worker must share its calling convention (__fastcall in /Gr TUs) for VC7.1 to inline it; a cdecl worker stays an out-of-line call.
- g++ behaviour tests on LP64 hosts: `long` is 8 bytes, so byte-compare tests over retail records need `#define long int` (test only) or field compares.
- Float-format tests: glibc rounds an exact binary tie to even (12.25 -> "12.2"), VC7.1's CRT rounds it away (-> "12.3"); use non-tie values.
- VC7.1 does same-TU side-effect analysis: a temporary passed by const& to a noinline same-TU function that never writes through it keeps its known values (destructor folds); declaration-only callees force a reload, and a body that never reads the value drops its initialisation.
- A trivially-copyable member struct copied inside a VC7.1 copy constructor re-bases both pointers (add/lea + [reg+4]); retail's direct-offset member copies mean the member type has a user copy constructor (C3DVector does: FableWin.pdb ??0C3DVector@@QAE@ABV0@@Z).
- STLport bitset const operator[] (`(w & mask) != 0` returned as bool) compiles to shr/test under VC7.1; retail's `test byte ptr [reg+N], mask` means the word & mask was tested directly in the if.
- VC7.1 inlines a destructor into the class's ??_G when the destructor is defined (non-inline) in the same file; an in-class inline destructor with a non-trivial member may instead be called out of line from ??_G.
- libpk MMX kernels (K062, 0x00C5BEF0 and copies) read ecx as an input and return with a caller-cleaned plain ret -- an inline-assembly block in a C shell; park them rather than chase intrinsics.
- Level-script members sit at Ego_r.pdb offset - 0x14 in retail (CScriptBase is 0x40 bytes), entity-script members at the PDB offsets; an Init that clears them stores in source order (K066 0x00E7B420 clears +0x49 before +0x48).
- A value parsed into a local and stored at vector[index] after a call keeps the vector start in a callee-saved register only when the source reads begin() into a named local first (`(*v)[i] = f()` evaluates the call first) -- K078.
- In a frame/size-TU STLport _M_find, retail keeps the header in edi and the candidate in [ebp-4]: read the header into a local declared AFTER __y/__x (K085; declared first it costs a byte, absent the header is re-read).
- A pair<K, CCountedPointer<V> > assignment that retail calls out of line from an STL algorithm is the IMPLICIT pair::operator= (VC7.1 emits and calls it); declaring it without a body changes the caller's register allocation (K087).
- Def Transfer bodies that form every member address in eax (lea eax ; push eax ; mov ecx,edi ; call) are size TUs: #pragma optimize("s", on); the speed build rotates eax/ecx/edx (K094).
- K096: value-initialised `CPersistTraits<K>()` temporaries of an empty class get a byte slot each (stosb); retail's "traits this = some live slot" needs function-scope default-initialised empty traits plus same-TU noinline callee stand-ins (0x00469381 recipe).
- An implicit destructor of a def element whose own members are trivial inlines to the bare base-dtor call with no vptr store (x_copy in _M_fill_insert); a member needing cleanup makes it an out-of-line ??1 call.
- A call through const& args to an out-of-line template (e.g. __distance) makes VC7.1 reload the referenced locals afterwards; retail keeping them in registers means the callee's body was in the TU -- add it as a same-TU noinline stand-in (K111).
- An explicitly instantiated function template's mangled name encodes the deduced _Tp, not the parameter type: _Destroy<T>(T*, T*) is ??$_Destroy@V<T>@@..., so a Leaf prefix of ??$_Destroy@PAV... matches nothing (K118).
- A compiler-generated destructor kept out of line has no vptr store; a user-declared one (even empty) stores it. Emit the implicit ??1 out of line with 'X* Make() { return new X; }' in a size TU (vtable -> ??_G -> call ??1) (K119).
- A refcount release written as 'if (--Object->RefCount == 0)' reloads Object after the dec (type-blind aliasing); retail's 'dec [ecx+4] ; jne' is an inline member Release() on the pointee (K119).
- Size mode emits an implicit operator= of a def class out of line (a call per element); retail's inline base-call + member moves need the memberwise operator= written out __forceinline (K124).
- K008: with CIntelligentPointer<T> declaring its own empty virtual destructor (as landed 0x00739550) VC7.1 assigns x->edi / n->ebx like retail; without it the two swap (same bytes otherwise). The K108 model lacks it but matched there -- keep the declared dtor in a shared header.
- STLport _Destroy(first, last) over deque iterators: retail keeps the by-value parameter copies (start in the frame, finish in four registers) before re-copying them into __destroy_aux's argument area -- needs _Deque_iterator's user copy ctor and a __forceinline _Destroy (plain inline is called out of line once the copies exist) (K007).
- same-TU noinline stand-ins for _Rb_global<bool>::_M_increment/_M_decrement (K001): VC7.1 keeps v's key in a register across the iterator steps only when it can see they write no memory
- K016: VC7.1 SIB base/index order for a hoisted-invariant + pointer address ([ecx+eax+4] vs [eax+ecx+4]) did not respond to any source spelling (13 forms); park as a lane gap
