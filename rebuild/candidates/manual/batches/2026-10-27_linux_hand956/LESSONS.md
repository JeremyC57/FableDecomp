# agent956 -- lessons (GOTCHAS one-liners)

- a std:: type as a template argument of a std:: template mangles with a back-reference (@2@ / @1@), so a hand-spelled leaf misses; write a prefix and let fixleaf resolve it.
- VC7.1 rejects `>>` closing nested template args (C2947); generators must emit `X<Y<Z> >` with a space.
- VC7.1 hoists a loop-invariant load across a call only when the callee's body is visible in the TU (noinline under auto_inline(off)); a bare declaration forces a reload every iteration.
- CIntelligentPointer<T>'s copy ctor must go through typed inline GetPItem/SetPItem wrappers; calling the base members directly swaps ebx/edi in list push_back.
- C3DVector has a user copy constructor (X(o.X), Y(o.Y), Z(o.Z)); modelling it as a plain POD makes VC7.1 copy it through bumped pointers inside a larger implicit copy.
- under /Os VC7.1 spells `p->~T()` (inline non-virtual dtor) as a call to the class's ??_G scalar deleting destructor with flags 0; an out-of-line declared dtor is called directly instead.
- a speed-looking body can be /Os with the copy constructor inlined: when the member copies all go through eax, model `optimize("s")` + a __forceinline member-wise copy constructor.
- a filter-functor template that calls another functor's operator() inline needs that operator() __forceinline in the probe, or the call stays out of line.
- STLport vector(n)'s fill folds the zero temporary only when the element's copy ctor/dtor are fully inline (no out-of-line ref-count helpers); force the fill inline.
- STLport _List_base ctor: build the sentinel in a local and store it last (direct _M_node._M_data writes reload after the first link).
- the range erase object also emits the out-of-line erase(iterator); pick the leaf ending `@0@Z` (bin/pickleaf.py FAM REGEX).
- under /Os, `p->~T()` calls ??_G(0) even for an out-of-line declared destructor; when retail calls the destructor directly use the qualified `p->T::~T()`.
- an out-of-line helper taking an empty tag by reference: give it a visible (noinline) body, or VC7.1 reserves a frame byte for the tag temporary instead of homing it in a dead argument slot.
- virtual ??_G with an empty inline derived dtor: emit it with a `new T` driver (the vtable COMDAT pulls the ??_G in).
- a modelled base with a double member pads its size to 8 -- put a derived class's offset padding in the derived class, not the base.
- under /Os an in-class CDefPointer copy ctor / dtor stays out of line (ebp frame + call); __forceinline them to get retail's register-only body.
- under /Os a plain-inline STLport _Construct stays out of line (push/push/call); mark it __forceinline to get retail's inline null-checked placement copy.
- STLport map::operator[] in speed TUs: retail stores the pair temporary's default second word after the argument pushes only when the insert_unique callee has a visible noinline body that reads just the key (landed precedent 0x00553E60); declaration-only or the real escaping body keep the early store.
- a CVectorMap/lower_bound loop over 8-byte entries in a speed TU folds the middle pointer into `cmp [esi+eax*8]` / `lea esi,[esi+eax*8+8]`; retail's `lea edx,[esi+eax*8]` then `cmp [edx]` / `lea esi,[edx+8]` is the size-TU form.
- a by-value push_back temporary and the empty __true_type tag are homed in a dead argument slot when the out-of-line _M_insert_overflow's REAL body is visible (`__declspec(noinline)` class member); the landed same-TU "stand-in" bodies are unnecessary.
- STLport `std::` back-references: a vector<pair<...>> operator= mangles the allocator's closing namespace as `@2@`, not `@std@@` -- take the leaf from the object (leaf_for + fixleaf), never hand-assemble it.
- STLport _Vector_base's own `if (_M_start != 0)` before deallocate changes a range destroy's loop: VC then tests first==last before the push and walks a member pointer (lea esi,[ecx+N]) -- leaving it out gives the indexed loop (42v44).
- `return new X(a, b, c);` with an out-of-line X ctor whose arguments equal the caller's compiles under VC7.1 to new + null test + `jmp ctor` (the ctor's `ret 0Ch` serves both frames).
- with plain `inline` STLport helpers VC7.1 inlines the head __uninitialized_copy of _M_insert_overflow and calls the tail one -- the retail mix of one inline and one out-of-line copy needs no attribute at all.
- a by-value C3DVector getter matches only with C3DVector's explicit member-wise copy constructor; the implicit copy makes VC7.1 pre-add the offset and copy through esi (30v24).
