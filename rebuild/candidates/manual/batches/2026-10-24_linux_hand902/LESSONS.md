# agent902 LESSONS (GOTCHAS one-liners)

- CPersistTraits<T> with the PDB `T DefaultVal` member + a noinline TransferBinaryIn: VC deletes the dead DefaultVal stores and packs the traits over the dead resize(n, T()) temporary, as retail (0x0067F430).
- Alias order: VC7.1 never moves a load above a store through a different base; a retail load scheduled before a store means the source reads it into a local first (0x0087C070 `const CBase* mode = CameraManager->CurrentMode;` before `DefaultFOV = 0.2f`).
- STLport map::operator[] with a class `_Tp`: write the default as `__default_constructed((_Tp*)0)` (inline template returning `_Tp()`); a plain `_Tp()` homes it elsewhere (0x00594A08).
- Placement copy with "retail loads both words before the first store": the callees that receive the temporary's address (copy ctor of a member, _M_insert_overflow, set::insert) need same-TU `auto_inline(off)` + `__declspec(noinline)` stand-ins -- one opaque callee is enough to block it (0x00721A50, 0x0070A490, 0x00A385A0).
- A value retail keeps cached across an out-of-line call (ours re-reads it, or matches only with /Oa): give the callee a same-TU noinline READ-ONLY body; VC7.1 uses the no-write fact and keeps the register (0x006384B0, replaces /Oa).
- A read-only stand-in can also hurt: when retail reads a member BEFORE an opaque call, a stand-in lets VC sink the load after the call (0x00807A90 GetPItem).
- Component lookups that retail leaves in eax (`mov eax,[eax+4] ; mov ecx,eax` or `mov eax,[eax+4] ; mov ecx,[eax+N]`): use the landed 0x007504E0 `__forceinline bool GetInterface(long type, T** out)` with the bit test inside and call it as `if (GetInterface(k, &p))` -- HasTC + GetTC, F88 tails and a void out-pointer form all load into ecx (0x0076D1B0, 0x006CE730). Without `__forceinline` it is called out of line.
- C3DVector placement copies in inline push_back: a memberwise user copy ctor (pack(1)) fixed an ecx/edx swap where the implicit copy did not (0x00A56AA0).
- An inline accessor for a virtual call's `this` (`CWorld::GetEnvironment()`) loads it straight into ecx (0x00732D40).
- Byte bool bit-fields give `mov al,[x] ; shr al,3 ; and al,1`; an out-pointer PeekTC needs `__forceinline` or it is called (0x007E4530).
- finish.py takes the FIRST `// X(` comment as the name line: keep the name on line 1, above any `// Grade: DIFFER(` line.
- g++ x64 tests: drop `extern "C" malloc/free` declarations (they clash with <stdlib.h>) and use `<new>` placement new under `#ifndef _MSC_VER`; guard sizeof checks of pointer-bearing classes with `sizeof(void*) == 4` (mktest.py does the first two).
- /G5 and /G7 left 0x00749620 byte-identical: they are not levers for VC7.1 register choice there.
- Hidden-result copy `push arg ; mov ecx,esi ; call copyctor` (retail) vs ours `mov ecx,esi ; push`: retail has ONE `return X;` that VC7.1 tail-duplicates; two source-level returns schedule the this-load first. Get the branch shape without bool materialisation from `(p == 0 && f() == 0) || (p != 0 && g(p))` (the second null test is threaded away) (0x00997F80).
- x87 values that stay on the stack after their last use and are popped at the end (`fstp st(2) ; fstp st(0)`, products read from `fld st(n)` copies) are NAMED float locals: VC7.1 pops enregistered x87 locals at scope end but consumes expression temporaries in place (`fmulp`). A named C2DVector local is not scalarised -- use two floats (0x00A57730).
- x87 value that retail uses from the REGISTER for some reads (fcom / fdivrp st) but reloads from its frame home for others (`fst [home]` right after the compute): assign it in the condition `if ((v = expr) != 0.0f)` / `if ((v = expr) < 0.0f || v >= 1.0f)` and RE-SPELL `expr` at the reloaded uses -- VC7.1 CSEs the repeated expression into the memory home (0x00A441E0, 0x00A442E0). A plain named local or the expression at every use reloads all of them.
- A float PARAMETER that retail loads once and compares on the x87 stack (`fld [esp+4] ; fcom [lo] ; ... fstp st(0) ; fld [lo]`) is clamped/modified IN PLACE (`if (v < lo) v = lo; else if (v > hi) v = hi;`): a multiply-defined param is enregistered, while a `const T&` Clamp or a copy local is copy-propagated back to the memory slot and reloaded per compare (0x0080C190).
- x87 register pressure is decided by NAMED float locals: a value retail fild/fld-s early and keeps to the end (`fmul st(1)` then a trailing `fstp st(0)`) is a named float local (`float direction = (float)sign;`), and the other value it displaces is homed with `fst` and re-read from memory. A double local compared with 1.0f compares a qword constant; a float local compares the dword (0x00670470).
- A read-only stand-in can over-inform VC7.1: when the caller destroys the passed temporary afterwards (a counted pointer known to be null), VC folds the release away. Give the stand-in a possible (never-taken) write to that member, e.g. `if (position._M_node == 0) const_cast<T&>(v.second) = T();` -- it still never keeps the address, so the non-escape scheduling stays (0x00A2D810).
- A sign multiply that retail does ONCE after the join (`fld1` / `fstp st(0) ; fld [-1.0]`, then one `fmulp`) but ours tail-duplicates into the negative arm: write `angle *= sign; return angle;` instead of `return angle * sign;` (or `sign * angle`) -- the compound assignment pins the product after the merge (0x00875A30).
- STLport set<T>::iterator / const_iterator = `_Rb_tree_iterator<T, _Const_traits<T> >`, whose copy constructor is IMPLICIT (its user ctor converts from the `_Nonconst_traits` iterator). A user copy ctor on the by-value set iterator stopped VC7.1 shrink-wrapping a callee-saved push behind the empty-range exit (0x00A557E0, 155v154 -> match). The opposite of the list-iterator rule (list iterators need the declared copy ctor).
- A flat invented list class with raw node pointers (`insert(_List_node_base*, x)`) shrink-wraps a callee-saved push into the placement-copy block; the real STLport list template with the by-value `_List_iterator<T, _Nonconst_traits<T> >` (declared copy ctor) restores retail's entry pushes (0x00729960, GOTCHAS 447 confirmed on a push_front).
- Register SWAPS (esi/edi, header vs best) in STL-walking code are often the flat invented container model, not a lane gap: the real STLport 4.6 templates (map -> _Rb_tree with the `_STLP_alloc_proxy` header, `_Rb_tree_iterator<V, _Nonconst_traits<V> >`, postfix ++ through the static `_Rb_global<bool>::_M_increment`) recoloured 0x004BCF50 to retail (141v141 swap -> match) where four declaration orders and a bare `_Rb_tree_base_iterator` base had not.
- A by-value parameter whose member address goes to an out-of-line copy (`Copy(&val.second)` in STLport `*first = val` / the by-value pass-on) is "captured" for VC7.1, so its other members are reloaded after every call. A same-TU noinline body of that copy (here CSmallVector::Copy 0x006FB5C0) keeps it uncaptured: retail's `mov ebx,[esp+8]` key held across __copy_backward (0x006FC3E0, with the real STLport __linear_insert template).
- Family recipe (pass 2): rows parked as "register swap / esi-edi permutation / shrink-wrap" over flat invented containers (CMeshEffectMap, CConversationMap, CExpressionStateList, a `std` list with a raw sentinel) matched once remodelled on the real STLport 4.6 templates in `_STL` (`_STLP_alloc_proxy` header/sentinel, `_Rb_tree_iterator` / `_List_iterator` over `_Const_traits`/`_Nonconst_traits`, pair with its user ctors, erase via `_Destroy` + allocator deallocate): 0x004BCF50, 0x006E5990, 0x00729960, 0x006D7EC0. Try this before calling a permutation a lane gap. Reusable list block: agent902/fam/stl_list46.inc.
- "The lane keeps the CSE'd zero in a callee-saved register to the end" (vs retail re-zeroing / `test reg,reg`) on a function that builds a local vector and hands it to an out-of-line same-TU filler: give the filler a same-TU noinline body that writes the vector's three words and never keeps its address (0x0066BDF0 PlayUnattachedCriteria, GetPotentialCriteriaStrings 0x0066BC10). The landed sibling 0x0066BD00 carries the same residue.
- An ebp frame plus a by-value pivot re-read from its argument slot every pass (STLport sort helpers over CCharString keys in a size TU): the opaque CBasicString<char>::operator< call is the cause. The landed 0x00429950 body as a same-TU `auto_inline(off)` + noinline template member (`other` read first) lets VC7.1 keep the key in esi and drop the frame (0x004DFCEA __unguarded_partition, 110v113 -> match).
- Two `return c ? A : B;` result arms laid out in the opposite order to retail: swap which verdict the `if` tests (`if (f()) return w ? 5 : 0; return w ? 0 : 5;` vs `if (!f()) ...`); VC7.1 puts the arm of the final `return` after the first test (0x006E9F60). The same row confirms lesson 9: a HasTC-guarded GetTC leaves the component in ecx, the out-pointer GetInterface puts it in eax and recolours the later key addresses.
- Byte-struct temporaries (CRGBColour): reuse the landed copy-ctor spelling (`CRGBColour(const CRGBColour& o) { Set(o.R, o.G, o.B, o.A); }`, Set storing R, G, B, A) -- it decides which byte copies VC7.1 forwards into registers and which it stores and reloads. With a single named local + `+=` in the body it matched 0x005305A0 ChangeColourDelta; an `operator+` temporary, the implicit dword copy and a memberwise B,G,R,A copy ctor all miss.
- The "x87 operand order of a double global times a float/long" lane gap (retail `fld qword [g] ; fmul dword [x]` / `fimul dword [x]`, lane `fld dword [x] ; fmul qword [g]`) is a source spelling: cast the global, `(float)g_VirtualWidth * x`. Without /Op the cast emits no code, but VC7.1 then loads the global first and keeps the coordinate as the memory operand. Matched 0x009E20F0 / 0x009E2240 and the landed 0x009E1DA0 GFAXToVX WITHOUT its `volatile` (agent902/fixes/009e1da0.cpp); the float siblings 0x009E1DD0 / 0x009E21D0 / 0x009E2020 are left with one fstp/`mov ecx,eax` swap.
