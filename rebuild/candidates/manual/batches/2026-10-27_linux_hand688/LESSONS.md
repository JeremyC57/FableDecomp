# Chunk 688 lessons (GOTCHAS one-liners)

- (2026-11-01, chunk 688) VC7.1 reassociates un-parenthesised float sums (`a+b+c`, `1-(a+b)`) copy by copy with a choice that ignores the operands' text order (a+b+c == c+b+a == b+c+a give identical bytes) but depends on the surrounding float expressions: explicit parentheses pin one order for every copy, loop clones are always uniform, explicit copies / inlined helpers rotate the order from copy to copy (0x00C88E60: retail's four fill copies use three different orders of the same sum -- parked).
- (2026-11-01, chunk 688) VC7.1 builds `_mm_set_ps` through four movss stores and a movaps pair and never zeroes a register with `subps x,x`: a `movss / unpcklps / shufps 44h` gather and `subps` zeroing mark a hand-written SSE block (grade retail_asm). Its C shell is the `/GS`-style aligned frame (`push ebx ; mov ebx,esp ; push ecx ; and esp,-16 ; add esp,4 ; push ebp ; mov ebp,esp`) with a C pointer local in [ebp-4] that the asm loads its base register from (`mov edx, p`).
- (2026-11-01, chunk 688) A chained first-order allpass pair (CStereoDelayLine::Process 0x00C75140) is one inline by-value helper called twice (`line1.Allpass(line0.Allpass(*p))`): the first line's delayed sample is copied through an integer register into a slot and its new value kept with `fst` because both feed the second inlined call; VC7.1 unrolls the pointer loop by four.
- (2026-11-01, chunk 688) A user destructor loop `for (it = L.begin(); it != L.end(); ++it) delete *it;` reloads the list header per iteration (759v758); `iterator end = L.end();` before the loop keeps it in a register as retail (0x00678460). The following `L.clear()` is the inline _List_base::clear (header re-read after each free).
- (2026-11-01, chunk 688) `C3DVector p = cond ? end : start + ...;` gives retail's pointer select (`mov eax,&end` / `lea eax,[temp]`) followed by one copy; `if/else` assignments copy twice. C3DVector::Length() must sum `Z*Z + Y*Y + X*X` (both fsqrt chains start with the Z product, 0x00761280 and the dot product of 0x00AC9A60). The `tanh` intrinsic is `_CItanh` 0x00BFECE2 with double constants (`tanh(x) * 5.0 + 0.25` stored as float).
- (2026-11-01, chunk 688) `while (type == LOAD_TYPE_IMMEDIATE && PLevelLoader->IsBusy()) Run();` gives retail's untransformed busy loop (guard tested once, `jmp` back to the IsBusy test); `if (type == 0) while (IsBusy()) Run();` rotates the loop and duplicates the test (0x00501150, 772v756 -> 756v756).
- (2026-11-01, chunk 688) The chunk-149 lane gap is still open: an empty `__false_type` tag passed by const reference to an out-of-line `__uninitialized_fill_n` is homed by retail in the LIVE `level` argument slot (`lea edx,[esp+50h]`), ours opens a frame byte (named tag local, `const long` parameter and a trivial tag struct do not help) -- 0x00501150 parked on that alone.
- (2026-11-01, chunk 688) Defining STLport's recursive `_M_erase` in-class makes VC7.1 inline one level of it into each set destructor (the `while (x) { _M_erase(right); y = left; free(x); x = y; }` loop with an out-of-line call for the right subtrees), which is retail's shape in 0x00AC9A60; declaring it out of line gives a plain call (0x00501150's set<CCharString> is that case).
- (2026-11-01, chunk 688) libvorbis res0.c statics: `extern "C" double __cdecl fabs(double)` + `#pragma intrinsic(fabs, memset)` (not <math.h>, whose float overload gives a direct `fcom`) reproduces the double maxima compares of `_2class` 0x00CA0890 (776 bytes, 2 probes).
- (2026-11-01, chunk 688) A `__fastcall` free ReadFromFile over CDataInputStream (0x00AA5460): a by-value `ReadFloat()` helper over the landed inline Read model gives one frame slot shared by all eight reads and integer-register copies into the members.
