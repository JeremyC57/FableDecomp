Tool. tools/ipmig7.py replaces the two local blocks with
    #define FABLE_RETAIL_CINTELLIGENTPOINTER
    [#define FABLE_RETAIL_CINTELLIGENTPOINTER_ASSIGN]   when the local template declares operator= (45 rows)
    [#define FABLE_RETAIL_CINTELLIGENTPOINTER_COPY]     when it declares a copy constructor (4 rows)
    #include "engine/CIntelligentPointer.h"
and moves the typed calls to the header's names: p.GetPItem() -> p.Get(), p.SetPItem(x) -> p.Set(x). Get and Set are FableWin.pdb
?Get@?$CIntelligentPointer@..@@QBEPAV..@XZ / ?Set@..; both are inline, so the bytes are the same GetPItem 0x00A01B50 /
SetPItem 0x00A01B90 calls and no relocation symbol changes. Objects declared as the plain CBaseIntelligentPointer keep
GetPItem / SetPItem. Both sub-macros already exist at HEAD (chunks 754 / 755); no header changes in this wave.
