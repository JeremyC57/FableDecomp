# NF139 lessons (one line each)
- Check the lock owner of every WORKLIST binder before planning: rows.txt here held only the self rows, the binders were still another agent's.
- A View-stand-in self row moves onto its shared header in one grade when the header already declares the member; rewrite its test on the header (zeroed block + fields written at their offsets), since the old test linked the stand-in member.
- When retail expands an out-of-line member inside a sibling, putting the body inline in the header makes the includer emit a COMDAT copy: if the owner row defines it strongly, convert the owner to the nf88 address-of scaffolding and prove it with a LINK=-cleared link (LNK2005 before, none after).
- In this lane, an inline member a row uses is emitted as a COMDAT even when fully inlined (??0C2DExtentsI, ?GetSize@CPackedUIntArray): check objdump before trusting "declaration only" changes.
- An inline ~T() { Uninitialise(); } added to a row's local T model also emits ??1T and ??_GT: that is a one-definition hold, so a local-model row cannot be moved off an out-of-line destructor in place.
- A 1-byte `ret` at a PDB-ordered slot (??1CInputEvent right before GetType) plus the binders' spelling is enough identity for an empty destructor.
- A row whose only header-class debt is a local model can swap just that class for the shared header (one transformer, six rows here) and keep its own leaf and other local models; check objdump: the gain should be only the header's inline pick-any COMDATs.
- refs.py hits that reloc_bindings cannot name are often immediates in code (a destructor address pushed for an EH vector iterator): map the file offset through the section table before calling it data.
