# NF210 lessons (one line each)
- A pick-any copy of a /Os owner's template member (_Rb_global<bool>::_M_decrement) comes out right as an inline EXPLICIT SPECIALIZATION under `#pragma optimize("s", on)` placed before first use: it compiles at its point of definition, where an out-of-class template definition is instantiated at the end of the TU at /O2 (0x006EDA80: 64 -> 57 bytes, equal to 0x004294E2).
- When a row's HEAD stand-in for a tree's erase(key) was a same-TU body that calls an extern sink, a declaration-only erase(const K&) (no pick-any copies at all) matched first time (0x006ED510): try the opaque form before the visible STLport body.
- One named key local reused for both lookups reproduces retail's single key slot and the early victim-UID store (0x006E93C0 now matches up to the GetRing push); the leftover is the struct-returning find in GetRing's object expression, which VC7.1 evaluates before the argument.
- A namespaced stand-in row (0x006EAC50) can move whole onto the headers in one form when its classes have header twins: list every newly defined COMDAT and grade it at its owner address with q.py; most STL / string inlines here matched retail outright.
- A declaration-only opt-in for an inline that the row EXPANDS (HasTC at 0x0047DB73) turns the expansion into an out-of-line call (DIFFER and a new binding): check that the row only calls the function before using the DECL_ONLY pattern.
- /d2inlT has a hard step between two adjacent values (0x006D41F0: T60..T64 = 269, T65 = 307). When the step skips retail's size, no per-row flag will do.
