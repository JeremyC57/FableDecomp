# Chunk 123 -- lessons from the authoring agent (fold into GOTCHAS at landing)

- A persist read whose value lands in a register (no store to the slot on the fast path) while a later temporary reuses the dead argument slot = the read goes through an inner helper with its OWN value local (`CPersistTraits<unsigned long>::TransferBinaryIn`-style `T value; in.Read(&value, 4); *out = value;`); reading straight into the outer local keeps it in the slot and pushes the temporary to a `push ecx` word (0x005DBF50).
- A float member copied through x87 (`fld [src] ... fstp [dst]`) while its neighbour is copied through an integer register = the value arrives through a float-RETURNING inline getter into an inline setter; plain `a = b` float copies use integer registers, and a `float last` local in the setter moves the x87 copy to the OTHER value (0x0070D030).
- A sub-object copied through a `lea` pointer pair (`lea edx,[edi+18h] ; mov ecx,[edx] ; lea eax,[esi+18h] ; mov [eax],ecx`) is a POD assigned with the implicit operator=; a user memberwise operator= folds the offsets into `[edi+18h]` moves (C3DVector in C3DAnimationInfo::operator=, 0x00A2B4E0).
- By-value iterator arguments copied twice (into registers / a frame copy, then into the argument area) need a user copy constructor; a memberwise one folds the member offsets, a copy constructor over a POD body (`It(const It& o) : d(o.d) {}`) gives the `lea`/`mov eax,esi` pointer reads; a POD iterator elides both copies (0x00412210, still a register-allocation DIFFER).
- `x == v.size()` vs `v.size() == x` picks `cmp eax,edx` vs `cmp edx,eax` -- write the operands in retail's order (0x0070C100).
- A bool result re-normalised with `test al,al ; setne al` after an `unsigned char` call = `return f() ? true : false;` (`!= 0` gives `neg ; sbb ; neg`); a cold early-return arm placed LAST is the `else` of an `if (!cond) { ...hot... }` (0x00A25A70).
- A loop whose `end` stays in a callee-saved register across out-of-line iterator calls takes `end()` into a local before the loop (`it != m.end()` re-reads the head after every call) (0x00A25A70, 0x00738F90).
- `switch` case labels sharing ONE body become a range test (`jl/jg`); separate identical bodies give the retail binary compare tree (merged afterwards) -- block placement of default/case bodies still differed (0x00C564F0).
- Under `/Os` (+ `y` off) the record/field store order follows the source order: write the field retail stores first (`time`) first -- in the found-entry arm that gives retail's load-before-`inc`, store-after shape, in the new-record arm the time store before the `push` and the other two fields after it (0x00647511).
- SGI algorithm helpers from /Gr TUs (`__unguarded_linear_insert`, ret 4 with the comparator by value) reproduce as explicit `__fastcall` templates with an explicit instantiation; the comparator is a one-pointer struct whose `operator()` inlines the bank accessors (0x009D2FC0).
- `throw CGenericException(msg)` with an EMPTY exception class (1 byte, inline ctor ignoring the message) reproduces the retail self-copy of the 1-byte object into the dead argument slot and the `(key + "...")` temporary in the dead result-pointer slot; no /EHsc in that TU (no unwind frame although a CCharString local is live) (0x009A7CA0; still DIFFER on the trailing int3).
- The intrusive `CCountedPointer` {object, block{count, __fastcall destroy(object), object}} release that re-reads the block after `dec` (`dec [eax] ; mov eax,[esi+X] ; cmp [eax],0`) is written `--m_pCount->m_references; if (m_pCount->m_references == 0)` on the member; a by-value parameter's destructor keeps the block in a register (0x009D66A0, 0x00B443B0, 0x009A7990).
- An empty-class temporary used as `this` of an out-of-line call (`CPersistTraits<float>().TransferIn(...)`) is homed in a dead argument slot only with a user default constructor (0x005DCA60).
- Behaviour tests on the 64-bit g++ host: `unsigned long` is 8 bytes -- a 4-byte stream read into one leaves garbage in the high half; use `unsigned int` in tests for 4-byte values.
