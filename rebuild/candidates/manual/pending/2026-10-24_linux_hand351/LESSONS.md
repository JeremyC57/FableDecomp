# Chunk 351 -- lessons from the authoring agent (fold into GOTCHAS at landing)

- The `_Copy_impl<...>` catalog family is STLport 4.x, told apart by the `ret`: `__uninitialized_copy(first, last, result, const __false_type&)` = `ret 8` with a placement-new null test; `__copy(first, last, result, const random_access_iterator_tag&, ptrdiff_t*)` = `ret 0Ch` with a precomputed count; `__copy_ptrs` / `__copy_backward_ptrs(first, last, result, const __false_type&)` with the inner loop inlined = `ret 8` without a null test; the top-level `copy_backward(first, last, result)` = `ret 4` (004e9bda, 00672210, 007108a0); callers push `0`, `lea` of a dead slot (the tag), result.
- In a copy loop a SECOND pair of strength-reduced pointers (src+N/dst+N besides the element pointers) means a nested record member: an 8-byte POD sub-record at +8 gives `lea esi,[ebx+8] ; lea edi,[ebp+8]` where two plain members compile to `[esi+8]`/`[edi+8]` (00748af0). In copy constructors the pair points at the record's LAST word, so its offset gives the member order: {CCharString, long, 12-byte record} -> +0x10, {CCharString, 12-byte record, long} -> +0xC (0088abc0 vs 00a6ed80; CTargetPoint +0x14 = TargetingPosition.Z in 00806c00).
- A by-value pair in an unguarded insertion step whose key is kept only in the frame and reloaded through eax for the final store needs STLport pair's memberwise USER copy constructor; the implicit copy keeps key and word in ebx/ebp (004d03c0, 84v87 -> MATCH).
- Under `#pragma optimize("s", on)` the lane's VC7.1 leaves `inline` STLport helpers out of line (`__copy` inside `__copy_ptrs`, `__unguarded_linear_insert`, list/back_insert iterator members); retail inlined them, so spell them `__forceinline` (004e9bda 21v95 -> MATCH, 00471239 50v65 -> MATCH, 005810ae, 00471be9).
- `__fastcall` with a by-value class result: the hidden result pointer takes ecx, class-type iterators stay on the stack, and the first pointer/reference argument (here the `const input_iterator_tag&`) takes edx even though it is the fourth parameter (005810ae, caller `lea edx,[ebp+13h]`).
- CDefendingCombatantInfo::CProng's C3DVector at +1 with the long at +0x10: declare the C3DVector record under `#pragma pack(push, 1)` (alignment 1), not the outer class (006f14a0, 006f10f0).
- An empty comparator by value and a 4-byte function-pointer comparator re-push the same dword (`mov eax,[esp+18h] ; push eax`); read the callee to pick the type (0x00A46530 `call ebx` = `__fastcall` function pointer, 0x00A70F40 inlines CCharString::operator< = empty functor).
- STLport `list::erase(first, last)` never reads `this` (no size member): a `__thiscall` body that ignores ecx and returns through `[esp+4]` is still the member; both erase overloads are emitted, so pin the leaf to the mangled range overload (00471be9).
