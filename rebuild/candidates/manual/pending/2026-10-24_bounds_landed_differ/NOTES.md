Lane: Linux Wine, VC7.1 RTM cl 13.10.3077 (`$S/wine/env.sh`). Each grade runs on the real retail span, with bytes read
straight from Fable.exe (`g.py <addr> <src> <len>`, built on `$S/bounds/grade.py`). Tests are self-contained: each
`test/<addr>.cpp` is a verbatim copy of `src/<addr>.cpp` plus stubs and a `main` (generated by

## Why the landed rows differed
- 0040bb90: a wrong paraphrase. It stored a "saved cursor" where retail runs STLport `vector::clear()` (an enum is not
  __type_traits-trivial, so the copy is the counted loop), then Save, then `while (!q.empty()) q.pop();` over a 128-byte-node
  deque. Re-authored. It matched on the first grade.
- 004012ce: the source was right and the flags were wrong. The CRT is size-optimised: with /O1, VC7.1 calls __SEH_prolog and
  __SEH_epilog (`push 0Ch ; push scopetable ; call`); with /O2 it inlines the fs:[0] frame (120 bytes).
- 005eadc0: an asm_bake of the 22-byte /GS prologue. Re-authored from the 005eaf30 twin with 4 by-value CWideStrings, the
  five-string SetText overload, AltState taken from the 7th argument and state 0x2E. It matched on the first grade.
- 0098b5e0: the source was fine. The test hung cl /Od. The rewrite puts each scenario in its own function and makes every
  check a single condition (it compiles in under 1 s).
- 00988a50 / 00bdc510 / 00bf4570: retail ran inline asm (evidence is in each differ/ header). 00988a50 holds two SSE 4x4
  multiplies (~68 instructions each). 00bdc510 and 00bf4570 share one 19-instruction SSE AABB squared-distance block. purity.py
  RETAIL_ASM_MAX is 8, so this needs an owner decision. 00bf4570 (4.9 KB) and 00bdc510 also need their C++ remainder rebuilt;
  the landed bodies are paraphrases (316 / 1044 bytes).
- 00b687d0: the landed body was a 327-byte paraphrase. The fresh reconstruction in differ/ matches everything except where
  locals sit on the stack (retail order: def +0x14, i +0x18, CCharString temp +0x1c) and the register choice in the 4th mip
  block. In retail the def pointer lives in ebp and is reloaded from its slot, and the def is released with no null check
  (`dec [ebp+4]`). Variants tried (16): CDefPointer with/without a null-checked dtor, a register copy of the def, explicit
  release, a function-scope def (this gets the slot order right but adds a zero-init), /Oa (worse, 1506), /Ow (much worse),
  and the ctor store order (WaterHeight before WaterType matches retail). Closest is 88 of ~480 instructions.

## GOTCHAS one-liners
- A catalog row "landed" in the old lane can still be byte-wrong. Grade it on Fable.exe bytes before trusting it: 0040bb90,
  00bdc510, 00b687d0, 00bf4570 and 00988a50 had catalog bytes equal to the exe but never matched.
- VC7.1 CRT rows (`__SEH_prolog` call at entry, `push 0Ch ; push <scopetable>`) are /O1 objects: grade them with `/O1`
  before suspecting the source.
- An SSE block whose pointer operands are stored to the stack and immediately reloaded into fixed registers
  (ecx/edx or eax/edx/edi) is retail inline asm, not intrinsics. Intrinsics keep the live registers and interleave.
- VC7.1 cl /Od hangs, with no error, when a `//` comment swallows a closing brace (unbalanced braces at EOF). In a test
  that "times out", check brace balance first. A `timeout` around the python driver does not stop the orphaned wine cl.exe.
- Python `re.sub` replacement strings turn `\n` into a real newline. That breaks C string literals written by a
  generator: use plain str.replace or the Edit tool.
- An unquoted bash heredoc runs backticks inside C++ comments as commands. Always quote the delimiter (`<<'EOF'`).
- STLport `vector<Enum>::clear()` compiles to `mov ecx,eax ; sub ecx,eax ; sar ecx,2` (count 0) plus an element loop.
  That is the non-trivial copy(end,end,begin), not a bug.
