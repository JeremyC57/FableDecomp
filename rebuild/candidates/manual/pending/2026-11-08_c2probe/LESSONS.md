# LESSONS (c2probe, 2026-11-08) -- GOTCHAS one-liners for the c2.dll allocator probe

- (2026-11-08, c2probe) c2.dll 13.10.3077's register allocator can be read live: copy c2.dll with `jmp $` (EB FE) at `_InvokeCompilerPass@12` (RVA 0x596f), compile with `/B2<copy>`, attach `winedbg --gdb` to the spinning cl.exe (found by a uniquely named cl.exe copy), restore the two bytes from gdb and plant breakpoints; the copy loads at its preferred base 0x10700000 under Wine 9.0, the compile finishes with a byte-identical `.text`, 6 s per micro-TU (`tools/c2prio.py`).
- (2026-11-08, c2probe) Attach only after the c2 copy is MAPPED (`/proc/<pid>/maps`): winedbg's `info process` lists cl.exe while c1xx is still parsing (up to a minute on a Fable row), and gdb then sees no c2 module.
- (2026-11-08, c2probe) c2.dll was built with hot/cold block splitting and no `int3` padding: an assertion site (`push line; push "color.c"; call 0x107fe722`) is a cold block that jumps back into its function's hot code far away; carve functions from `call` targets by control flow, not by padding.
- (2026-11-08, c2probe) VC7.1's priority is exactly MSVC 5's: prio(c) = sum over blocks of w(b)*K(b)*cost_b minus w(b)*K(b) per block the value is live through unreferenced, with w = 1 << loop depth (block +0xa6), K = candidates referenced in the block (constants included), cost 2 per variable reference; the per-block shares add up to candidate +0x0c (p7_loop: i = 10 + 48 = 58, a = 10 - 8 + 12 = 14).
- (2026-11-08, c2probe) The equal-priority tie key is candidate +0x44 = the number of the last tuple that WRITES it, tuples numbered block by block and each block from its last tuple to its first: the value defined earlier gets the larger key and is coloured first (sorted list: prio desc, key desc, new before equal).
- (2026-11-08, c2probe) The chooser (0x107833f2) walks the order table eax, ecx, edx, esi, edi, ebx, ebp and keeps the allowed register with the smallest cost under strict `<`; a copy relation to a coloured neighbour or a fixed register is a -1..-3 cost, a neighbour with one register left adds 100*weight, otherwise all zero -> first allowed table entry. A -1 from `it = v.begin()` is why 0050a650's free reloads `_M_start` into ebx (retail eax: two webs there).
- (2026-11-08, c2probe) Expression temporaries (0x10775acc) take the first free of eax/ecx/edx from a per-function rotating pointer (0x108a7d0c into the table 0x108a9738, reset at 0x10775844) and move it past the register taken; `--rotation` shows the pointer before each choice. 0085c7d0's `mov edx,[ecx]; lea eax` v retail `mov eax,[ecx]; lea edx` is the pointer sitting at edx instead of eax at the vptr load; removing the one scratch temporary before it (variant C) fixes the pair but makes the moved load a callee-saved candidate.
- (2026-11-08, c2probe) A callee-saved register that holds only constants is given back after code generation when the constants' benefit (descriptor +0x38) is <= 2 (0x10785300): consts.cpp zc4's `const 0` gets edi from the allocator and ends as immediates; zc5 (benefit 3) keeps `xor edi,edi`.
- (2026-11-08, c2probe) Address-taken locals are not candidates at all: 005253f0's text-loop `uid` (passed by reference to the out-of-line `map::operator[]`) has no candidate, so `this`'s split piece (prio -313) takes ebx as its only register; retail's ebx `uid` means retail's key was a copy, not `uid` itself.
- (2026-11-08, c2probe) Candidate ids restart at 1 per function (counter 0x10882154 reset in 0x1077c367), and a record taken from the free list 0x108a92d8 keeps its OLD id, so split pieces reuse freed ids; identify a candidate by (time, id), never by id alone.
- (2026-11-08, c2probe) research861's `gr.py` stages every file into one `g_<addr>` directory: grading two variants of one address concurrently compiles the wrong source (SRC_FAIL naming the other variant's identifiers); run grades sequentially, probes may run in parallel.
