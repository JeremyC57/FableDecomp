## 0x0044C72B
Fix-up: Row 0x0044C72B CGameDefinitionManager::InitAndCompile now passes the strict-header check. The read-only vland with LANDVERIFY_STRICT_HEADERS=1 prints `0044c72b RELOCATION_MATCH PASS` and no WARN of any kind (no HEADER_POLICY, SHARED_HEADER_AVAILABLE, RELOC_IDENTITY or STANDIN_LEAF). vt.py PASS, and addmatch was redone with the method name `InitAndCompile`; the earlier mangled name was what caused the STANDIN_LEAF warning.

**Why it failed, and the precedent.** The check in verify_and_land.py (around line 522) is purely textual: it fires on `(struct|class) Name {` when rebuild/include/engine/Name.h exists and the source does not contain `engine/Name.h`. There is no allow-list marker and no sanctioned template form. The cited precedent 0x004EE23F does not pass strict mode either: 75 of its `class XDef {` lines would hit, and it was landed without strict mode. Its thing-component classes only slip past the regex because they carry `: public CTCBase`.

**Fix.** The row now includes 85 shared headers: the 81 repo headers, plus engine/CCarrySlotDef.h (new in the overlay only), plus NUISystem_CUIDef.h, NUISystem_CUILocaleGraphicsDef.h and NUISystem_CUIMiscThingsDef.h. The regex does not flag those three NUISystem headers, but they are shared headers, so the rule covers them. All 85 compile together in one TU; no pair conflicts. How each class gets its static Alloc:
- 8 headers already declare it by default.
- 8 declare it under existing opt-ins that the row now enables: CDEGRADABLEDEF_ORIGINAL_FUNCTORS, SKYBEAM_ORIGINAL, CTHINGOBJECTDEF_VALIDATE, CSIMBUILDINGDEF, CENVIRONMENTDEF_PARENT, CENVIRONMENTTHEMEDAYSETDEF, CSPECIALABILITIESFIREBALLSPELLDEF_MEMBERS, CJACKDRAGONDEF.
- FABLE_RETAIL_CTHINGBUILDINGDEF is also enabled, because the default branch of that header is a _quarantine include. CCOMBATABILITYDATA, _BLOCKINGDATA and _PROJECTILEATTACKDATA are enabled so the combat-ability headers' layout asserts hold.
- 69 headers get a new additive FABLE_RETAIL_<CLASS>_ALLOC opt-in in $W/hdr. It adds `public: static class CDefClassBase* FABLE_FASTCALL Alloc();` before each class end. The elaborated `class` means no include is needed; I checked that VC7.1 still mangles it `?Alloc@X@@SIPAVCDefClassBase@@XZ`. Single-line classes get an #ifdef twin with the original line kept in #else. Default text is unchanged. Moved asserts are pinned with pin_asserts.py; CThingHolySiteDef.h line 20 was pinned by hand. Every Alloc symbol is in both Ego_r.pdb and FableWin.pdb.
- I did not enable the multi-header opt-ins FIRE_RANGED_WEAPON, BRIAR_ROSE and AUGMENTATION_PARTICLES, because they reach NCreatureMode and the stlport containers. CHeroCombatDef, CBriarRoseDef and CAugmentationDef got their own _ALLOC opt-in instead.
- The 52 registered classes that have no header anywhere keep the registration-interface-only declaration, as in 0x004EE23F.

**Trap found and guarded.** A class whose header lacks Alloc compiles silently and binds the base class's Alloc. That happened with CThingObjectDef, which bound CThingBaseDef::Alloc and gave DIFFER(8992v8995) until CTHINGOBJECTDEF_VALIDATE was on. As a guard I compared the object's extern symbol set (objdump -t) with the original all-local version: all 162 symbols are identical.
