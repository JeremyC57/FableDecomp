# Chunk H40b lessons (GOTCHAS-ready one-liners)

- (chunk H40b, 2026-11-11) A masked-diff tool that masks branch targets (hand H40 tools/md.py) HIDES the real residue of the near script Mains: "4 lines, natural-exit ~seh_me store order" (0x00E3EB10) and "11 lines, arm merge" (0x00DFE0F0) were both a jump whose TARGET differed. Always run a branch-target diff (hand H40b tools/jt.py: aligned jumps whose targets map to different retail addresses) and a size diff (tools/sz.py: short v near jumps) before reading a store-order or alignment residue.
- (chunk H40b) "Natural-exit expanded ~seh_me emitted in REVERSE program order (vptr, Info, Data)" (GOTCHAS chunk 824, 0x00E6BC50 / 0x00E3EB10) is not the scheduler: c2's late DAG cross-jump (c2.dll 0x107B6DDD, called from 0x107B6C94 in pass mode 2) merged TWO expanded copies of that dtor (the natural exit and one `return`), and it re-emits the matched independent instructions in reverse (each inserted before the previous: watchpoints on the tuple links show unlink 0x10735DFD / relink 0x10735E08). Retail's program order means retail had ONE expanded copy there: find the extra copy with tools/jt.py (a `jne` into the natural exit where retail jumps to a called-dtor pad, 0x00E3ED00 `jne 0x00E3F740`) and make that site call the dtor (scoped `#pragma inline_depth(0)` round its `return;`). Probe without a grade: hand H40b tools/so2.sh (scheduler DAG of the exit: `mov mov mov lea call` = one copy, `lea mov mov mov call` = merged copies), tools/xj.sh (the cross-jump's inputs).
- (chunk H40b) Which epilogue copy a conditional early `return` jumps to tells the loop spelling: retail's entry check jumping to the FIRST epilogue in the function (0x00E3EB5D `jne 0x00E3F749`) = the function's end is NOT reachable, the main loop is `for (;; NSF) { if (T) return ...; ... }`; jumping to the LAST epilogue (0x00DFE151 `jne 0x00E00602`) = the end is reachable. `for (; !T; NSF)` + natural exit gives LAST. 0x00E3EB10 and 0x00E6BC50's store order closed with the `for (;;)` form.
- (chunk H40b) A `return;` followed by a user label after a `for (; !T; NSF)` loop (the `goto rescued` form of 0x00DFE0F0) makes the first loop's exit the true epilogue: the entry returns jump to it and the TRADERB / TRADERC arms no longer merge. `for (;; NSF) { if (T) return; if (cond) break; ... }` with the rescue code after the loop (no label, no extra return) gives retail's survivor AND the whole-arm merge that six earlier chunks could not spell.
- (chunk H40b) Frame-packer ties are measurable without a grade: hand886 tools8/phook.py runs under the c2dbg host (hand H40b tools/pk.sh prints every slot's weight, size and nodes). 0x00D8BCD0: the WifeTimer slot (45 + 3 of a string temporary sharing it, 4 bytes) tied the four 1-byte compare flags (12) at density 12000 and sorted first; `while (!T) { ... }` instead of `if (T) return; do { ... } while (!T);` is one dtor reference fewer (44 + 3), the flags sort first and land at [esp+13h] with the timer at [esp+14h] as retail. Every `return` in an object's scope is +1 IL weight for it.
- (chunk H40b) Where VC7.1 lays the out-of-line exit pads of a switch-in-loop script tells the SOURCE ORDER of the cases: a case that ends in `return` and is jumped over by the previous case's `break` is moved behind the loop exit, and the pads of returns that come AFTER it in the source are laid after it. 0x00E84B80: retail has `[loop exit][case LEAVING_FC][pads][shared tail]`; with LEAVING_FC written last ours had the pads in front of it (16 bytes, 55 lines, 38 grades in chunk H40); written second (enum order, after REACHING_FC) it matched at once. Jump-table case addresses in ascending order = source order, except such a moved case.
- (chunk H40b) c2 probes that need no grade (all through tools/sched/host.py + c2dbg): scheduler DAG (t13/t15), frame packer (phook), late cross-jump inputs (xj.py, hook 0x107B6C93: ebx = the jump tuple, [[ebx+28h]+18h]+33h = its label), tuple-link watchpoints (w1.py; x86 has 4 hardware watchpoints, tuple addresses are stable between runs of the same source).
- (chunk H40b) Per-site call / expand splits are measurable without a grade: hand883 tools/inl.py (hook c2.dll 0x1078D1AA) through hand H40b tools/inl.sh prints each site's callee cost c1, static frequency, score and result. 0x00D0F640: ~vector<CScriptThing> c1 44, T 74, scores 45..68 at frequencies 659..66 -- every site expands; a `/d2inlT52` flag is no shortcut (it changes the callee's own inlining: c1 29).
- (chunk H40b) c2's static frequency follows the flow graph, not the loop keyword: for (;; NSF) { if (T) return; }, for (;;) + bottom check, do { } while (!T), do { } while (true), a goto loop and if / else instead of `break` all gave identical site frequencies in 0x00D0F640; `if (T) return; while (true) { ...; NSF; if (T) return; }` HALVED all of them (the constant loop test is a block of its own when frequencies are assigned), and do { if (T) return; } while (0) round every thread check raised them by 11 %.
- (chunk H40b) Frame-slot permutations of equal-size scalars: read retail's slot SHARING, not only the offsets. Each later, lighter node joins the LATEST slot it does not conflict with, so who shares with whom gives the creation order of the slots and with it the weight order of their first nodes (0x00D5AE70: multiCounter -> the 2nd tick's slot, timerInfo -> the 1st's, a weight-1 temp -> the 3rd's proves creation order 3rd, 1st, 2nd). Weights are IL references at pack time: uses that sit in a register piece do not count (tick1 10 -> 8 with three uses in ebp). hand H40b tools/pk2.sh (slots + node order) and pkw.sh (the order in which nodes gain weight; equal weights keep first-to-reach order).
- (chunk H40b) An eax / edx swap at one virtual call with everything else equal is one step of the expression-temporary rotation: `c2prio --rotation` lists the pointer before each temporary in code-generation order (thread-exit pads come last, not in place). 0x00E64FB0: the in-place CRGBColour pointer (`mov eax,esp`) and the Game load are allocator candidates, not rotation temporaries; only the vptr rotates, so the step must come from a temporary before the statement.
- (chunk H40b) tools/hmerge.py can place a re-based opt-in inside a neighbouring `#ifdef` of HEAD (0x00E64FB0: FORCEINLINE_ASSIGN landed inside OUTOFLINE_DTOR and silently did nothing: 461 lines instead of 8). After every hmerge, read the lines round the inserted block.
