- (wfB1, x87 / push interleave) The order of x87 stores among argument pushes is not CPU scheduling (/G5 /G6 /G7 identical): it is a slot template counted in instructions after the last fadd (fld st(1) +6, fstp +8, fst +11, pops +13 / +15) that c2 fills top-down only when >= 10 integer instructions are available; with 9 it places the fst one slot early. A one-instruction residue of this kind means retail had one more integer instruction in the region when the stores were placed: look for a statement fact that adds an instruction which later disappears, not for another spelling of the pushed value (ten spellings of the value gave identical order). tools/fl.py prints the region compactly.
- (wfB1, twin idioms are per function) The matched PC twin's spelling of a shared block is evidence only where the twin's RETAIL has the same destructor facts: 0x0058807D keeps the `Object = 0` stores of its GetSubDef targets, 0x0058578B drops all four, so the twin's flat `mod` declaration costs a null store here. Compare the null-store pattern of both retails before porting a twin block.

Read the two priorities of the swapped pair before trying spellings (0x00652FA4: an exact tie 0xE0 v 0xE0 decided by the store flag; retail needs +4 on the push).

- (0x00652FA4) Integer commutative add order (`i + loop temp`) and x87 `a.X + b.X` order are both c2 record-id sorts, readable in 2 minutes with the comparator log (wfD2 tools/lk with the float filter removed: tools/lk/lka.py, show3.py, named.py). Integer leaves: key = id * 32 (bigger id first); float indirections: (pointer id * 0x2000 + 8) mod 0x10000, i.e. id MOD 8 -- so dead-local rulers flip x87 sums with period 8 and a k = 1..7 sweep can never be neutral for them.
- (0x00652FA4) c2 creates a function's symbol records in IL order in chunks of 32 ids; other tables take chunks in between, so one record moved across such a point shifts every later record of the function by 32 (not 1). The neutral way to use that is to MOVE a record, not add one: declare a constructor-less out-variable (`C2DVector text;`) one scope out, before the condition where the other table allocates. Bisect the point with a dead ruler first (fixes before it, not after it).
