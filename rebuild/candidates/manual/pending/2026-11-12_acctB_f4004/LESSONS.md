# LESSONS -- chunk 4004 (GOTCHAS-style; addresses are retail)
- c2 has two inline rules; which one a call site gets depends on whether the CALLEE was already compiled in the TU. Already compiled: the cost rule. Not yet compiled: a BUDGET rule (c2.dll 0x107284A3): refuse when the running size G2 > 35000, else accept when w <= 40 or the caller's budget (min(35000, max(1000, 2 x caller w))) still covers w (w = the callee's c1 size word). A long list of small inline calls that stops being expanded part-way (0x00F2D6E0: statements 1..451 expanded, 452..944 called, cut at 0x00F30F13) is this rule running out of G2, not a source change at that statement. Review at landing: MATCHING_PLAYBOOK inline section.
- c1 emits an INLINE virtual that only the vtable needs BEFORE the templates it is first to use; a non-inline member gets its templates first. Retail layout tells which one a row was: 0x00F2D6E0 is followed by its own TransferVector<CDefString> 0x00F333B0 and the sub-component instances; 0x00F2D330 CFeatDef::Transfer by Transfer<EFeatAttackType> 0x00F2D4D0. An inline virtual needs a vtable user in the row TU to be emitted (`CScriptDef::CScriptDef() {}`); taking its address or calling it directly does not give the same order.
- Under the budget rule, a callee that is accepted but then fails to expand (a switch body: TransferVector<T>, TransferVectorOfSubComponents<T>) still costs budget and G2, nested accepted callees included. So a template body the row never expands must still be VISIBLE with the right c1 size (0x00F2D6E0 needs the TransferVector named body: without it the cut is elsewhere). Review at landing: rows that hide such bodies behind declarations.
- A nested inline (GetDefaultVal<T> inside Transfer<T>(name, value)) gets floor(budget / remaining top-level sites); it expands only at the last few sites where that share reaches its size (0x00F30E97 and 0x00F30EF7: share 48, GetDefaultVal<long> w 48). One unit of c1 size decides it: GetDefaultVal<float> must be 49 to be refused at 0x00F30E76 / 0x00F30EB5 / 0x00F30ED6.
- c1 size words measured (tools/w6.sh): a traits local with user ctor + dtor returning a member = 48; without the dtor 28; `return CPersistTraits<T>().DefaultVal` 41; a `const` data member adds 1; Transfer<T>(name, value) 38 (CDefString 34, CCharString 48); TransferVector<T> named body 151.
- An explicit instantiation ahead of a function moves that instance from the budget rule to the cost rule for the function (0x0049B8D0 TransferVector<CCharString> for 0x00F2D6E0: cut 394 -> 450). It is a stand-in for "the TU compiled it earlier"; look for the real earlier user when the TU is assembled.
- Debug-info flags (/Z7, /Zi, /Zd), the `inline` keyword alone and definition order do not move the split; emission order does.
- 0x007E37C0 is CPersistContext::GetDefaultVal<CDefString> (fastcall, hidden result in ecx), not CDefString::CDefString: same 9 bytes, and the VC7.1 instance of the template compiles to exactly them. 0x0042D9D0 carries the same body under the constructor's name. Review at landing: landed row 0x007E37C0 and its FABLE_RETAIL_CDEFSTRING_DEFAULTCTOR_OUTOFLINE opt-in.
