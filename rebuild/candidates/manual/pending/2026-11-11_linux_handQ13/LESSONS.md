# Chunk Q13 lessons (GOTCHAS-ready)

- (chunk Q13, 0x00DD9520) An inline slot wrapper that returns its call parenthesised, `return (PImp.Data->GetAngleXY());`, adds a PAREN tuple. That moves the fstp of the float-argument temporary one list-scheduling slot later, after the next inline null re-test (0x00DD9631..0x00DD9637).
- (chunk Q13, 0x0092ACE0) A file-static float, `static float g = 0.01f;`, schedules its integer argument copy (`mov edx,[g] ; push edx`) after the first x87 load of the neighbouring by-value vector argument (0x0092ADD5). An extern float schedules it before. This is the same effect as the landed 0x0092AFE0 function-local static.
- (chunk Q13, 0x0092ACE0) A by-value C3DVector call argument built as a named `C3DVector target = a + b;` before the call builds through eax after `mov ecx,esi` (0x0092ADEF). The inline `a + b` in the argument list builds through ecx.
- (chunk Q13, 0x009DD960) Two reads of one global float into two struct fields become one integer load plus a register copy (`mov edx,[g] ; mov eax,edx`) when both statements come after the neighbouring zero stores (0x009DD9C8). Written earlier, they compile to two loads; written as `b = a.f`, they compile to fld/fst/fstp.
- (chunk Q13, 0x00666310) At this site, even `((unsigned char*)this)[0x15c] &= 0x7d` compiles to load/and/store through al. Retail's `and byte ptr [esi+15Ch],7Dh` is therefore not decided by the member spelling: a bool bitfield, an unsigned char bitfield and an inline clear member all give the same bytes.
