- (0x007F2DC0) Spelling an alive test out (`p.Get() == 0 || p->IsDead() || ...`) instead of `!IS_THING_ALIVE(p) || ...` adds an `||` term and HALVES the static frequency of all later code: that moved three inline decisions in a later loop (IS_THING_ALIVE 72 -> 117, CIntelligentPointer(T*) 85 -> 150, operator= 64 -> 112) to retail's "called". - (0x007F2DC0) A `for (; it != end; )` loop with `continue`s is weighted like a `while` (body x9, test x10 in the inline trace); an `if (x == 0 || x->IsDead()) { erase; continue; }` makes the two identical erase blocks cross-jump into one (retail keeps two: write `!IS_THING_ALIVE`-shaped single tests).
- (0x007F2DC0) An `if (!v.empty()) { iterator it = v.begin(); <call>; do { ... } while (++it != v.end()); }` gives retail's guard-then-aligned-loop-head with no re-test after the call (`for` re-tests after the call because the vector escaped).
- (0x007F2DC0, solved in the continuation) VC7.1 forwards a single-use copy of a member (`long t = m; ... (float)t`) into its use unless a CONTROL-FLOW JOIN lies between def and use. Retail's `mov eax,[m]` / `mov [esp+X],eax` / later `fild [esp+X]` = the copy followed by something that materialises through a join before the use: here `const bool has_life_time = PDef->LifeTime > 0.0f;` between `long timer = Timer;` and `if ((has_life_time && timer > ...)` (the join is threaded away later, the copy stays, and the load is scheduled between the bool's `fld` and `fcomp`).
