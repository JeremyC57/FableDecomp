# Chunk 257 -- lessons from the authoring agent (fold into GOTCHAS at landing)

- Chunk ReadFromFile rows (0x00AA9BA0, 0x00AB9FC0, 0x00ABA170, 0x00AAAB10): the landed 0x00AA5370 stream model (inline `Read` + by-value `ReadLong/ReadFloat/ReadULong`, virtual slot 6 `ReadNullTerminatedString`, by-value `ReadMatrix3x4`/`Read3DVector`) matches first try; a version word read and dropped is a bare `in.ReadULong();`; `Planes.resize(count)` is the inline STLport `resize(n, T())` over out-of-line erase/insert.
- `while ((length = strlen(text)) != 0)` gives retail's `sub eax,edx ; test eax,eax ; mov [len],eax ; je`; a separate `length = strlen(text)` before the loop and at its bottom drops the `test` (0x00A2ED10).
- An inline CCharString accessor tested null-first (`Data == 0 ? "" : Data->Text`) gives retail's `jne nonnull ; mov eax,"" ; jmp`; `Data ? Data->Text : ""` lays the arms out the other way (0x00A2ED10).
- Two arms that each compute a CRC then UpperBound-LowerBound are `__forceinline` GetNoDummyObjects/GetNoHelperPoints helpers called per arm; same-TU noinline bodies for `_M_insert_overflow` and the four bound searches let the name temporary and the tag live in the dead argument slots (frame 0x18 -> 0x10) (0x00A2ED10).
- Nested counted-pointer walks: when the inner pointer's destructor runs AFTER the outer FindNext call, the inner pointer is a local of the outer `while` body, not a `for` init (0x00ABC1B0).
- A 12-byte struct (C3DVector) that VC keeps in ebx/ebp, where retail keeps it in the frame, needs a user copy constructor. Without one, the struct is scalar-replaced, which steals the callee-saved registers that retail gives to the loop variables. Seen at 0x0092A220, and also 0x00929340, where the copy constructor lets operator+ build straight into the by-value argument slot.
- Register colouring in loops: when retail caches a member that is read once per iteration (e.g. ebx = Action) and reloads a loop-invariant local (proximity), copy the member into a named local just before its use (`long action = Action;` ahead of the dead lookup). This frees the register VC would otherwise spend on the invariant (0x0092A220).
- `do { ... } while (result == 4); return result == 2;` reproduces retail's unrotated retry loop (`cmp ebp,4 ; je top`). A `for(;;)` with `if (result != 4) return ...` gets rotated, and the call block is duplicated (0x0092A220).
- AI-action calls whose action temporary sits inside `&&` get VC conditional-temporary flag words (`mov [esp+x],0` at entry, `test byte [flag],1` before the destructor). Retail rows without such flags store the action result in a statement (`EAIActionReturn r = AIAction_...(&CAction(...), ...); if (r == 2 && ...)`). Retail rows that have the flags really do write `if (flag && Perform(&CAction(...)) != 2)` (0x0095E0B0 v 0x00929340).
- VC7.1 has a per-function inline budget. In a long Update, the first IS_THING_ALIVE checks and CIntelligentPointer copy constructors are inlined, and the later ones become out-of-line calls (0x0069CE20 / 0x00654D58). Defining them as plain `inline` functions reproduces the split; forcing everything inline or everything out of line does not (0x0095E0B0).
- A distance between a thing pointer and the creature, written through a `__forceinline` helper `(a->GetPosition() - b->GetPosition()).GetLengthSquared()` called with `(node.GetPItem(), GetCreature())`, gives retail's order: creature load, GetPItem, creature GetPosition, then the thing's GetPosition. Written inline, the call order is wrong, and a non-forceinline helper is called out of line (0x00929020).
- x87 sums of three squares over stack temporaries: `Y*Y + X*X + Z*Z` emits retail's ZZ, YY, XX order (`fld st0 ; fmul st1 ; fld st2 ; fmul st3`). Writing `X*X + Y*Y + Z*Z` emits ZZ, XX, YY instead (0x00929020).
- Engine headers that flatten the base (`__vftable` as void*) must not gain virtuals in the method struct, because that adds a second vptr and shifts every member by 4. Dispatch through a separate `CXxxDispatch` struct cast from `this` (0x00929340, 0x00929020).
- Virtual slot 70 (+0x118) of the thing placement (+0x60) is GetFacing, returning C3DVector by hidden pointer. Slot 72 (+0x120) is GetOrientation, returning const CRightHandedSet& with Forward at +0xc (0x0094F480, 0x00929340).
