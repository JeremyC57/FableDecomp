# Chunk 402 -- lessons from the authoring agent (fold into GOTCHAS at landing)

- `__forceinline` GetTC that copies the type into a local key (`long key = type;`) before LowerBound gives a compare against the constant or register. Binding the parameter itself to LowerBound's reference instead makes VC re-read the slot for `type < it->type` (`mov ecx,[esp+4] ; cmp ecx,[eax]`) (0x0085EEB0, all 24 family rows).
- Two interface lookups in one function, both written as out-parameter `GetInterface(&p, type)`, share ONE frame key slot (`push ecx`). HasTC + GetTC twice gives two slots (`sub esp,8`) (0x0085EF70).
- The out-parameter GetInterface keeps the component in eax, and the scratchpad byte is read through cl. The `(T*)GetTC(type)` form puts it in ecx or edx (0x0085F880, 0x0085FD70, 0x0085FE60).
- For a placement copy of a struct with a PDB `bool` that retail copies as a whole word, write a memberwise user copy ctor and model the bool as `unsigned long`. The result is five dword moves. The implicit copy gives a re-based block copy, and a real bool gives a byte move plus a register shuffle (0x0085D7A0).
- `x == y ? false : true` on a `bool` operator== result gives the 8-bit `neg al ; sbb al,al ; inc al`. `!(x == y)` gives the 32-bit `sbb eax,eax`, and an inline operator!= pushes the literal after the call (0x0085FBC0, parked for another reason).
- The STLport list ctor written as `_M_node(0)`, a `__tmp` sentinel linked to itself, then `_M_node = __tmp` gives retail's zero store, the self links, then the pointer store (0x00863170).
- An inlined `push_back(&ref)` = `insert(end(), x)` with placement new reads the argument slot straight into the node (0x008631D0).
- `if (fallback == anim) return 0; return anim;` is if-converted to `xor ecx,ecx ; cmp ebx,eax ; sete cl ; dec ecx ; and eax,ecx`. Putting the FIRST lookup on the left of `==` gives `cmp ebx,eax`; `anim == fallback` gives `cmp eax,ebx` (0x008618B0).
- The same helper inlined into a caller that null-tests it folds to `cmp ebx,eax ; je zero ; test eax,eax ; jne call`. Writing `if (!anim) return 0.0f; return f(*anim);` keeps the zero block on the fall-through; `if (anim) return f(...);` puts the call there (0x00861C90).
- A vector length read in place from a member C3DVector (`info->MovementVector.GetLength()`, sqrt(X*X+Y*Y+Z*Z)) loads Z, Y, X, because VC evaluates the right operand of a float `+` first. A C3DVector built from the three floats loads X, Y, Z whatever the sum order. Model the PDB's member C3DVector when the engine header flattens it (0x00861950).
- `float distance = length * 0.01f;` as a named local keeps the constant multiply right after fsqrt. Inside one long product chain (`len * 0.01f * a * b / c`) VC moves the constant multiply to the end (0x00861950).
- Two separate early returns with identical bodies (`if (it == end()) return null; if (!it->second.Data) return null;`) give one merged null block on the `jne` fall-through. One `||` condition moves that block to the end of the function (0x00857430).
- A same-TU `auto_inline(off)` + `__declspec(noinline)` body for the const LowerBound (0x004365B0) lets a later address-taken local reuse the dead lookup-key slot, here the radius out-parameter in the thing argument's home. With the external declaration VC keeps the key alive and the frame is 4 bytes bigger. This is the chunk 240 lever, now confirmed for float out-parameters (0x0085B160).
- In an inlined filter, `const T* p; if (thing.GetInterface(&p, 0x7f)) p->GetBoundingSphere(c, r, true);` pushes the arguments in retail's order. GetTC inside the call expression interleaves the lookup with the pushes differently (0x0085B160).
- A type-traits tag passed by const reference as a named local (`__false_type isPOD; f(..., isPOD);`) costs no store. The value-initialised temporary `__false_type()` adds `mov byte ptr [esp+N],0` (0x0085DFD0).
- A getter that retail calls BEFORE an inline ctor's stores (CAnimInit's Frame zeroing) is read into a local declared before the object (`unsigned long flags = anim->GetAnimateThingFlags(); CAnimInit init;`). Calling it inside the Init argument list puts the zeroing stores and `push 64h` first (0x008619C0).
- Define an anonymous-namespace function inside `namespace { }`. A global-scope definition after an anonymous-namespace declaration emits `?Name@@...` (a different global function). VC7.1 does emit the unreferenced anonymous-namespace body. The leaf must be a prefix up to `?A0x` because the hash differs per TU (0x008619C0, 0x0085B160).
- A vptr-only filter temporary (inline virtual dtor in the base) passed by const reference leaves no destructor vtable store behind. The constructor's vtable store is scheduled after the argument pushes (0x008619C0).
- For a non-polymorphic class freed with `delete p`, `??_G` (`QAEPAXI@Z`) is emitted. A CIntelligentPointer<T> member whose derived class declares no destructor is destroyed by a direct call to the base's out-of-line ~CBaseIntelligentPointer, with no vtable store (0x0085AE90).
- Return-tail order gap (parked): the final `mov al,1` / `xor al,al` pair after the last test comes out in the opposite order to retail. This resisted `||`, switch, separate ifs, optimize("s") and the QFE compiler (0x0085FA00, 0x0085FB30). The same gap affects the shared false block placement in 0x0085FBC0.

Review at landing:
- Two leaves are prefixes ending in `?A0x` because the anonymous-namespace hash is per TU: 0x0085B160 and 0x008619C0. Check that the lander matches a leaf by prefix, as `q.py` does.
- 0x0085B160 carries a same-TU LowerBound stand-in body (a second function in the object). Its leaf selects the operator() instance.
- 0x0085DFD0 element type (NThingMap::CThingMapCell) comes from the caller chain plus Ego_r.pdb CThingMap::Cells, not from a symbol at the address.
- 0x0085AE90 class identity comes from the member layout only. There are no callers or references.
- The family uses a local CThing / CThingCreatureBase model: engine/CThingCreatureBase.h disagrees with retail at +0x100. 0x00861950 uses a local C3DAnimationInfo, because the engine header flattens MovementVector into three floats.
- The landed 0x008350D0 comment has CAnimFilterAnyGroup's vtable slots 0 and 2 swapped (slot 2 is the deleting destructor).
