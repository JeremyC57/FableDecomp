- A STLport non-POD vector destructor that calls `__fastcall __destroy_range(first, last, const __false_type&)` needs a NAMED empty tag local (`__false_type tag;`): a `__false_type()` temporary emits a dead byte store.
- An inline vector-of-objects destructor loop must cache the end pointer (`T* last = _M_finish;`) to get retail's `mov ebx,[esi+n]` loop bound; re-reading the member each iteration gives `cmp edi,[esi+n]`.
- A value that retail keeps in a callee-saved register after an inlined Read(&local, 4) is an inline `long ReadLong() { long v; Read(&v, 4); return v; }` helper: the helper's frame word is read once and the value lives in the register; a plain `long length; Read(&length, 4);` re-reads the frame.
- A retail store into a dead argument slot late in a function (`mov [esp+argN],eax ; lea eax,[esp+argN] ; push`) is an inline helper's by-value parameter (`WriteLong(long v) { WriteData(&v, 4); }`); a fresh named local gets a new frame slot and reassigning the parameter forces its earlier reads through memory.
- `cmp ebp,[ebx+14h] ; jg` in the inline stream Read is `if (size <= SourceChunkBytesRemaining)`; the reversed operand order (`cmp [ebx+14h],ebp ; jl`) comes from `Remaining >= size`.
- An inline helper with no frame of its own homes its locals in the function's dead argument slots (ReadLong's value at [esp+4] over the `in` reference argument of CDefStringTable::ReadTable): this one is NOT a lane gap.
- NPlayerGui UI rows are `#pragma optimize("y", off)` + `("s", on)` TUs; a by-value CRGBColour argument is built in its argument slot only when the class has a user copy constructor (B,G,R,A layout, ctor body assigns R,G,B,A), otherwise it is built in the frame and pushed.
- A `fld dword ptr [0x0122xxxx]` next to `fld1` in UI code is a float-pool literal (0.5f at 0x0122F59C), not a named global: check the .rdata value before declaring an extern.
- `(world = World)->Query()` inside the third `&&` term names the pointer register (edi) without hoisting the load above the earlier calls.
- A map destructor inline in a class destructor follows the landed CRetailTree_erase model exactly (erase(head->parent), head->left/parent/right reset, count = 0, free(head)) and VC schedules the CCountedPointer / CWideString destructors around it without help.
- CDefinitionManager retail layout = engine header minus 4 per 16-byte PDB vector (SymbolPathList +0x40 .. RecompiledDefs +0xc4); CCountedPointer<CSymbolMap> is {object, SCountBlock*} with the per-type `__fastcall Destroy` at block +4 (`mov ecx,[eax+8] ; call [eax+4]`).
- A ctor whose only diffs are a scheduled argument load and a `lea` pair inside a 30-store zero run is a scheduling lane gap: init-list vs body placement of nearby members did not move them (0x009B0470).
- Two CDefPointer temporaries released in sibling arms: when ours shares one frame slot VC merges the arms into one tail; retail with distinct slots keeps them apart -- no source lever found (0x0064BE45).
- When retail calls `mov ecx,[esp+this] ; add ecx,8 ; call GetPItem` repeatedly, VC with a free callee-saved register will hoist `lea ebp,[ecx+8]` instead; an inlined member helper did not stop the hoist (0x008D5300).
- 0x004C73D0 has a 4-argument overload: the `lea edx,[esp+n] ; push` before it points at the scoped empty CCharString, not at a C3DVector out-param (frame 0x14, not 0x20).
- `fistp [ebp+arg] ; fild [ebp+arg]` round-to-nearest helpers over a dead argument slot (0x00646010, 0x0064D404) stay a lane gap: park at once.
