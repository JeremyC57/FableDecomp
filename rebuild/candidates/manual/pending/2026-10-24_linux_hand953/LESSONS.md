# Chunk 953 -- lessons from the authoring agent (fold into GOTCHAS at landing)

## Codegen (source form -> retail shape)

- **Loop iterators that survive an erase are declared before the loop.** In list::erase loops, declare `next` together with `it` ahead of the loop and give a converting temporary (CCountedPointer<Base> from CCountedPointer<Derived>) its own named block. An unnamed conversion inside the `if` reused the constructor's eax, and `next = it; ++next` inside the loop gave an extra `mov ebx,[esi]` (J002 0x00660787, 115v118 -> RELOCATION_MATCH).
- **STLport trees compiled against a visible compare.** `_Rb_tree<CCharString, ...>::insert_unique` matches only when the landed `less<CCharString>::operator()` / `CBasicString<char>::operator<` bodies are in the TU (noinline). Declared-only compares make VC7.1 reload the header pointer after each call (J045 0x0042BD4A, 153v166). The hinted insert also needs the `_Rb_global<bool>::_M_increment/_M_decrement` bodies in the TU (J046 0x0042C940, 449v456).
- **Traits objects get a store and a slot only when their body is compiled later in the TU.** In GFSerialiseMapBinaryIn, function-scope keyTraits/valueTraits plus explicit member specializations reproduce which traits bodies retail had already compiled. Use the row's entry bytes to decide which bodies are visible (J060/J061 0x0045DADB, 4 grades; J047 0x004312B4 re-stamped from the same model).
- **Empty tags and the dead argument slot.** A constructor-less `__false_type`, with the `__uninitialized_copy`/`__uninitialized_fill_n` bodies explicitly instantiated ahead of the growth insert, makes all three tags share the padding slot (J071, 177v176 -> RELOCATION_MATCH). A stand-alone `struct random_access_iterator_tag { };` is an aggregate: `random_access_iterator_tag()` zero-fills its byte. Use STLport's derived tag hierarchy (J095, 102v97 -> RELOCATION_MATCH).
- **A same-TU `__declspec(noinline)` __copy body homes the empty tag in the LIVE `first` slot**, as retail does. A declared-only __copy uses the dead `last` slot (J092, 77v77 -> RELOCATION_MATCH).
- **Inline-or-not under /Os.** VC7.1 keeps a class-body `~CDefPointer()` out of line under `optimize("s")`; `__forceinline` brings it back (J081, 27v40 -> RELOCATION_MATCH). In vector::erase(first, last) over trivially-assigned records, a plain `inline` __copy also stays out of line, so `__copy_ptrs`/`__copy` need `__forceinline` (J102, 43v99 -> MATCH).
- **Write CDefPointer accessors in the landed form.** Use `if (Object) Object->Release();` (or the PDB's mutable IVRefCount AddRef/Release). A local-copy destructor that nulls Object schedules `dec eax` ahead of `push esi` (J099, 32v32 -> MATCH).
- **A size-optimised CTCVillage TU wants two separate `if { assign; return true; }` tests.** One `||` condition loads the vptr first and folds the false return (DIFFER 48v52), and without `#pragma optimize("s", on)` the result is DIFFER 53v52 (J105 0x006584C5, 3 grades).
- **Private CPlayer methods use the layout-rename include.** `#define CPlayer CPlayerPdb` / include / `#undef`, then `class CPlayer : public CPlayerPdb { void Method(...); }`. Opaque members are reinterpret_cast to their real types, and the component comes from the inline `GetTC<T>(T**)` (J104 0x00635080).
- **Compiler-generated destructors.** CIntelligentPointer<T>'s destructor is implicit (vtable 0x01238C6C has one slot), so a containing class's ??_G and STLport element loops call `CBaseIntelligentPointer::~CBaseIntelligentPointer` 0x00A01C10 directly, with no vptr store. A user `virtual ~CEventBase() {}` stores the base vptr. The vtable that a ??_G needs is emitted through a `void* MakeOne() { return new X(...); }` modelling device (J108/J109).
- **STLport __copy's source const-ness follows the caller.** vector::operator= passes `const_pointer` (`__copy<const T*, T*, int>`); erase and resize pass `pointer` (`__copy<T*, T*, int>`). One element type can therefore have two distinct out-of-line __copy COMDATs, for example 0x00672F40 (const) and 0x0086EFA0 for `pair<EExpressionType, CExpressionSet::CEntry>` (J112).
- **~vector and _M_clear have the same body.** The function is ~vector when it runs in a destructor context: an atexit stub, a class destructor, or the jmp thunks of CArray/CVectorMap destructors. It is the protected `_M_clear()` (IAEXXZ) when its only caller is the vector's `_M_insert_overflow` (J113 0x00687180 vs 0x008E38D0, same element type).

## Identity (naming) recipes

- **FableWin.pdb's per-type member sets identify a container's element type.** The sets of `pop_front`, `remove_if` and `clear` instantiations do this even for unreferenced rows. 0x009C6C60 (J110) is `list<CCountedPointer<const CFileInstaller::CFileInfo>>::erase` by elimination: FableWin.pdb has pop_front for exactly four counted-pointer list types, and the other three are the family's other rows.
- **For list clears, get the element from the owner's destructor offset (retail offsets, not Ego_r).** Then confirm it with the code that fills the list: `new` plus the stored vtable's RTTI, wrapped by the CCountedPointer(T*) constructor and push_back. CSoundEmitterLH::CActiveSound (0x00AACC60) is named only by RTTI; neither PDB has the class (J111).
- **A def's operator= / Transfer slots identify CDefPointer member types.** CCreatureDef::Transfer is slot 18 and Copy is slot 19 (vtable 0x0125B43C). +0x28 is PWoundMorphs, +0x30 PRandomAppearanceMorph, +0x38 PExpressions and +0x40 PStats, which settles which TransferBinaryIn and vector operator= belong to CExpressionSet (J112).
