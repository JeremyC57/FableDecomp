# Chunk 111 -- lessons from the authoring agent (fold into GOTCHAS at landing)

- MSVC lays OVERLOADED virtual functions out in reverse declaration order: `virtual CMap& GetMapAt(const C2DCoordI&); virtual const CMap& GetMapAt(const C2DCoordI&) const;` puts the non-const one in the HIGHER slot. Declare the const overload first to get retail's slot 14 = non-const, 15 = const (CThingManager::GetMapAt 0x0051DEE0 / 0x0051DF20); a const member calling through a non-const member pointer still picks the non-const overload -- `static_cast<const T*>(p)->` selects the const one.
- A `??_G` with no vtable store whose counted member is released `mov ecx,[esi+N] ; test ; je ; dec [ecx+4] ; jne ; call [eax+4] ; mov [esi+N],0` reproduces only with the release as a member of the BLOCK (`m_pBlock->Release()` with `if (--m_references == 0) Destroy();`); the same test written in the pointer's destructor re-reads the member after the decrement (0x00A009A0, 0x0084B620, 0x00982550). A derived class with a compiler-generated destructor calls `??1` out of line from its `??_G`; the first-member model inlines it.
- A struct copied with `mov edx,[eax] ; mov [esi+20h],edx ...` straight into the destination members (no `lea edx,[esi+20h]`) in a constructor initialiser is a class with a memberwise USER copy constructor (C2DBoxI in CThingMap 0x0085D370); the implicit POD copy goes through a `lea` base and edi.
- DirectShow base classes: `AM_NOVTABLE` (`__declspec(novtable)`) on CBaseFilter and its interfaces explains constructors with no vtable stores at all; the SDK layout and initialiser list reproduce as published (0x00CAC830).
- A call whose result is unused right before a `__stdcall` call that never reads ecx is a STATIC member called through an object expression (`GetDisplayEngine()->DivideByGameSpeed(x)`, 0x00702C60): VC evaluates the object, never loads ecx.
- `unsigned __int64` behind a vptr realigns the class to 8 (`[eax+20h]` instead of `[eax+18h]`): `#pragma pack(push, 4)` for the CThing UniqueID at +0x18 (0x005202F0, 0x005215F0).
- A map key copied into a frame temporary before `erase(const key&)` comes from an inline accessor returning the key BY VALUE (0x005215F0); an 8-byte `pair<iterator,bool>` insert result returned through a hidden pointer needs a user constructor on the iterator.
- `find(k) == end()` written inline loads `end()` (the head) before the find call; a named iterator local keeps retail's `cmp eax,[esi]` after the call (0x00521A90, parked for register choice only).
- The 14-byte packed CEngineGraphic copies as `movsd x3 ; movsw` only in a size TU (`#pragma optimize("s", on)`, the Def::Copy family 0x00464498 / 0x004644C0); the speed TU copies it through edx/ax (0x0083BA20).
- `if (base) { if (c && x < k) return byte_expr; return true; } return false;` -- the nested form keeps retail's shared `xor al,al` tail; `if (!base) return false;` returns the callee's al directly (0x00702C60).
- `!bitfield` in a bool return gives `xor eax,eax ; mov al,[..] ; shr eax,n ; not eax ; and eax,1` (0x00703470).
- Retail CThing layout confirmed across rows: +0x18 UniqueID (u64), +0x20 component presence bitset, +0x44 interface map, +0x5c driver TC, +0x60 PhysicsTC, +0x64 PTCGraphicAppearance, +0x7c/+0x80 render-list links, +0x8c DefGlobalIndex, +0x91 flag byte (bit 0 Dead, bit 1 CreatedByOwnerThingCreation); CThingManager: +0x18 thing list (VC6 list head), +0x28 WorldMap, +0x54 NonScriptedEntitesPauseMode, +0x58 UIDToThingMap, +0x84 RenderList, +0xcc NPCNameMap.
