# wfE2 LESSONS
- (0x00E33EA0) `Give(Def->Vec[rand() % Def->Vec.size()])` through CDefPointer::operator-> makes VC7.1 evaluate the vector object (def pointer) BEFORE the rand() argument and keep it in a callee-saved register across the call (+8 bytes per site, register rotation over the whole tail); retail reloads the global after rand(): compute the index into a block-local first (`unsigned long idx = rand() % size; ...[idx]`). 75 hunks -> 2 in one step.
- (0x00E33EA0) An old draft with 300+ differing lines may be a handful of discrete facts: run the call-target diff (tools/ct.py) first; equal call lists + equal length mean the rest is local (here two swapped arguments, visible as push order: `push 0 ; push &Me ; call GetHero ; push eax` = f(GetHero(), Me, false)).
- (0x00D0F640) Retail per-site inline decisions can be impossible for ANY uniform threshold when the cut-scene block must expand a callee (map ctor) that scores above callees the later block must call; compute the needed frequency ratio from the trace (score order map ctor < ~CScriptThing < ~vector at equal f) before trying loop spellings.
- (0x00E5FD40) A 9.4 KB CV_ script Main went 9471 -> 9381 (equal length, 8 hunks) by ONE change: the main loop `for (; !false; Game->NewScriptFrame()) { if (T) return; ... }` (the CBanditKing 0x00D0A830 spelling) instead of an earlier lane's folded `for (; !T && true; NSF)`; try the landed siblings' exact loop spelling (`!false`, not `;;`, not `!T`) before any frequency device.
- (0x00D973D0) When retail never expands a cheap inline dtor (~CTimer, sz 20) but ours does at a few return sites, check the trace for f=1.0000 sites: returns inside an endless `for(;;)` body and the return after `if (!T) continue;` are scored at f=1.0 (sc 14) whatever the nesting; a `while (cond)` loop removes them (and lets every exit pad cross-jump into the shared final chain, one ret like retail).
- (0x00D0F640) When the natural shape EXPANDS every site retail expands and only over-expands, stop fitting frequencies: (1) find the smallest /d2inlT<N> that calls the extra sites, (2) FABLE_FORCEINLINE a row-local inline whose wanted-E sites score above any usable N and put inline_depth(0) round the one statement where retail calls it, (3) if two dtors share a return and must split (vector<CScriptThing> called, vector<unsigned long> expanded), change the loop spelling before that return (`while` v `for`: post-loop block f 0.3 v 2.06) instead of a pragma, which calls both.
- (0x00D973D0) The landed-sibling main-loop idiom `for (; !false; Game->NewScriptFrame()) { T; ...}` also fixes INNER loops: c2 emits the body-top T once before the loop and again after the NSF (retail `je top ; jmp exit`), and removes the f=1.0 return sites that expand cheap dtors (~CTimer) in an endless `for(;;)` body. 9964 -> 9805 in one grade.
- (0x00D973D0) neg/sbb/inc on a call result kept across a temp dtor = the source NEGATES that result (`while (!IsRegionLoaded(...))`); a draft with the plain test can be normalised-equal elsewhere and still be a behaviour bug.
- (0x00E5FD40) When retail keeps the FIRST arm's copy of a tail that all arms of an if/else-if chain share and the other arms jump into the middle of it (into the temp dtor call), and the arms schedule `mov bl,al` before vs after `lea ecx` differently, the source had ONE tail behind a shared bool (`bool said = false; ... said = f(); ... if (said) {tail}`): jump threading, not cross-jumping, produced the merge. A forward chain with per-arm copies always keeps the last copy.
- (0x00D973D0) Before fitting a frame-slot residue, run pk.py --iset: a size-1 item that interferes with nothing still lands in the MOST RECENT compatible slot (hand890 TRACE: join scans slots newest first), so its slot is decided by its processing order (weight = memory refs after RA, ties by creation order), not by liveness; an extra register-only read does not raise the weight.
