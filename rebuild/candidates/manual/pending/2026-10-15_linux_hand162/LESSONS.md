# Chunk 162 lessons (for GOTCHAS)
- An STLport map::find modelled as returning a one-pointer iterator struct with a member function returned through a hidden pointer here; declaring it to return the node pointer gives the eax result (0x812E20/0x812EB0).
- Two by-value key copies into the same frame slot before find and erase, with the key itself in ebx/ebp, come from a UID local passed to two `__forceinline` helpers taking the key by value; const-reference calls on the local (even with casts) merge into one copy (0x813100).
- A frame-pointer ctor whose out-of-line list ctors get `lea eax,[ebp+0Bh]` is `optimize("y", off)` + `("s", on)`: the default `allocator()` argument temporary lands in the top byte of the dead parameter slot (0x4DEFA7, CTCKraken). So the "one byte packed into a parameter slot" shape is reachable outside /GS.
- An unrelated polymorphic empty base (CBaseClassNonCopyable, out-of-line ctor storing a vtable) must be the polymorphic root, or the derived vptr is placed first and the base call gets `this+4` (0x778D60).
- C3DVector's user copy ctor (`X(o.X), Y(o.Y), Z(o.Z)`) fixed three more register rotations: a member init from a const reference, an interpolator ctor and a by-value return of a referenced vector (0x778D60, 0x6E0500, 0x6E0620).
- A dtor with no own vtable store over an out-of-line base dtor = `__declspec(novtable)` class (0x9CB350 NGameText::CTextEntry); STLport `_Destroy(first, last)` taking the bounds by value keeps finish in a callee-saved register.
- `test edx,0FFFFFFF0h ; je` before an index loop ending in `jne` is `for (unsigned i = 0; i != v.size(); ++i)` over 16-byte elements (`<` gives `sar 4 ; test ; jbe` and `jb`) (0x80C350).
- VC7.1 canonicalises x87 sums of squares of float locals regardless of source operand order (only the association changes the order), so retail's dz,dx,dy / dx,dz,dy orders were not reachable (0x6CB620/0x6CB6E0/0x6CB840).
- Retail sometimes keeps the GetInterface component in ecx on both arms (`mov ecx,[eax+4] ; jmp ; mov ecx,[esp+N]`); every source form tried gives eax + `mov ecx,eax` (0x784600, 0x683650, 0x749BF0), while landed relatives in other TUs do use eax: treat as a lane gap after one try.
- Five labels in this chunk were byte-twin / propagated constructors and destructors of other classes (vtable store checks: CGlobalDef, CTCOverheadDisplay, CTCKraken, CThingPhysical, NGameText::CTextEntry) plus one SGI __pop_heap.
