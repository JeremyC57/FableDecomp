# Chunk 278 -- lessons from the authoring agent (fold into GOTCHAS at landing)

- CAIStateGroup interface lookups where retail stores the result to the SAME frame word as the key (`mov [esp+X],0xad ; ... ; mov [esp+X],edx ; mov ecx,[esp+X]`): write the key into the out variable itself, `*(long*)&boss = 0xad; it = map->LowerBound((long*)&boss); boss = ...;` -- the address-taken out slot keeps the component in memory instead of a callee-saved register (0x00954F40 went from 597v604 to 604v604).
- When retail tests the present bit and stores it as a byte (`shr ecx,N ; and cl,1 ; mov [esp+X],cl`), write `bool has = (bits[w] >> b) & 1; if (has) {...}` explicitly (0x0095B020, 0x00915350).
- A search rectangle written member by member (`area.Left = x - r; area.Top = y - r; area.Right = x + r; area.Bottom = y + r;`) as a function-scope local reproduces retail's `lea ecx,[eax-r] ; add eax,r` schedule and keeps its own frame words. A block-scoped rectangle or a ctor shares the next vector's slot and schedules x+r first (0x0095B020 RELOCATION_MATCH).
- `GetValidPositions` 0x0074A5D0 is `__fastcall(vector& out, nav, map, const C3DVector& pos, float radius, long, long)`; edx is the CWorld slot-12 result. Evaluating the world, creature and world map into named locals in that order reproduces retail's argument order. Repeating `positions.size()` inside WorldRandomRange keeps the retail `test edi,edi ; je` zero guard; reusing the tested `count` lets the compiler drop it.
- A temporary CThingFilter built in the argument list from a NAMED CCharString keeps the `lea` re-address of the name (a CCharString temporary instead passes the ctor's `eax`).
- Distance compares: when retail pops the vector temps before `fcomp` (`fstp st(2) ; fstp st(0) ; fcomp K`), store the squared length in a named float before comparing. An inline helper (`__forceinline bool IsMotherClose()`) used in an `||` with the alive test merges both failures into one tail block (0x00915350).
- `IsAlive`-style inline helpers and ctor-form `operator-` must be `__forceinline` in big bodies, or VC7.1 emits calls.
- MoveToThingProximity / LookAtThing argument pointers: fetch `GetPItem()` into a named local BEFORE the call. The inline `CIntelligentPointer<const CThing>(CThing*)` ctor (base ctor + vptr 0x01237F1C + SetPItem) then runs after the constant pushes, as in retail.
- Hand-released defs (`T* def = 0; GetSubDef(&def);`): retail null-checks only on the exit before the def is first used. Later exits do `dec [ebp+4]` directly, so write those exits as `if (--d->RefCount == 0) d->Destroy();` without a null test, with `d` a named copy.
- Retail `free` thunk 0x00BFEA14 releases STLport vector<C3DVector> storage. 0x0066E370 is `_M_insert_overflow(pos, x, __true_type, 1, true)` for the inlined `push_back`; placement new gives the `cmp ecx,0 ; je` guard.

- Inline fast Normalise (table 0x013CE558, 3.0f/0.5f Newton step): when retail SPILLS the reciprocal (`fstp [r] ; fxch ; fmul [r]` x3), write `*this *= FastInvSqrt(lenSq)` with `__forceinline C3DVector& operator*=(const float& s)`. The const-ref binding to the inline temporary forces the store. Every plain form keeps r on the x87 stack (`fst [r] ; fmul st(2)`): X*=r, by-value operator*=(float), a union or address-taken r, or /Op. When retail keeps r in a register (0x00973DC0), use the plain `X *= r` body. This took 0x0095BCF0 from 967 to 948v948 and 0x0095AD20 from 748 to 754v754.
- `Direction(const CThing* to, const CThing* from) { return to->GetPosition() - from->GetPosition(); }` as a `__forceinline` free helper reproduces retail's call order: `from` loads first, then to.GetPItem, from.GetPosition, to.GetPosition. Writing the subtraction inline calls the creature's GetPosition before GetPItem.
- A 2D length computed from the UN-normalised offset while a COPY is normalised (`C3DVector dir = offset; dir.Normalise(); ... offset.GetXYLength() < 12`) lets VC7.1 CSE the X*X/Y*Y squares into frame words, as retail does (0x0095B9E0).
- Retail's single `push 9 ; mov ecx,esi ; push eax ; call` after an index chosen by if/else is two calls, one per arm (`r = Goto(GetNext(), 9);` / `r = Goto(GetPrev(), 9);`), tail-merged by VC7.1. A named index with one call puts `mov ecx,esi` after both pushes.
- An array element whose begin pointer is loaded once and reused across two GetPItem calls (`mov ebx,[esi+50h]` kept in ebx) is a named reference `T& first = *v._M_start;`.
- A hand-released def read into a callee-saved register right after GetSubDef (`mov ebx,[esp+X]`), with the zero store scheduled after the push: give GetSubDef a same-TU `#pragma auto_inline(off)` stand-in AND copy the pointer into a named local `d` (0x0095BCF0).
- VC7.1 orders frame slots by TYPE CLASS, not by declaration order (advisor AdvB3 finding on 0x00954F40): reordering same-class declarations does not move them.
- `fpatan` on (x, y) is `atan2(x, y)` with `#pragma intrinsic(atan2)`. The JoB pillar facing is `atan2(X, Y) / 2pi` (0.15915494f) wrapped by `if (v < 0 || v >= 1) { v = fmod((double)v, 1.0); if (v < 0) v += 1; }`. Writing `!(v < 1)` gives `test ah,5 ; jnp` instead of `test ah,1 ; jne`.

Review at landing:
- Engine headers for these classes are flattened, so local layouts are used, with offsets cross-checked against retail disassembly (JackDragon pack(1); CThing +0x60 physics body, +0x70 def, +0x91 flags, +0x180 creature mother pointer).
- 0x0095C1F0 over-captures 0x0095C430/0x0095C440 and carries an 8-entry jump table: land only after the catalog split.
- /GS rows: 0x0095B020 (landed, sprintf buffer) and 0x00954F40 (parked).
- Rows that needed more than 4 grades: 0x0095BCF0 (15), 0x0095B9E0 (13), 0x00954F40 (12 + 16 advisor), 0x00915350 (11), 0x0095AD20 (8), 0x00941FC0 (8 + 64 advisor). Three HoverHornetQueen rows (0x0095AD20, 0x0095B9E0, 0x0095BCF0) are queued with advisor AdvB3; any match arrives as an advisor batch.
- Earlier parked rows 0x0095A490, 0x0091E270 and 0x009735D0 carry the same reciprocal-spill miss. Retry them with the const float& operator*= normalise form before anything else.
- GetSubDef<CAICreatureWillPowerIndicatorDef> labels at 0x008C33E0 and 0x0095C5C0 cannot both be right (the callers read different def layouts). 0x008C5410's BriarRoseShotFarInto label is likely propagated.
