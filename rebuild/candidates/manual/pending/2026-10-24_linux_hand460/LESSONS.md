# Chunk 460 -- lessons from the authoring agent (fold into GOTCHAS at landing)

- STLport two-argument `sort(first, last)` passes `__less(_STLP_VALUE_TYPE(first))`. Model `less<_Tp>` as deriving from `binary_function<_Tp,_Tp,bool>`: without the base, VC7.1 value-initialises the empty temporary (zero byte stores plus a register swap, 123v117). With it, the uninitialised `push ecx` frame word is pushed to every callee, as in retail (0x009B8440).
- vector::push_back taking `const T&` matches with `_M_insert_overflow` declaration-only (0x009B9170, 0x009CB740, 0x009CB790, 0x00AB4640). The by-value caller `RegisterBank(CBankFileAsync* bank)` needs a same-TU `__declspec(noinline)` STLport POD `_M_insert_overflow` body under `auto_inline(off)` before the __true_type tag is homed in the dead slot instead of its own frame byte (0x009D6420, 99v97 -> match).
- `CVectorMap::DeallocateMemory` is `Map.clear(); CVectorMap empty; swap(empty);`. The swap is the vector swap (three `std::swap` of the words) plus `std::swap(Dirty, other.Dirty)`. The empty temporary's destructor is what frees the old block (0x009E79E0).
- In introsort loops whose comparator is big (CCharString compare, CBankFile::CompareDataOffset), retail calls `__median` out of line. Declare it and let VC call it instead of inlining the STLport body (0x009B8B50, 0x009D48C0).
- `map::operator[]` over a value with a counted pointer: write the release as `info = Info; if (info && --info->RefCount == 0) { info->DeleteFunc(info->Data); delete info; }` (no zero stores). Then add a same-TU noinline `insert_unique(hint, v)` stand-in that reads v and may write its counted pointer. Declared-only, the escaped value_type temporary is re-read after `dec` (141/142v137). This is the landed 0x00A2D810 recipe, re-confirmed on 0x00AD6740.
- A forwarding overload whose tag lookup must come first (`return F(bank->GetTagFromCRC(name.GetCRC()), a, b, c, d)`) pushes the by-value bools before the CRC call. Retail computes the bank pointer and the tag in separate statements, so the global load is hoisted and the bools are re-pushed after the lookup (0x0066BED0, 94v93 -> match).
- A downcast to a multiply-inherited component right after a member read through the same pointer (`if (param->Type == 1) static_cast<CComponent*>(param)->Virtual(...)`) has no null test (`lea ecx,[edi-18h]`). The pointer form and the reference form `static_cast<CComponent&>(*param)` grade identically, because VC7.1 drops the adjust-null test once the pointer has been dereferenced (0x0053FDE0).
- STLport 4.6 `list::operator=` matches verbatim when the member-template `insert(pos, first, last)` is inline over a declared `_M_insert_dispatch(..., const __false_type&)` (tag with a user constructor). Both the erase result and the tag land in the dead `x` slot (0x00517720, 0x00535800).
- `__make_heap` over a 12-byte POD (CBlockInfo) builds the by-value `_Tp(*(first + parent))` word by word in the `__adjust_heap` argument slot (`mov eax,esp`) with no user copy constructor (0x00ADB420).
- calls.py matches `// Leaf:` as a symbol PREFIX. Bare substrings such as `__partial_sort` or `_M_insert_overflow` grade fine (largest symbol containing them) but show "0 blocks" in calls.py. Use `??$__partial_sort@`, `??$__introsort_loop@` and `?_M_insert_overflow@`.
- Several "std::_Iterator_base12::_Getcont" catalog rows are small engine methods (CWideString, CDefString, CTCSoundPlayer) with no STL in them. Always name them from the callers, the neighbouring landed rows and the PDB name sets.

Review at landing:
- 0x009C2900 (vector<C2DLineF>::reserve) is parked after 4 grades (frame-slot swap only). The next idea is in NOTES.md.
- 0x006AEB10 and the landed 0x004B7980 both claim `??8CDefString@@QBE_NABVCCharString@@@Z`, but their bodies differ (_stricmp call vs inline strcmp, 50 vs 107 bytes). Two different bodies cannot share one inline symbol, so one of the two is mislabelled. 0x006AEB10's single caller is the landed IsHeroPerformingExpression 0x008953A0. Check which of 0x004B7980's 12 callers expect case-sensitive equality before landing both.
- 0x00BFEBA8 is MSVCR71 `_stricmp` (IAT 0x014400EC), but the landed CBankFileManager::CloseRetailBank 0x009A78D0 and CBankFileEntryUpdateData::Equals 0x009CC750 declare it as `strcmp`. Check them against the lander's import-identity check.
- The landed CGroup `__adjust_heap` 0x00AD1DD0 is modelled in namespace `std` (leaf `...@std@@`). Its family (sort_heap 0x00AD4960, unguarded_linear_insert 0x00AD08B0, and this chunk's 0x00AD2CE0 / 0x00AD4880 / 0x00AD5BC0) is STLport `std`.
- Local models next to existing engine headers:

  - 0x009D4620 / 0x009D48C0 use a CBankFile_Retail model, because engine/CBankFile.h disagrees with the retail offsets.

- Same-TU noinline stand-ins (chunk-422 recipe): 0x00AD6740 (insert_unique stand-in that may write v), 0x009D6420 (STLport POD _M_insert_overflow body). Only the leaf function is graded.
- 0x0066BED0 uses the `""` literal for the shared empty string 0x0129AAF4, as the landed 0x0054F410 does. calls.py shows it binding to 0x0129AAF4.
