- A register-only residue on a vtable call through a def (`call [eax+28h]` on a CDefPointer) can come from a wrong callee identity: slot 10 is CDefClassBase::GetInstantiationName (CDefClassBase.h); with the right identities and the shared headers 0x00846DD0 matched with no register work at all.
- A `new` size mismatch (`push 8` v `push 20h`) means the local model of the allocated class lacks its members: give a header-less class its Ego_r.pdb members even when the row never touches them.
- One TU can call CIntelligentPointer<CThing>'s (T*) ctor / operator= out of line in one place and build a default pointer inline in another (base ctor + vtable + SetPItem(0), then GetPItem/SetPItem): spell the inline one as a default-constructed local + Set(0) + Set(other.Get()).
- Shared-header ports fix layout-driven residues (CArray byte vector, CDataInputStream::Read with a constant size held in a register) but leave loop-counter register swaps (i in esi v edi) untouched; stop after a few spellings.
- Defines must precede every include in a row: appending a second block of `#define FABLE_RETAIL_*` after Q25's include list silently skips them (CDefString ==, STLport list size).
- For `if (T) return; X;` tail blocks with destructors, `if (!T) X;` moves the return copy to the function end but changes which copy the other returns tail-merge into; keep whichever leaves fewer hunks and record both.
