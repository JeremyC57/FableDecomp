# Chunk 1009 lessons (one line each, ready for GOTCHAS)

- **A named bool read twice stays materialised.** 0x005A3734 / 0x005A8175 RefreshBuyPossibilityNumbers(PC) emit `cmp [ebx+18h],0 ; sete al ; test al,al ; jne` (0x005A383C). Write the stock test as one named bool (`bool soldOut = count == 0;`) that guards the PeekTC (`if (!soldOut) PeekTC(..)`) and opens the next `if (!soldOut && ..)`. These spellings all fold to `je`: one `if (count == 0) continue;`, a ternary local, and a file-static forced-inline predicate (plain or ternary).
- **Frame slots follow variable identity.** 0x005A8175 has retail's menu entry and its special-shop entry in one `[ebp-14h]` slot, above the PeekTC out-parameter locals. Reusing one `CComponent*` local for both gives retail's slot order. A second local takes `[ebp-24h]` and pushes the entry slot below the hero-stats / shop slots (1800v1800 with 3 slots rotated). Moving the declaration to the top of the function did nothing.
- **Cache the list end in a named iterator.** In 0x005B0AAC BuyItemPC, a list `end()` read once into a named iterator before the gold-text loop closes a 3-byte frame-slot residue (1515 v 1518).
- **Name the argument before the virtual call.** In 0x0059BB1B AttachToFrame, `child = X; frame->AddPositionChild(child);` puts the vtable load after the argument, where retail has it. The nested call form loads the vtable first. One reused `child` / `entry` local per block also fixes the frame-slot reuse.
- **AttachToFrame needs the opt-ins of landed 0x005A5B31.** 0x0059BB1B compiles only with `FABLE_RETAIL_CIVCOUNTEDPOINTER` plus `engine/ETCInterfaceType.h` and `engine/CThing.h` before `CTCInventoryTrade.h`. Without them the build fails with C2118 in CEnginePersistentPrimitiveBase.h. The row uses `optimize("s",on)` only (FPO).
- **Port a landed twin first.** Console/PC and buy/sell twins in CTCInventoryTrade match in one grade when you port the landed twin and change only the strings, members and callees. This worked for 0x0059D270 (from 0x0059CB90), 0x005A3E47 / 0x005A79E6 (from 0x005A45F6), 0x005A9A87 (from 0x005A887D) and 0x005A3734 (from BuyItem 0x005AF64E's sell-side subtitle code). Then 0x005A8175 came from 0x005A3734.
- **Wanted-total operand order is an open gap.** In 0x005A6769, VC7.1 loads `TotNumItemsWanted` first in `W + I + C`, while retail loads Weapons first. The matched sell / buy sums of the same function do load W first. The difference is that the wanted counters are `inc [mem]`. No spelling flipped the order: source order, the order of the reset stores, the switch-case order, or a sequenced `t = W; t += I; t += C;`.
- **Check the catalog extent of every 0x005B row.** The catalog gave 0x005B0AAC BuyItemPC 1793 bytes, but it ends at 0x005B109A (1518 bytes). Grade it through SPLITS.tsv / QLEN.
