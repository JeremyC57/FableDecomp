# Chunk 859 lessons (GOTCHAS one-liners)

- 2026-11-07 (chunk 859, 0x00A852B0 / 0x0058301A): VC7.1 address exposure is flow-insensitive: a local or temporary whose address reaches a DECLARED-ONLY callee is treated as aliased for its whole life (dead stores kept, reloads before every call, home slot pinned); give the callee a same-TU body kept out of line with `__declspec(noinline)` (what retail's TU had from the STLport / engine headers: `list::_M_insert_dispatch` 0x005152C0, `pair::pair(const pair&)` 0x00A825D0, `vector::_M_insert_overflow` 0x00A84C20, `~_List_base` 0x005127A0, `list::push_back` 0x005939EE) and the stores and reloads fall into retail's order. The lever only helps when retail's TU really saw the body: a stand-in body for a callee retail only declared (0x00F36A30 / CNoise::PerlinNoise) makes the row worse (350 v 361 B).
- 2026-11-07 (chunk 859, 0x00C75F80 CCombFilter::Allocate, MATCH after 391 grades): VC7.1 forwards a member store into a later load of the same member (and then CSEs what the forwarded value feeds -- here `m_size * 4` with the cursor bump's `length * 4` scale, hoisting the memset byte count) ONLY when the store and the load use the same base expression. Retail's shape (count formed at the memset site from the back end's register copy `mov ecx,esi; shl ecx,2`, `m_data` re-read `mov edi,[edx+4]`) comes from storing through a derived pointer (`CRingBuffer* ring = &m_ring; ring->m_data = ...; ring->m_size = ...;`) while calling `m_ring.Clear()` on the member. A residue that looks like "the count is hoisted / a value is re-read" is a forwarding-barrier difference, not a scheduling tie: try mixing a pointer/reference base for the stores with the member for the loads (or the reverse) before parking.
- 2026-11-07 (chunk 859, 0x006A9690): a joined float local (`float a; if (c) a = f(); else a = g();`) pushed straight into a member call makes VC7.1 emit the callee's `this` lea BEFORE the local's reload/push; passing it through a reference (`float& turn = angle; v.RotateXY(turn);`) gives retail's push-then-lea order. Micro-probe (probe/micro_lea*.cpp): a single-call result gives lea after push; a ternary, `+0.0f` or a second copy gives lea first; the `float&` form gives lea after push.
- 2026-11-07 (chunk 859, 0x0047ED76): on a stack-only x87 subtraction VC7.1 always emits the argument `push` before the `fsubp`; `fsubp` comes first only when the subtrahend is a memory operand (named float local or a vector half), which changes the surrounding bytes -- a `fsubp ; push` residue on a stack-stack subtraction is a scheduler tie, not a spelling.
- 2026-11-07 (chunk 859, 0x00986ED0): the operand order of x87 commutative `fmul` pairs (which of two memory operands is loaded, which is the fmul operand) is not textual: 8 textual forms of a cross product never reproduce retail's second-operand sequence (probe/micro_cross.cpp); do not spend grades on textual reorders of commutative float products.
- 2026-11-07 (chunk 859, 0x00CFE030): SIB base/index order (`[edi+ecx]` v `[ecx+edi]`) for a strength-reduced vector offset is a register tie: retail uses both orders in one function (compare sites `[ecx+edi]; add ecx,edi`, create sites `[edi+ecx]`); index spellings (operator[], begin()+i, front(), references, int/long counters) never flip it.
- 2026-11-07 (chunk 859, tooling): `finish.py`'s line-1 parser splits on `::` before the first `(`, so template arguments containing `::` must stay out of line 1 (`// CVectorMap::Insert(...)`, the full instantiation in the Identity comment and the `// Leaf:` line).
