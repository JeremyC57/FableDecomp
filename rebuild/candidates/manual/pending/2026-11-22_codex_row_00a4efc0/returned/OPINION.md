# Release bounds-check reconstruction

I recommend accepting the new CArray opt-in for this row as an explicitly inferred release implementation. The unchanged function body and the existing common allocator compile to the exact retail section with stock VC7.1. The evidence establishes the result and the debug behavior. It does not establish the exact text of the shipping preprocessor macro.

FableWin’s mutable CArray<C3DKeyframe> subscript at 0322E450 and const matrix subscript at 0322C360 both check index against size. In the debug build the error path can display a detailed message, test IsDebuggerPresent and break into the debugger. Both overloads then call the mutable vector subscript. The verified release model retains the index check and debugger tail inside a compile-time-disabled branch. Production executes neither the bounds check nor the debugger call. The fallback for FABLE_PORTABLE and non-MSVC builds uses the original simple subscript. The new option is local to this source.

This model was selected by grading finitely many candidate release expansions. Preserving the full debug message or stripping the entire arm produced different code. Additional controls tested the genuine VS 2003 headers, vendor STLport alternatives, alternate copy walkers, and comparisons written with reversed operands. The break-only disabled form plus the common allocator is the combination that satisfied all acceptance measurements. There is no compiler modification, injected instruction, per-comparison sequencing helper or prebuilt code in the delivery.

The target passed with both the project CRT include set and pristine Visual Studio 2003 RTM headers. Compiler outputs have identical leaf bytes and relocation lists. All 26 mapped helper copies match. The 25 directly or recursively reached, in-object helpers match their catalogued extents; there are 48 nested operands. The two counts of helpers overlap. All three unchanged witness leaves reproduce under the same header set. These are checks on the model; the exact release assertion spelling remains an inference.
