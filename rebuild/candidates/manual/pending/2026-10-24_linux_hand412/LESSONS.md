# Chunk 412 -- lessons from the authoring agent (fold into GOTCHAS at landing)

- STLport vector fill/size constructors match only with the real `_Vector_base(n, a) : _M_start(0), _M_finish(0), _M_end_of_storage(__a, 0)`, where `_M_end_of_storage` is an `_STLP_alloc_proxy` (allocator base + `_M_data`) and `allocate` goes through it. Three plain pointers and a temporary allocator schedule `mov esi,ecx` one slot late (0x009D2A40, also 0x009CD620).
- `vector<T>(1)` with a non-POD T: STLport `uninitialized_fill_n(start, n, _Tp())` with the constant unrolls to one placement copy-construct with its null test, and the `_Tp()` temporary dies right after (0x009CD620). `allocate(1)` loses its `n != 0` test.
- `template <class It> void __fastcall f(...)`: put `__fastcall` on the template DEFINITION. An explicit instantiation that only spells it there still mangles cdecl `YA` (0x009CA500).
- An element-range destroy that is out of line for some element types and inlined for others: model STLport `_Destroy -> __destroy -> __destroy_aux(first, last, const __false_type&)` as inline templates. Declare (do not define) `template <> void __fastcall __destroy_aux<T*>(T*, T*, const __false_type&);` for the out-of-line instantiations. The tag temporary then sits in the push-ecx slot (`lea eax,[esp+13h]`), and the CCharString range still inlines to a dtor call loop (0x009C87C0).
- A destructor reached only through an atexit stub (`mov ecx, <global> ; jmp dtor` in the 0x0122xxxx funclet area) is the global's class dtor: 0x009D4E90 is `g_DefStringTable`'s ~CDefStringTable. Its first inline map clear is the dtor body. `~_Rb_tree` repeats clear(), then `~_Rb_tree_base` frees the header with STLport's `if (p) free(p)`.
- A thiscall wrapper that copies a CCountedPointer into an outgoing by-value slot and releases it at the end is a function TAKING the counted pointer by value. The callee (not the caller) destroys it, so the release is in this body (0x009CD620).
- When a two-step float conversion reads the dimension through `[eax]` after the call (`call GetRenderTargetDimensions ; fld/fmul ; fidiv [eax]`), route the product through an inline helper taking the extents by `const&` as its LAST parameter (`Scale(g, x, display->GetRenderTargetDimensions())`). VC evaluates the arguments right to left, so the call comes first and the divide uses the returned pointer. A one-expression body hoists the product above the call and spills it as a double (0x009E21D0, 0x009E2020, 0x009E2240, 0x009E20F0 all reach equal size).
- The A->V converters' remaining residue is the x87 operand order of `g_Virtual * x`: retail `fld qword [g] ; fmul dword [x]` (or `fimul`), the lane `fld/fild x ; fmul qword [g]` for every source order, by-value helper parameter or getter. The landed 0x009E1DA0 needed a cv-qualified global. Treat it as a lane gap.
- STLport `__final_insertion_sort` / `__unguarded_partition` for the CBankFile entry sort are verbatim STLport with `__fastcall`. `last - first > 16` (elements) compiles to `sub ; and eax,-4 ; cmp eax,40h ; jle` (0x009D3ED0, 0x009D2ED0).

Review at landing:
- Landed 0x009D8AD0 is named CShaderStatesScope, but the PDB class is CScopedShadersEnable (members OldVertexEnable/OldPixelEnable, setters SetVertexShadersEnable/SetPixelShadersEnable). Rename it together with this chunk's 0x009D8B40 dtor.
- Landed GFAXToVX 0x009E1DA0 uses a cv-qualified global (`extern ... double g_FableVirtualWidth_013961E8`) to get retail's x87 order. The purity gate rejects that word. It is the same lane gap as the five parked A->V rows here (0x009E1DD0, 0x009E2020, 0x009E20F0, 0x009E21D0, 0x009E2240).
- 0x009D8650 MicroThreadSleep (whole-body esp switch) and 0x009E1C70 GFGetFastSubFrameTimer (inline `rdtsc`) are retail_asm candidates for the owner's 2026-10-24 exception. Only 0x009E1C70 fits the "minimal asm + C++ body" form. 0x009D8650 is asm end to end.
- Manifest signature of 0x009D5D30 (CBankFileAsyncData ctor, 4 params) is propagated from 0x009D5DF0. Retail pushes 3 (buffer, size, bank).
- The CDataBank second base at +0x164 (0x7C bytes, dtor 0x009FC690, labelled ~CDynamicList) is modelled as an opaque `CBankSecondaryBase`, as in the landed CParticleDataBank 0x00AF1600. Ego_r's CDynamicList is 436 bytes, so the label does not fit. Its identity is still open.
