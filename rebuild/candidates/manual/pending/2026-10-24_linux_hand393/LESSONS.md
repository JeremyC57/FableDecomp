# Chunk 393 -- lessons from the authoring agent (fold into GOTCHAS at landing)

- A push_back of `this` into a pointer vector whose growth callee has a same-TU `auto_inline(off)` + `__declspec(noinline)` `_M_insert_overflow` body (reads x only through its reference, never touches the tag) gets retail's shape: the `this` temporary AND the `__true_type` tag both homed on the one dead argument slot (0x00762090). This closes the chunks 203-204 "lane never re-uses one dead slot for a push_back value and its tag" gap.
- STLport `find_if` with a same-TU `__find_if` body (auto_inline(off) + noinline, tag untouched) homes the `random_access_iterator_tag` temporary on a LIVE argument slot (the out pointer, 0x00761B50) -- the wave 24l/24p "tag over a live slot" gap is also a TU gap. Model the tags as STLport's derived chain (input -> forward -> bidirectional -> random_access): a plain empty POD tag is value-initialised (`mov byte`) into its own frame byte. An empty POD predicate built as `CIsShapeTrack()` IS value-initialised in retail (`mov byte [esp+8],0`, pushed as a dword).
- A counted-pointer vector whose `push_back(CDefPointer())` shows no release code after the overflow call (and no EH frame) has a destructor-less CDefPointer element model (copy ctor addrefs; the null temporary folds to `mov [ecx],0`) (0x00766D70).
- `if (def->Name > 0) { Bank* bank = g->TextBank; return bank->Get(def->Name, true)->GetText(); }`: the block-local bank loads before the argument pushes (`mov edx,[g] ; mov ecx,[edx+14h] ; push 1 ; push eax ; lea edx`); naming the Name as a local instead moves the pushes ahead of the bank load (0x00765F90).
- A loop over `PDef->Vec` whose retail CSEs the vector ADDRESS (`lea edx,[eax+40h]` reused in the body as `mov edx,[edx]`) wants an inline const-ref accessor (`PDef->GetInitialAugmentations().size()` / `[i]`); a named `long index` local loads the element once for the `> 0` test and the push (0x00768010; the loop-end scheduling still differs).
- STLport `erase(remove(begin(), end(), this))` on a global pointer vector gives retail's destructor shape exactly: out-of-line `__find` (same-TU body), remove_copy inline with the global finish re-read after each store and the copy loop against the saved last, single erase inline as `memmove` + `--finish` (0x00762110).
- C3DVector dot products over three normalised copies: `na.Dot(nc) > ab` (the later value on the left) gives `fcomp st(1)`; `ab < na.Dot(nc)` gives `fld st(1) ; fcompp` (0x0075FF00).
- Over engine/CTCBase.h (vptr modelled as a data member) a derived override must not be declared `virtual`, or the layout shifts by 4 (0x0075DC60).
- From the earlier rows: a counted-pointer `Release()` reads the pointee into a local before the `dec` (0x007691A0); a CDefPointer<const T> needs a `mutable` count and `Destroy() const` (0x00769210); `_M_insert_overflow` stand-ins need `__declspec(noinline)`, `auto_inline(off)` alone is not enough in a speed TU (0x0076B760); a CVectorMap POD pair needs a user memberwise copy ctor for `Add` (0x00759570); `map::operator[]` with `insert` an inline forwarder to the out-of-line `insert_unique` re-reads the result from the dead key slot (0x0076AFF0); `_M_insert` splits `_M_create_node` into a `__forceinline` copy in the left branch and the out-of-line COMDAT in the right (0x0076A110).
- Test gotcha: VC7.1 has no NRVO -- a test helper that returns a NAMED local with a releasing destructor double-releases under VC7.1 but not g++; return a temporary built by a constructor (0x00765F90 test).
