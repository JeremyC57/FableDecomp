- (remat v memory) A named reference/pointer 'p = base + const' that retail keeps in a frame slot while ours re-emits 'lea [base+const]' at every use: c2 rematerialises only while base's register is live at EVERY use. Find the use where retail has already overwritten base's register (in-place 'add reg,const' before a call) -- the evaluation order of that one expression (argument address formed before the call that takes p) is the source fact; all the other uses follow.
- (GOTCHAS Q19 again) CDefPointer destructors with `add eax,4 ; dec [eax] ; cmp [eax],0` + a null store where retail has `dec [eax+4] ; jne` and no store, and locals that do not share slots: the GetDef<T> / GetSubDef<T> template bodies must be in the TU (FABLE_RETAIL_CDEFINITIONMANAGER_GETDEF_GLOBAL_BODY, FABLE_RETAIL_CDEFCLASSBASE_GETSUBDEF_BODY); 47 bytes in one step. - (same-TU callees) Port the landed bodies of the row's own-class out-of-line callees (DrawIcon, DrawEffectAtPos, GFAnchorToBottomLeft) into the row under `#pragma auto_inline(off)`: their reference arguments stop escaping, sums fold X-first, and an inlined helper on a returned temporary (ToC2DCoordI) gets retail's direct X-then-Y stores.
- (frame +8 / RVO) `lea ecx,[local] ; call` on a by-value-returning call = a DECLARATION initialised by the call; an assignment goes through a temporary and a copy. c2 packs frame slots by lifetime, so a first-statement temporary, a function-level `pos` and loop-local `pos` objects can all sit in one slot: count declarations, not slots.
- (early computation) A reference `r = v[i]` that retail computes completely before the next call (index arithmetic included) has TWO later uses (`r.Offset` twice); a single-use reference is forwarded past the call with only the vector-begin load left behind.
- (implicit conversion) `lea eax,[tmp] ; push eax` after a string ctor whose return value is NOT reused, with the object pointer loaded after the ctor call = an implicit `const char*` -> CCharString argument conversion, not an explicit `CCharString("...")`.
- (forced inline evidence) A helper whose FableWin /Od size matches the text but which plain `inline` leaves called in an optimize("s") caller (inline trace: sz 37 v largest expanded 29) while retail expands it = FABLE_FORCEINLINE in the header opt-in; verify with a scratch overlay copy first (HDRO=... g.sh), never in hdr/.
- (operand order of inlined C2DVector operator+) X order is record-id keyed (ruler period 4 units); Y order is structural: `fld vector.Y ; fadd this.Y` when one operand is a call-result temporary (swap the source operands / name the member reference), def-member-first whatever the roles when the other operand is a memory-homed named reference.
- (priority flips) this (652) v def (647) were 5 apart: one named reference to a def member (+33 for def) swaps esi/edi for the whole function. Run a 30 s priority trace (tools/tr1.sh) before grading any respelling that adds a def-derived local.
- (C41, x87 order phase) The X order of an inlined `C2DVector::operator+` sum is keyed on the count of symbols created before it, PERIOD 8, and the unit is a NAMED LOCAL INSIDE AN EXPANDED INLINE or a USED named local / reference of the function itself (an empty or pass-through inline and a dead local count nothing). Measure each site's window with a top-ruler scan (tools/best.sh, 16 s); when several sites are right at ONE phase only, the texts before them are right.
- (C41, same idiom twice) When two loops do the same thing, try the matched loop's exact idiom in the other: loop 2 in loop 1's spelling (`const T& button = v[i]; const C2DVector& offset = button.Offset; ... button.Offset` again later) gave retail's `add eax,[i*50h] ; add eax,48h` (the last byte) AND put four X orders right at once.
- (C41, store scheduling behind pushes) Constant byte stores of a temporary argument that retail emits AFTER an indirect load of a later argument (`push [eax+1614Ch]`) = IL order call -> load -> stores: the indirect load may alias the address-taken temporary so c2 keeps IL order. Spelling: the call result and the loaded reference are named locals before the call statement (`unsigned char alpha = ScaleAlpha(0xff); const CFontBank& font = ...; Draw2DText(text, name, font, CRGBColour(0xff,0xff,0xff,alpha), ...)`).

A priority jump of +33 after adding a named reference means retail has the parameter form, not the reference.
- (C41, spelling of the same address) `ringsPos` (named reference) and `def.DPadRingsPos` compile to the same bytes but are different operands for c2's commutative ordering: with the reference the operator+ roles do not matter, with the member spelling they do (`def.GuildSealMainLevelUpOffset + def.DPadRingsPos` gave retail's Y order at 0x00653F18).
