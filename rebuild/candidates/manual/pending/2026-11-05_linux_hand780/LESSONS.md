- (chunk 780) `inline bool CScriptThing::IsAlive() const { return PImp.Data && PImp.Data->IsAlive(); }` gives retail's `test al,al` after the slot-75 call where the if/return spelling gives `je`.
- (chunk 780) exits.py idiom: classify every `mov ecx,this ; call IsActiveThreadTerminating ; test al,al ; jcc` site by its target (INLINE dtor copy / outline `lea ecx ; call` tail / ret) in retail and in the build before touching a spelling -- it shows which exits are too hot or too cold in one screen (CV_FishermanScript: retail's prelude checks P0, P1 and the hit-loop bottom check share ONE inline ~npc block 0x00E7C17F; VC7.1 never gave that from a plain, nested-REST, `||`-merged, rotated or do-while(!T) form).
- (chunk 780) VC7.1 pushes a callee-saved register lazily after an entry-block early return when the register is first needed later (`push edi ; mov edi,edi` at the loop head, a private epilogue copy for the early exit); the body nested under `if (!IsActiveThreadTerminating()) {...}` or the check inside the loop (`for (;;) { if (T) return; ...}`, peeled by VC to the same layout) restores the entry push -- but both forms cool the post-loop blocks: in CV_BeardyBaldyScript::Main the barber IsAlive site goes from inline to a call (T* 150-170 against 74) while the plain early-return form keeps it inline. The two levers (entry push / post-loop frequency) did not combine in 27 forms.
- (chunk 780) do-while(0) terminate-check levers are coarse: in BeardyBaldy's Main one wrapped check changes nothing, two on the same loop level ({loop-top, post-wait}) flip BOTH IsAlive sites inline; the retail split (first inline, second called) sits between them.
- (chunk 780) A catalog row can hide a switch jump table and the next functions: 0x00E6FC40 (1828 bytes) = CDF_Dragon::Main + 8-entry table + CDF_SummonsCreatures::Alloc + GetParentScript -- check `xdis` for a `ret` followed by table pointers before authoring a long script row.
