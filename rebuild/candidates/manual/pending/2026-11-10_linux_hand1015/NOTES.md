**FABLE_HDR_OVERLAY:** every grade, including the final `gall.sh`, ran with `export FABLE_HDR_OVERLAY=$A/hdr`.
The rows do not compile against the repo headers alone, because the shared template body and the element classes live in the overlay (`hdr/README.md`).

## Identities proven

- All 13 rows are the one-argument TLC form `CPersistContext::TransferVectorOfSubComponents<T>(std::vector<T>&)`:
  - `__thiscall`, `ret 4`
  - `CheckCRC("")` with the pooled empty key 0x0122D70E
  - load arm (Mode==1): `ReadSLONG`, then `resize`, then a `T::Transfer` loop through vtable slot 18 (+0x48)
  - default arm: `size()`, then `WriteSLONG`, then the same loop
- Element type per row: see STATUS.tsv and LABELS.tsv. Each one is backed by:
  1. the `idiv` stride (`push sizeof(T); pop ecx; cdq; idiv`)
  2. the vtable RTTI of the default element the load arm builds (rtti-vtables slot 0)
  3. the element ctor/dtor and `resize` callees
  4. the xref caller (the owning def's `Transfer`)
  5. the naming wave 1 DECISIONS
- The catalog labelled 12 of the 13 rows `<CAbilityButtonGuiDef>`, a propagated label. Only 0x0047652B really is that type (NAME_FIXES.tsv).

## Three body shapes, one source

| Size | Rows | Shape | Flag |
|---|---|---|---|
| 255 bytes | 0x00476024, 0x0047652B, 0x004769D0, 0x00478AE5, 0x00479EF4, 0x004FA0A9 | Element has an implicit ctor/dtor (`CParentDefClassBase` 0x00430370 / 0x00430300 plus the vtable store inlined); STLport `resize(n)` = `resize(n, T())` expands inline | `/d2inlS40` |
| 245 bytes | 0x00479466, 0x004798AB, 0x0047A2F5, 0x004F9C07 | Element has an out-of-line ctor/dtor; `resize(n)` expands inline | `/d2inlS30` |
| 223 bytes | 0x004ECF6E, 0x004ED953, 0x004EDE2B | Retail calls the out-of-line `vector<T>::resize(size_type)` COMDAT | none (the default S=9 keeps the call) |

The flags are inline-budget levers only. Measured with the c2 inline trace in size mode, a site expands iff cost < S, where S defaults to 9 and is set by `/d2inlS<N>`:

- The forwarder costs 39 in the 255 shape and 29 in the 245 shape.
- So 40 and 30 are the smallest budgets that reproduce retail.
- The 223 shape expands at S40–70, which would break it, so those rows take no flag.

The `if (count > 0)` guard around the load loop is load-bearing.

- In c2's register-priority sum it lowers `this` from 29 to 27 (below the neighbour's 28), so `this` lands in the retail register.
- Without the guard, 0x004ECF6E (and the other shapes) diverge in register allocation only.
- It is a plain C++ spelling of an early-out the original template evidently had.
