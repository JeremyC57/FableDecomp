- (wfB1, x87 / push interleave) The order of x87 stores among argument pushes is not CPU scheduling (/G5 /G6 /G7 identical): it is a slot template counted in instructions after the last fadd (fld st(1) +6, fstp +8, fst +11, pops +13 / +15) that c2 fills top-down only when >= 10 integer instructions are available; with 9 it places the fst one slot early. A one-instruction residue of this kind means retail had one more integer instruction in the region when the stores were placed: look for a statement fact that adds an instruction which later disappears, not for another spelling of the pushed value (ten spellings of the value gave identical order). tools/fl.py prints the region compactly.
- (wfB1, twin idioms are per function) The matched PC twin's spelling of a shared block is evidence only where the twin's RETAIL has the same destructor facts: 0x0058807D keeps the `Object = 0` stores of its GetSubDef targets, 0x0058578B drops all four, so the twin's flat `mod` declaration costs a null store here. Compare the null-store pattern of both retails before porting a twin block.
- (wfB1, eliminated loops leave no c2 block) An empty STL `_Destroy` range loop is gone before c2 forms the blocks it colours (block count and K unchanged with or without the loop text): it cannot explain a "block boundary without a branch".
- (wfB1, tools) c2prio trace (tools/pt.sh) costs 80 s and the forced-priority lens (tools/wf.sh) 17 s on an 8 KB row; both work on this machine from $W/tools copies of C35 / C44 (copy the wf/ directory too).
- (wfB1 successor, scheduler is measurable) hand892's c2 list-scheduler trace runs on this machine in 16 s (wfB1/tools/sc.sh + sched/ + showdag.py + cy.py + pm.py): it prints the region's DAG (successors / latencies), every cycle's ready list and the picks. A one-instruction x87 / push order residue is then a NUMBER: c2 issues one integer and one x87 instruction per cycle in priority order, priority = 0x100*(4*successors + longest latency path) + 0x8000 for a memory load + 1 for an x87 store. Read the two priorities of the swapped pair before trying spellings (0x00652FA4: an exact tie 0xE0 v 0xE0 decided by the store flag; retail needs +4 on the push).
- (wfB1 successor, frame-masked diffs hide commutative swaps) `mov ecx,[ebp+5Ch] / mov eax,[ebp+10h] / add` v the same with the two frame slots exchanged is a real residue that a frame-masked structural diff reports as equal; count real hunks with rh.py / q.py before writing "one instruction out of place".
- (wfB1 successor, PAREN probe) One no-code PAREN on the X sum of an inline operator+ (scratch overlay) flipped a commutative operand order 0x800 bytes away and nothing else: candidate ids of a shared inline's temporaries decide such swaps; test the shared inline's text before touching the statement that shows the swap.
- (wfB1 successor, callee visibility is not a scheduler lever) Making an out-of-line callee's body visible in the TU does not remove the scheduler's store -> call edges (same DAG), but it lets an earlier pass move stores across the call (0x0065348E): a store group that sits AFTER the call in retail proves the callee was opaque there.
