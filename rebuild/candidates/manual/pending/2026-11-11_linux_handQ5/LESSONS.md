# Chunk Q5 lessons (GOTCHAS-ready)
- (chunk Q5) 0x00497FD0 CProgressDisplay::DisplayCenteredText: retail spills a count once, in the draw loop's pre-header after the guard (`mov [esp+24h],edi` 0x004980FE). The spelling that reproduces it is `if (cond) { long lineNo = count; do { ... --lineNo; } while (cond); }`. A plain `while` stores at the count loop's exit (and at the init). A `long lineNo = count;` copy before the `while` stores before the guard and swaps esi/edi.
- (chunk Q5) 0x00497FD0: retail interleaves an aggregate copy from a named, address-exposed C2DVector (`shadow = position`, 0x00498328: load X, store X, load Y, store Y later), but ours emits a block copy. Memberwise statements, Initialise(), a user operator= or a copy-constructed temporary all re-shape the frame (position gets scalarised or a new slot appears). Still open.
- (chunk Q5) 0x007CCF50: the loop-exit reload order did not follow "ascending final piece ids" here (ours ebp #52, esi #21, edi #45). Twelve code-neutral spellings left the split pieces identical. Probe the pieces with c2prio before spending grades.
- (chunk Q5) 0x008F61A0: CHeightMap indexes its cells top down with one extra cell per row, `(SizeY - y) * (SizeX + 1) + x` (AlterHeightBy 0x008F60F5, Resize 0x008F6325). The PDBs also name the private static `GetExtraCells` (?GetExtraCells@CHeightMap@@CIJXZ, __fastcall). As inline `return 1` it is byte-neutral.
- (chunk Q5) 0x0078C900: VC7.1 zeroes a conditional-temporary flag word in the prologue, so its block-1 reference (w*K*2 = 20 here) dominates its priority. That is why it beats the && result bools (10/9/9) for the only byte-capable callee-saved register.
