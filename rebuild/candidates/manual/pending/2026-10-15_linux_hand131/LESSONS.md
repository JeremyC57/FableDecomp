# Lessons from chunk 131 (candidates for docs/pipeline/GOTCHAS.md)

- A call result that retail fetches BEFORE pushing constant arguments (`lea ecx,[edi+8] ; call GetPItem ; push 0 ; push 0`) is a named local (`CThing* c = PCreature.GetPItem(); c->SetSuspendAnimation(false, false);`); inline in the call the lane pushes the constants first (0x008EC470).
- A member re-read after a call that follows its own increment (`++LoopNum == 5` then a temporary built from LoopNum) means the call came first in the source: fetch the creature into a local before building the temporary, otherwise VC keeps the incremented value in a callee-saved register (0x008C5370).
- SGI `__linear_insert` / `__pop_heap` element copies: STLport's pair has an EXPLICIT copy constructor (`first(o.first), second(o.second)`); a 12/16-byte second whose words are copied straight from the argument slots has a memberwise user copy constructor over dword members, an implicit struct copy goes through `lea`/`add reg,4` re-based pointers (0x0077ED20, 0x00A33780, 0x006F46D0).
- STLport `copy_backward` front end: `__copy_backward(first, last, result, random_access_iterator_tag(), (Distance*)0)` with the tag as a const-ref temporary homed in the dead comparator slot (`lea eax,[esp+N] ; push eax`) (0x0081BDA0).
- STLport `_Destroy(first, last)` must take its bounds BY VALUE (an inline free function): the end is then cached in ebx; a loop on the vector's members re-reads `_M_finish` every iteration (0x006EC7D0).
- `push_back(T(size(), def))`: a named `long index = size();` before the call moves the argument load after the reciprocal-multiply division (inline, VC loads the argument before the prologue) (0x006EC7D0).
- A loop over an array that retail walks with a cursor register (`mov ebx,[edi+204h]` once, `add ebx,4`) while re-reading the size each iteration is an explicit element pointer local; `array[i]` re-reads the base (0x009C7EF0).
- A counted pointer returned by value whose object is then read from the hidden-result slot (`mov esi,[esp+10h]`) is a NAMED local (`CIVCountedPointer p = Get(...); T* e = p.m_pObject;`); reading the temporary's member uses the returned eax. Release after a by-value return of a member: an inline guard object on the pointer local (`dec [esi+4] ; jne ; call [vt+4]` after the copy) -- a destructor on the counted-pointer object re-reads the slot at every use (0x009C95E0).
- A const-ref parameter of a callee bound to a variable of a DIFFERENT integer type (`long key` to `const unsigned long&`) creates a conversion temporary homed in a dead argument slot while the compare keeps the register copy (0x009AD410, partial).
- `if (x >= 0) member = x;` on a float member reloads (`fcomp` + `mov`); retail's `fcom` + `fstp` (value kept on the FPU) is an inline helper taking the value BY VALUE: `template<class T> void ApplyIfSet(T& s, T v) { if (v >= 0) s = v; }` (0x00B8FC40).
- A member function returns even an 8-byte POD (`_FILETIME`) through the hidden pointer (`ret 4`, `mov eax,[esp+1Ch]` at the end); a /Gr `__fastcall` template returning a POD by value also takes the hidden pointer on the STACK with its first argument in ecx (0x009E9D40, 0x0082F5C0).
- CRGBColour (B,G,R,A bytes) zeroed byte by byte = `CRGBColour() : B(0), G(0), R(0), A(0) {}`; copied out as stores +2,+1,+0,+3 = a user copy constructor `R = o.R; G = o.G; B = o.B; A = o.A;` (0x009945E0); the 4-argument constructor with an R,G,B,A body reproduces the float->byte conversion order (0x00429880).
- The engine headers type the vptr as `void*`; for a virtual call on `this` (CDataOutputStream::Write slot 4) model the stream locally (0x00994230); for non-virtual work derive a `_Methods`/`Reader` struct from the header class (0x009945E0 family).
- A `jmp` over a 3-byte alignment `lea ecx,[ecx]` before a loop head plus `and esp,-8` + cookie is just `/GS` on a speed TU with a 256-byte buffer (0x00994230).
- Declaring `strcmp` by hand (`extern "C" int __cdecl strcmp(...); #pragma intrinsic(strcmp)`) avoids `<string.h>` when the same TU needs a dllimport `_stricmp` (C2375 otherwise) (0x00C0BCE0).
- `_STLP_DEFAULT_CONSTRUCTED(_Tp)` is the out-of-line `__default_constructed((_Tp*)0)` (caller: `xor ecx,ecx ; push &tmp ; call`), not a constructor; retail copies uninitialised words out through frame temporaries (0x0082F5C0, parked).
- Lane gaps seen: a component pointer used as `this` and for an argument byte lands in eax and is copied (retail ecx/dl, 0x00847FB0); a RMW bit-field store and an unaligned immediate store sink below a constructor's vtable store (0x00F29D00); a by-value record whose tail goes to an out-of-line copy ctor is treated as memory across calls (key not cached, 0x00720CB0); an address-taken out-value local homed in a dead argument slot where retail gives it a frame word (0x009AD410).
