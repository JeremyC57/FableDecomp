# Chunk 356 -- lessons from the authoring agent (fold into GOTCHAS at landing)

- Random "coin" predicate inlined into a branch: `if (Random() & 1) return false; return true;` gives retail's bare `test al,1 ; jne`. The forms `return (x & 1) == 0`, `!(x & 1)` and `(x & 1) ? false : true` all compile to `not al ; test al,1`. Seen at 0x00805FE0 (SGI `__median`, CDoNotUseBinaryPredicate); the same form also grades 0x00806910 (`__unguarded_linear_insert`).
- String compares that keep data pointers in registers across `call CBasicString::operator<` (no reload of `[edi]`/`[esi]` after the call) are `/Oa` TUs. Seen at 0x00A40250 (pair `operator<`), 0x00A70020 and 0x004DFC42 (`__median<pair<CCharString,CCharString>>`). Without `/Oa` VC7.1 reloads the pointers and frees ebx/ebp.
- Under `#pragma optimize("s", on)` (frame-pointer TU at 0x4DFxxx) VC7.1 calls small comparator functors and CCharString::operator< out of line. Mark them `__forceinline` to get retail's fully inlined `__median` (0x004DFC42).
- Leaf for an operator template: the mangled name does not contain "operator<". Use the mangled prefix (`??$?M` for a templated `operator<`), especially when the TU also emits an out-of-line `??MCCharString` (0x00A40250).
- STLport `merge()` and the counted `__copy(first, last, result, random_access_iterator_tag, Distance*)` inline with plain `inline`; VC7.1 folds source and destination into one `[ecx+eax]` walk (0x00B85510, 0x00710310).
- SGI `__make_heap(first, last, comp, T*, Distance*)` (`ret 0Ch`): the `T(*(first + parent))` argument is built memberwise in the argument area from a strength-reduced `first + parent*size + k` pointer when the element has any user-copy member (C3DVector). A CCompositeBlendDesc with an IMPLICIT copy constructor is inlined there (CRGBColour `Set` byte moves), even though the pop_heap of the same TU (0x00720610) calls the out-of-line 0x005BA48A (0x00720710).
- STLport `list<T>::insert(iterator, const T&)` (`ret 0Ch`, hidden result first, `this` unused): `_M_create_node` = `malloc(sizeof(node))` + placement new of `_M_data`. The null test is on `&node->_M_data`. An iterator with user constructors is returned through the hidden pointer (0x005355C0, 0x00AEC6F0).
- STLport `__uninitialized_copy(first, last, result, const __false_type&)` over a record of counted pointers: plain `for (; first != last; ++first, ++cur) new (cur) T(*first);`. VC7.1 adds the `+0x10` second induction pointers on both sides by itself (0x00513500, 0x006C2AA0).
- `_Move<X*>` catalog rows that call an out-of-line 12-byte `operator=` plus a byte at +0xD are `__copy_backward` over 16-byte CVectorMap records {vector, empty comparator, Dirty}. The landed 0x0086D5E0 model fits as is (0x0086D5A0).
- SGI `__unguarded_insertion_sort_aux` over a 32-byte record holding C3DVectors: the IMPLICIT element copy (memberwise, eight dword moves, key also kept in ebp) plus the implicit trivial assignment (`rep movsd 8`) is exactly retail. No user copy constructor is needed on the record itself (0x00817540).

Review at landing:
- 0086fac0 and 004c5100 are parked only because their 4 grades were spent before the GOTCHAS 24l fix (the real `__copy_backward` body under `auto_inline(off)` + `noinline`) was found on 004c5190. One grade with that fix should land both.
- 0067ee30 needed all 4 grades (the third `__forceinline`, on `__linear_insert`, was the last missing piece).
- 009d3b90 uses a local `CBankFile_Retail` model (copied from the landed 0x009D2FC0) next to the existing `engine/CBankFile.h`. The header's retail layout has the right offsets (RuntimeData +0x20, PackedDataOffset +0x38), but it types them as opaque byte arrays, and its PDB layout puts them at +0x28 / +0x48. The typed CArray / CPackedUIntArray accessors therefore need the local model.
- 00a40250 grades under the leaf `??$?M`. With leaf "operator<" it silently graded the largest function, which happens to be the same body.
- 0x00806910 (`__unguarded_linear_insert<CIntelligentPointer<CThing>, CDoNotUseBinaryPredicate>`, not a chunk row, manifest label "_Push_heap<...>") graded RELOCATION_MATCH from probe/uli_B.cpp under a custom-oracle probe. It is a candidate for a later batch.
