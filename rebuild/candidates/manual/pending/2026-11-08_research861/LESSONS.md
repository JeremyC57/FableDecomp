# LESSONS (research861, 2026-11-08) -- GOTCHAS one-liners, each verified on the lane (probe/ holds the micro-TUs)

- (2026-11-08, research861) VC7.1 c2 is function-local and deterministic: 0..70,000 extra `extern`/struct/prototype declarations, the source path length (122..221 chars) and dummy functions before or after the row change NO byte of 0x0085C7D0 / 0x00C52BB0 (MSVC 5's symbol-id and path-length tie effects documented by the byte-tactics project do not exist in 13.10.3077); a tie is decided inside the function's own IR.
- (2026-11-08, research861) /G5, /G6 and /GB are byte-identical to the default on every landed row of the CTCPhysicsBase TU (0x006AF000-0x006B2000) and on 26 parked rows; /G7 changes 23 of those landed rows (inc/dec vs add/sub, sizes 19v17 .. 879v811) and matches no parked row: retail is not /G7, and the /G switch space in VC7.1 is just {default, /G7}.
- (2026-11-08, research861) A per-TU flag is admissible only if every landed row of that TU still matches under it (`tu_flag_check.py <lo> <hi> <flag>`): /Ow and /Oa make 0x006AFE60 RELOCATION_MATCH but break landed 0x006B1450 GetRHSet, 0x006B1960 and 10 more rows of the same TU, so the match is a false lead and the residue is a source-shape alias effect.
- (2026-11-08, research861) VC7.1 holds a zero constant in a register exactly as MSVC 5: 3+ `p->f[i] = 0` stores without calls -> `xor ecx,ecx`; 5+ with a call after each -> `xor edi,edi`; fewer -> immediates (probe/consts.cpp). "Retail keeps 0 in ebx" is a weighted use-count threshold, not a spelling.
- (2026-11-08, research861) Expression temporaries rotate eax, ecx, edx from a pointer reset once per function and skip registers holding variables (probe/rotation.cpp: `G[i]=G[j]+k` x4 gives eax,ecx,edx,eax; with the base in eax: ecx,edx,ecx,edx): adding, removing or reordering ONE temporary before the site shifts every later scratch register.
- (2026-11-08, research861) Values live across calls take esi, edi, ebx, ebp in priority (weighted reference count) order; equal priority goes to the value defined first in code; one loop reference outweighs ~7 straight-line references (probe/prio.cpp p1-p7). ebp is used only when esi/edi/ebx are taken.
- (2026-11-08, research861) Callee-saved pushes are interleaved into the prologue right before the register's first definition, and the first definitions follow the scheduled first uses: `this` copied after a parameter load (retail 0x00B92300 shape) means `this` is first needed later than that parameter (probe/sched.cpp s4).
- (2026-11-08, research861) Commutative x87 ops on two register-indirect loads with simple bases (parameters, members): the operand with the LARGER displacement is `fld`ed first and the smaller becomes the `fmul/fadd` memory operand, textual order irrelevant; equal displacements -> the earlier-declared parameter first; direct operands (globals, by-value params, frame locals) are not canonicalised: the RIGHT operand is `fld`ed first; a direct operand beats an indirect one; a computed (register) operand is evaluated first (probe/x87order*.cpp).
- (2026-11-08, research861) Sums of products are re-sorted by the same key regardless of parentheses, a named float local, (float)(double) wraps or `*1.0f` (k20-k22, m1, m5, m6, m11-m13); a store to memory (global, `*out`, a by-ref parameter) or a call between the terms pins the order (m2, m3, m4, m14). Subtraction and division keep textual order; `-(a*b) + c*d` is re-sorted as an addition.
- (2026-11-08, research861) `const float* pb = &b.Y; pb[0]` / `pb[-1]` are folded back to `[reg+disp]` before the operand sort (k17-k19), so a pre-offset pointer changes nothing unless the pointer survives as a variable.
- (2026-11-08, research861) Off a register base that is a call result (not a parameter), the within-product load order is NOT the displacement rule: it follows IR creation / CSE history of earlier products in the same expression (probe/cross.cpp c1-c7: 4 of 6 products flip with the spelling); such ties are decided by which operand node existed first.
- (2026-11-08, research861) Loop-head alignment: VC7.1 /O2 pads a counted `for` loop head to 16 bytes only when the pad needed is small (observed 4 and 6-7 bytes; never 10, 12, 14), never pads `while (!call())` / do-while-with-call loops, and never under /Os (probe/align*.cpp). A missing 4-byte instruction earlier in the function (0x00E72630's dead `mov [esp+3Ch],ebp`) therefore also explains both of its retail pads: fix the earlier byte first, the pads follow.
- (2026-11-08, research861) VC7.1's same-TU mod/ref analysis is what makes address-taken locals share a slot: a visible `auto_inline(off)` callee that only READS through the pointer lets three block locals share one slot and constant-folds their values (probe/frame3.cpp v1: frame 4 bytes); a visible callee that WRITES through the pointer, or a declared-only callee, keeps three slots (v2, v3). Chunk 860's lever needs read-only bodies.
- (2026-11-08, research861) Declaration order of address-taken locals does not change their slots (probe/frame.cpp fr1 = fr2 byte-identical).
- (2026-11-08, research861) c2.dll 13.10.3077 has no instruction scheduler strings; its reordering is DAG/tuple emission order plus load hoisting across statements limited by free scratch registers (probe/rotation.cpp r1/r3: 3 loads, 3 adds, 3 stores). "One load one slot early/late" residues are IR-numbering ties, not latency scheduling, and /G5-/G7 cannot move them.
- (2026-11-08, research861) The c2 diagnostic switch set of 13.10.3077 is in probe/c2_switches.txt (122 names: -inlS/-inlT/-inlcrmax/-inluserinl, -Loop, -db, -off, -dslow/-dshigh, -optref, -datasort, -bzalign, -ltcg, -pgo...); color.c (28 assert sites 0x107C1C73..), tuple.c, stack.c, dag.c, fppeeps.c, lowerflt.c locations are in probe/c2_assert_sites.txt for a future debugger-based allocator probe (the byte-tactics `c2prio.py` method).
