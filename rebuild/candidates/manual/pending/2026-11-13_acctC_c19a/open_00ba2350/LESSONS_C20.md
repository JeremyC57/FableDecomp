# agentC20 lessons (one line each; C19's lessons in prev_C19/LESSONS.md still hold)
- (0x00BA2350) `test reg,imm ; mov al,[x] ; jcc` with the SAME register for the flags temp and the loaded byte means the load is written in BOTH arms and c2 head-merged it after allocation (machine-level prefix merge of both successors, placed between the compare and the jcc); a single read before the `if` forces the flags temp into another register.
- c2 cleans every dead branch before the priority pass: dead-arm asserts, `__assume(x)`, `if (!x) {}`, `if (!x) __assume(0)`, an empty-inline call in the arm and a once-through `for(;;){...break}` all give byte-identical objects, so none of them can split a block or add a reference; named references / single-use locals / the FableWin static getters are forwarded and do not change K either.
- Write the priority as an inequality in block K's before trying spellings: here mesh - sub = 17 - S - 2*K(block 1); with K1 = 16 fixed by retail's visible block 1 the gap is 11-12 points, which no code-identical spelling found so far moves by more than 0.
- A forced c2 priority (C2_FORCEID) is the right way to test whether the REST of a text is right: after the alpha head-merge fix one forced priority takes the row from masked lcs 2014 to 2310/2419, which separates "wrong structure" from "wrong colouring order".
- FableWin.exe is not on the Linux lane (only its per-function size / instruction-count signatures): /Od counts are the only debug evidence; one FableWin ASSERT is ~85-90 instructions, so (FW count - ours) / 87 estimates the number of asserts in a row (here ~4).
- Never name variant files after files you still need (w/t3.cpp was the TU copy and got overwritten by a `t3` variant; restored from prev_C19/differ).
