# wfE5 lessons (one line each)
- (0x00BBAC60) A both-arm duplicated conversion in retail (`if (p) { T c(x); modify; f(C4D(c)); } else f(C4D(T(x)));`, tails cross-jumped) is a source fact, not a scheduling tie: writing the call in both arms took 80 bytes and every frame-slot hunk at once.
- (0x00BBAC60) A pure SIB base/index flip that k unused locals at the top cannot move can still be a symbol-record threshold: a DIAG ruler at the END (DiagRuler3 x 24) proves it in 6 grades; then 2..6 dead FABLE_RETAIL_ASSERTs (FableWin count 3) close it.
- Grades in this lane take ~20 s each when the Wine box is shared: sweep 5-6 variants per call with sw.sh in the foreground with a 900 s timeout.
- (0x00BC04F0) A parked row with a landed same-TU sibling closes by RE-AUTHORING on the sibling's text (opt-ins, helper texts, reference locals), not by porting its stale draft: 135 diff lines -> RELOCATION_MATCH in ~15 grades; keep from the draft only what the sibling lacks (alpha_scale colour, c2.W store).
- (0x00BC04F0) When PeekGraphic / the capture-block ctor are called instead of expanded, sweep /d2inlT first (T79 here), then fix the rest; the frame-size gap (0x20 v 0x30) was a source fact (a named premultiplied C3DVector), not packing.
- (0x00BCA950) The matched sibling's vertex-write idiom (`v0 = vertices++; v1 = vertices++; SetPosition / SetDiffuseColour / SetU1V1`) instead of `vertices->X = ...; ++vertices;` took the row from 103 to 27 hunks: the setter layer and the two named pointers decide the whole loop's allocation.
- A shared header whose class declares virtuals over CEngineInternalPrimitiveBase needs FABLE_RETAIL_CENGINEINTERNALPRIMITIVEBASE_CLASS (polymorphic base): with the flat default the derived class gets a second vptr and the size assert fails (CEngineInternalPrimitiveSpriteTrail.h: 180).
- (0x00BAE2D0) A 5.9 KB render row with a good acctB OUTLINE and a matched same-family sibling (0x00BB30A0 helper texts) went from nothing to RELOCATION_MATCH in ~16 grades by hand-authoring: the decisive source facts were a value read once and converted as unsigned long (named `unsigned long alpha`) and the textures initializer; the last test/or flip closed with a named blend-mode local per arm (FITTED).
- (0x00BC8A60) A blend helper returning bool compiled into retail's layout only as `alpha = colour.A; if (!Setup(mode)) brightness = 0xff; else brightness = alpha;` (else arm adjacent to the join = the arm that falls into the common code; the hoisted load is a named local): ternary / if-true-first forms each move ~50 hunks.
- (0x00BC8A60) One call reached from both arms of a ternary with the push inside each arm (`je ; mov eax,[g] ; add eax,X ; push eax ; jmp` / `mov ecx,[g] ; add ecx,Y ; push ecx`) is an if/else with two calls cross-jumped, not a ternary argument.
- (0x00BC8A60) `fst [tmp] ... fdiv st(1) ... fstp st(0)` around a clip factor is the denominator written as its own expression (end.Z - start.Z) CSE'd with the vector difference, not `delta.Z` of a named delta.
- (0x00BC8A60) A frame larger than retail by one vector, with retail storing a late vector into an earlier vector's slots and copying fields as integer moves, is c2 scalar-slot sharing after the earlier vector dies: look for what keeps the earlier vector live in ours (copy propagation of a field into a later object).
- (0x00BCA950) An IV / address-form residue on a vector expression (one operand addressed off another's IV in ours, its own strength-reduced IV in retail) can be a PDB inline helper the author did not use: FableWin listed C3DVector::Interpolate; spelling the lerp through it closed the hunk at once.
- (0x00BC8A60) Corner Z fields copied as INT moves in retail while ours copy-propagates the source vector's Z (keeping it live, frame one vector larger) = the corners are vector sums with a zero-Z offset (`start - C3DVector(px, py, 0.0f)`): the Z - 0.0f folds after copy propagation, leaving a real copy and freeing the source's slots.
- (0x00BCA950) VC7.1 canonicalises integer linear expressions before CSE: points*16-14, (points*8-7)*2, (trail_size-skip-1)*16+2 and 2*(segments*8+1) all compile to the CSE'd `segments<<4 + 2`; no arithmetic spelling separates a count from an earlier `points - 1`.
- (0x00BCA950) A block-local expression temp (here `trail.MaxLength - 2` feeding one fild) is not a c2 colouring candidate (absent from c2prio's list): its register is whatever the global pieces leave, so an ecx/edx swap on it is decided by the neighbouring global piece, not by its own spelling.
- (0x00BC8A60) x87 commutative-order residues that 1..256 live-initialised float rulers (top of function or right before the vector) cannot move are not record-id ties; rulers >= 16 only grow the frame (disp8 -> disp32 lengths), so read their hunks with that in mind.
- (0x00BB0970) A straight-line render block spanning calls is ONE c2 scheduling region cut into 83-node windows; one-or-two-instruction x87 / int interleave residues at two places = window edges. Trace it (wfB1/tools/sched via a sc.sh wrapper, pat = the region's first ops) and move the edges by node count: `(a - b) * k` has a float-rounding node after the subtraction that `box.GetWidth() * k` lacks; `x *= s; x -= 1.0f;` adds nodes over `x = x * s - 1.0f` with identical bytes.
- (0x00BB0970) `uvs = f()` (struct returned through a hidden pointer) copies from the returned eax; retail's `lea esi,[temp]` copy source = a named copy `{ T quad = f(); uvs = quad; }` in its own block (a function-scope named copy keeps its own slot).
- (0x00BAFA00) An inline the row needs that /d2inlT never moves can be a caller-size cap: /d2inlS<N> (smallest N measured by bisection, here 18) expands it; the landed text stays plain inline.
- (0x00BAFA00) Constant 0 kept in a callee-saved register across a loop and a later push, with another local spilled, is c2 priority ORDER between that local and the split pass that makes the zero piece: c2prio --trace shows it; lengthening the local's live range flips it.
- (0x00BC8A60, 7th author) c2 canonicalises commutative x87 sums: swapping the terms of an inline helper's row (`E22*yy+E12*xx` v `E12*xx+E22*yy`) or the operands of `start + offset` gives byte-identical code, so an x87 operand-order residue is never fixed by term order in a header text; measure symbol / IL facts instead.
- (0x00BCA950, 7th author) c2prio's --json trace keeps the piece lineage (`new` events with `parent`, `ref` events with tuple number and block): follow a candidate's pieces through every split pass with a 20-line script before theorising about which references share a piece.
