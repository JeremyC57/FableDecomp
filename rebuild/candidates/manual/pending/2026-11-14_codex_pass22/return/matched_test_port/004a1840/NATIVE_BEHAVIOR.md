# Observed native behavior and portable domain

Load extracts the input world's basename and assigns CurrentWorldName before attempting the initial file open. A caught CBBBFileException formats and displays a critical message, then returns through normal file/name cleanup. Only that Open call is inside the catch. Later failures are outside the tested normal-callee domain.

Successful loading profiles quests, derives static-map and quest paths, loads existing level/global quest files with opposite bool modes, and closes each temporary before proceeding. It first clears the map's WAD selection. GUseLevelWAD enables creation and selection using2 actual path conversions. It then loads the world and drains the real level loader. Every IsBusy and RunSuspendableProcess expression owns a separate counted temporary; its reference ends before the next expression. A final false condition can release the last loader reference safely.

Offline generation invokes the real GenerateOfflineDataForWorld body: when GEnableStaticMapCreation is set, it derives a static path and evaluates GetWorldMap().CreateStaticMaps(path, engine). The zero-argument virtual getter returns the map; the subsequent2-argument native ret8 stub consumes the path/engine arguments. No actual file generation is claimed for that retail stub. Load always installs the derived static-map filename through CIEngine::SetStaticMapFileForUse, emits the final progress message, ends profiling and cleans up all root locals.

Both compilers execute the full returned Load/Generate bodies and actual shared file destructor/count/exception definitions across1024 cases. File/backend operations are controlled callees that assert exact arguments and event order. The initial-file failure triggers real C++ catch handling in both test runtimes. File/base/string/resource counts balance. Host long/pointers remain64-bit; reference counts/indices fit32-bit; progress-1.0f is exact. Wide strings use each host's wchar_t over bounded ASCII values. The original catch passes a wchar pointer to a narrow formatter: the fixture asserts that exact observed argument and forwarding of the formatter's controlled result; it does not assert cross-platform formatter byte encoding.

Required references remain valid, loader is nonnull while busy, and other file/quest/WAD/profile/engine calls succeed. These are explicit fixture/input invariants, not newly added source guards. No unsupported null object/component path, arbitrary overflow or native-runtime ABI equivalence is claimed. The native match and all exception metadata/vtable bindings are verified independently from the portable behavior fixture.
