# Native behavior and portable domain

A zero podium stamp always updates; otherwise the quest manager's boast-update stamp must be unsigned greater than or equal to it. The podium marks BoastingActive from signed boast count. More boasts than activated positions causes every position to be deactivated, count cleared, then selected groups1/2/1+3/2+4 for1/2/3/4 boasts to receive successive boast IDs/costs. Matching group ranges are original mutable LowerBound/UpperBound results over sorted map entries.

Otherwise, when count exceeds LastPositionsWithBoastCount, a pointer list collects boasts not already held by any position whose HasBoast is true. It then assigns those pointers in order to activated positions without a boast, stopping when no pending pointer remains. If count is0, every activated position removes its boast and LastPositionsWithBoastCount becomes0. A decreasing positive count does not enter cleanup. The update stamp is refreshed through PeekWorld/GetFrame. Parent SetAsFrameUpdated and SetAsRenderedThisFrame(4) happen even when the stamp check skips all other work.

Required inputs: position objects are alive and have consistent valid BoastingPosition components, map keys are sorted, and selected group populations do not exhaust the available boast list. The original debug code asserts these properties; native release ignores failed GetTC results. The portable fixture provides them and does not invent null/invalid-component support. It exercises empty maps with real33-element storage. BoastOn initially implies activation. Numeric counts/costs/indices/frame stamps fit signed32; host long/pointer widths remain64-bit. No floating point operation or wraparound contract is involved.

The fixture uses actual shared STLport list/vector/pair and observer-pointer templates plus all3 bound helpers, and the complete specialized push_back and FrameUpdate verbatim. Its external overflow callee implements the tested append contract with guarded null-size arithmetic, constructs a potentially aliased value before destroying old storage and preserves vector ownership.
