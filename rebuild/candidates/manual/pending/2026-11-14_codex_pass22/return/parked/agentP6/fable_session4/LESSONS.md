# agentP6G lessons (0x00F3E120), GOTCHAS-ready, one line each

- 0x00F3E120 (agentP6G, not matched): retail's prologue store order (this spill, vertex_count, best_score, best_start_vert, start_vert) fixes the IL order to count, score, vertex -- the three stores tie at scheduler priority 0xc00 and come out by IL index, and a higher priority for the count store would also put it ahead of the `this` spill, which retail does not show. So the u1 base (score, vertex, count) cannot be the original; the residue is the reload pair alone.
- c2 root candidates (hook hooks/tsym.py at 0x1077FCF1): roots are created by walking c2's symbol blocks (list head 0x108A79C0, 32 syms of 0x60 bytes per block, blocks in creation order, four streams opened per function at 0x10776598). Block 1 holds `this`, the parameters in reverse order and the first locals in FIRST-REFERENCE order (a bare declaration creates no symbol; `long vertex_count;` assigned last comes after best_score / best_start_vert). A dummy function in front of the row (1..13 parameters) does not move anything: the walk is per function.
- c2 constant table (0x1077E10B / 0x1077E132): the key is (operand kind, value); kind 7 integers hash by value & 0x3F, kind 3 address constants by a symbol field & 0x3F; both kinds can be freed at round 0 and feed the first root ids.
- c2 split rounds (c2prio `split` events): every round splits its failed candidates in ASCENDING record id and pops c2's free list. Round 1 here is [1,2,3,4,6,8,9,...]; round 2 is the phase-1 start_vert alone, whose old record (the root id of best_score, 12) is freed and taken by the lower-numbered of this / vertex_link_map; the other gets #72. vertex_to_poly_map gets #14 (the root id of start_vert). Reloads at a region entry come out in piece-id order, so retail needs `this` to be the second of the pair.
- c2 drops (0x10782AA7, `[cand+0x40] <= 0` and fewer than 2 references): constants 2 and 4 (the two pointer-induction strides) are dropped before round 1 and are the top two free records; one use each in retail's bytes, so that drop is not a lever. Float candidates (best_score, the two real constants, two score webs, four pieces) put ten records above best_score's; none of the float spellings tried (functional cast, assignment in the comparison, named local constant, double) changes that count without changing bytes.
- Every byte-neutral rewrite of the prologue, of the fan-walk exit, of the scoring block and of the loop tail canonicalises to the same IL (same root ids, same constants): 4 differing lines on the PDB-order base, 3 on u1. `long best_start_vert = -1;` before the count (vertex, count, score) fixes both reloads like u1 does and leaves the store order as its only residue (3 lines).
- A source line that makes cl.exe spin (a duplicated `for` header) hangs q.py twice (it recompiles on SRC_FAIL); batch runs need a watchdog that kills a cl.exe older than 40 s.
- /d2inlT (60..120) and the QFE 13.10.4035 toolset give the same bytes for this row as RTM with T70; neither is the residue.
