- PeekVFOV: retail's `fld 1.0 ; fdiv Aspect ; fmul HFOV` is `HFOV * (1.0f / Aspect)`; `1.0f / Aspect * HFOV` folds to `HFOV / Aspect` (6 bytes short).
- (0x00B70A90) Bookmark blocks of a function's LAST setter run did not respond to any count ruler (k = 1..64 unused locals, 1..8 dead asserts) while earlier blocks flip at several k: the last run's ids come from a free list -- do not sweep rulers further there.

- (c2 scheduler, 0x00B6EDF0) Scheduling regions are 81 tuples cut from the START of the basic block; inline setters called on different array elements (v[i].Set...) get one base each, so every store gets a latency-0 edge to every later store of another element -- store reordering can only happen inside one element. Dump it with agentC6's t13 hook (k/t13b.py: `on = len(res) > 60`) + k/pk.py before sweeping spellings of a constant-store block.
- (bookmark rows) Split the residue first: tools/bk.py prints the load-order pattern (S/C, second pass) AND the `or` destination (state v mask register). A pure `or`-destination swap with equal S/C is a register pick, not a first-pass key wrap.
- (0x00B5CA70) A length gap of 8 bytes per site in a SetPixelShaderConstant run is `or [mem],r` (fused, 6 b) v `mov r2,[mem] / or r2,r / mov [mem],r2` (14 b): the fusion is decided before scheduling, so it is an IL / source fact, not a scheduling tie.
- (0x00B5CA70) Undecorated names in the Ego_r / FableWin name sets (`GetRotationVector`) are S_LPROC32 static helpers of the TU: if the function is uncalled in retail (rel32 scan), every call was inlined -- write the helper and call it; it moved a 24-byte residue to equal length at once.
- (0x00B5CA70) FableWin COMDAT placement: an inline helper (`?pow@@YAMMM@Z`, `@powf@8`) emitted right after a function in FableWin is first used by that TU -> use that overload (pow(float, float)), not the explicit double form; its inline chain adds PAREN tuples that move c2's 81-tuple cuts.

- (0x00B5CA70) Remaining bookmark sites after the structure is right: sweep the 7 combinations of the repo SetRenderState opt-ins x dead-assert counts 0..16 in one go (~1 s a grade, tools/swp.sh): one combo + count closed both sites; then re-place the asserts naturally and regrade.
- (wfE6-4, 0x00B783F0 / 0x00B70A90) A bookmark "or-destination register swap" is bit B, not a colouring pick: c2prio shows the 5-ref `or` destination candidate always takes edx; which VALUE is the destination follows B = [2X mod 2048 >= 2Y mod 2048] on the CSE temp ids (lk comparator log, tools/lkb2.py). Unused named locals, dead asserts and local renames do NOT move X or Y (they move only bit A): solve the needed shift first with tools/fsolve.py (F temps before every site, T temps after the last) and look for TEMP-creating structure (inline layers / helper locals), not rulers.
- (wfE6-6, bit-B rows) Insertions at or BEFORE a bad site's first-pass id are neutral for it (X and the late Y move together); only the net record change AFTER X counts, and late Y ids follow the function's total record count -- so tail text probes are the lever; measure them with one lk run (an inline-layer change in the scoped capture block moved every late Y by +2, X unchanged).
- (tools) tools/rh.sh: one line per variant with the count of REAL hunks (R text != O text; fg's identical-text display hunks dropped), OVL=<overlay> for probe overlays; tools/nf.py / nfs.sh: esp-frame + reloc masked difflib metric for big x87 rows.
- (wfE6-5, 0x00B70A90) c2 record ids come in 32-blocks per inline instance: every dead FABLE_RETAIL_ASSERT arm with a real condition and every inline helper call adds 32 to ALL later X/Y ids (position-independent); assert content does not change the count, only bit A. So bit-B residues of bookmark blocks are solved by counting asserts / inline helper layers in steps of 32 (F) plus a small Y-X gap change (T) from a code-neutral spelling (an inline clamp v a helper, a re-read of an accessor). Measure with lk, solve with the exact (F, T) table (fsolve.py's printed T ranges hide gaps), then sweep with ab.py patterns.
- (wfE6-5) A made-up inline helper in a row (GFClamp01) is not neutral: removing it (writing the code inline) shifts c2 ids by one 32-block; prefer inline code where no PDB names a helper.
- (wfE6 succ3, 0x00B6EDF0) Store-scheduling residues in unrolled vertex/struct fills are decided by c2 memory edges: setters on `p[k]` make a
  `this` temp per call (edges between setters of the same element), plain `p[k].f` stores are fully disambiguated (no cross-element edges),
  a pointer variable reassigned per element (`e = &p[k]; e->Set...`) gives "independent inside an element, dependent across elements".
  Dump the DAG once, fit prio = outdeg + H (H = max(H(succ)+1+lat)), simulate the list scheduler and search alias patterns in Python
  before spelling variants; it found the match in ~10 grades after 150 spelling grades had failed.
- (wfE6-7, bit-B rows) The late temp ids follow a WHOLE-FUNCTION record pass: deleting code after the bad site moves its late Y (Select call -51..-59, two setters -186), so any code-neutral IL change anywhere is a T lever. A named bool holding a materialised `a || b` that is only used in a branch costs 1 first-pass + 3 late records (dropping it = F -1, T -3); `bool x = false; if (a || b) x = true;` saves 1 late record v `bool x = a || b;` but hoists the 0 store into the entry block.
