# wfA4 lessons (one line each)
- (water rows) The Lionhead water passes re-author cleanly on shared headers with RenderSnow 0x00B54E30's idioms (CRenderStateScopedCaptureBlock, PeekGraphicBank->PeekGraphicInfoFrame->GetFrame with an in-row PeekGraphic body, CGraphicFrame GETTEXTURE / DTOR_FORCEINLINE): both rows reproduced their old local-model drafts byte for byte.
- (0x00B751F0) Bookmark test/or operand order there is NOT a pure whole-body count: dead-assert sweeps 0..90 move sites 3-6 together but never sites 1-2 with them, and the assert POSITION (start / between sites / after the loop) gives identical results.
- (0x00B77370) An "expanded at two sites, ??_G called at the third" split with identical c1/f at every site (sc 60) is a caller-size flip only if a+g can cross 9000 between the sites: measure a+g with tools/inl.sh first (here 4850 v 5078 -> needs +4000 tuples, not a ruler-sized gap).
- (0x00BE0EB0, 0x00B5A3F0) c2 reassociates x87 products (z*a*100/b came out a/b*z*100): source order of a one-expression helper text cannot pin it; FableWin /Od counts still choose between one-expression and split texts (27i v 31i).
- (fwsize) A FableWin helper that is 9..12 instructions where ours is 30-60 is a one-call wrapper (TransformViewToWorld -> TransformPoint, ~CGraphicFrame -> ReleaseData, C4DVector(colour) -> InitialiseFromColour): use the existing repo/overlay opt-ins for those first.
- (tools) ka.py must insert the fable_assert.h block before the first #define when the source has no fable_compiler.h include (older drafts), else every variant is SRC_FAIL.
- (stale draft port, 0x00BAA870) Re-applying stale opt-ins: grep today's repo for an opt-in with the same TEXT under a new name first (C3DMESHINFO_LODS = DETAILLEVEL, CSCOPEDSHADERSENABLE_FORCEINLINE_DTOR = _FORCEINLINE); keep every default pad verbatim under #else; wrap a default-only assert (offsetof __vftable) in #ifndef of the typed opt-in.
- (setter guards) A draft's hand-written guard before an inline setter (`bool f = true; if (ShadowMode != 1) f = false; Set(f)`) is usually the PDB setter body inlined: use the repo's PDB-body opt-in and call it with the constant (0x00BAA870: fixed the cmp operand order without the stale fitted ENABLE_FIRST).
- (bookmark test/or windows, 0x00B751F0) Per-expansion dead asserts inside SetRenderState / AddStateToUpdateList act exactly like 7 (= expansions) body asserts: the decision depends on the TOTAL count only. Map the wrong-site sets over a count sweep first: if each site's right-window is narrower than the stagger across sites, no count can close it -- stop counting and look for a structural per-site difference.
- (fwsize for counts) Measure the ROW itself with FW_EXTRA=/EHsc with and without the dead asserts: our dead arm is 18i at /Od, so a fitted count whose /Od total lands on FableWin's row size (0x00BE0EB0: 394i v 400i at k=10) is size-backed. A helper "not found" in FableWin (TransformScreenXYLinearZToWorld) means the row called the two parts itself.
- (0x00B77370) A scoped #pragma inline_depth(N) only limits the calls made in the statements it covers; a callee nested in a header body (??_G under Release) takes the header statement's state, so in-row regions cannot split it. Global inline_depth before the includes measures the nesting depth exactly (here ??_G at depth 5).
- (0x00B77370) Caller-size (a+g > 9000) inline flips can be located with dead asserts (~4 trace units each), but hundreds of asserts recolour the whole row: use it only to confirm the mechanism, not as a device.
- (0x00B5A3F0) A load/or/store where retail has `or [mem],reg` (next statement's stack load hoisted above the store in ours only) = the local is address-exposed in retail: confirm with a diagnostic opaque call taking its address before hunting for spellings.
- (0x00BE0EB0) c2 reorders a one-expression x87 product by record key whatever the source order; a named intermediate (const float x = a*b; r = x*c) pins it (two camera helper sites closed this way; FITTED, FableWin /Od +2i).
- (tools) tools/fgc.sh = fg.py with relocation-identical replace pairs dropped: prints only real hunks per variant (q.py hunk counts include masked relocation lines).
- (0x00BE0EB0) x87 parenthesisation (named == parenthesised one-expression) moves an integer instruction's schedule slot inside an x87 run one slot per level; a named camera reference local re-keys c2's commutative x87 order -- calling NEngineInternal::GPCamera-> per helper (retail reloads the global each time) fixed the product order with no fitted text.
- (0x00BE0EB0) After a header port the dead-assert matching window can shift by one (7..9 -> 6..8): always re-sweep the count after changing headers.
- (fg.py) --flags swallows every following argument (fg.py takes a[i+1:]): put --flags LAST, after --note.
- (0x00B77370) /d2inlS<N> does not move a FORCEINLINE-chain ??_G expansion (caller-size cap a+g>9000 unaffected): do not sweep it for that residue class.
- (0x00B5A3F0) A lone load/or/store v RMW hunk (a prefetch hoisted between the flags load and store) is a LOCAL register pick, not alias exposure: c2prio lists the 3-ref flags temps as dropped (local allocation over the whole branch-free block, calls included). Respell a neighbouring statement of the same block (here `x += 0.5f; T*x` -> `T*(x + 0.5f)`); k unused locals and dead asserts are byte-neutral for it.
- (0x00B5A3F0) A row calling engine/GFFloatToLongNear.h needs its own `// Retail-asm:` line (retail address + fld/fistp of the helper) or vland grades it NOT_GENUINE.
- (0x00B77370) The VC7.1 caller-size inline cap is hard-coded: c2 0x1078D1ED `cmp (g + a), 9000` (g = per-function growth counter 0x10882B58), then pen ~ (a+g)/216 joins the score. A "retail calls ??_G at the last site only" residue = retail's g was ~3500 higher: dead asserts whose condition contains an INLINE call (index < v.size()) inside a multiply-expanded helper add ~50 g per dead expansion (asserts with plain conditions add ~0); 18 in PeekGraphic closed the split.
- (0x00B77370) Read which frame a register holds from the GetFrame expansion it sits in, not from fetch order: ebx loaded at 0x00B77660 was the second frame, which reversed an earlier "stage 3 texture is wrong" theory.
- (0x00BB2540) Two 1-byte locals at adjacent bytes of one slot (retail [esp+0x84] / [esp+0x85] in a dead bool argument slot) are ONE 2-byte object: `unsigned char winding[2]` (+ FableWin SWAP<unsigned char>) packs there; two named bytes take two slots.
- (0x00BB2540) A loop-invariant member pointer hoisted into a register while a sibling member is re-read per iteration = a named local copy of the first (`const C4DVector* positions = PositionBuffer;`); its declaration position decides which callee-saved register keeps `this` across the calls before the loop.
- (0x00BB2540) Strength-reduced pointer bias (`add esi,2` then [esi-2],[esi],[esi+2]..) differs between a walked pointer (`++quad`, base at offset 0) and an indexed loop (`quads[q]`): try the other loop form when only the field displacements of one loop differ.
- (0x00BAA870) A frame-local home at an odd offset INSIDE another object's slot (efm: retail window_right at sphere+8) is a field of a by-value class copy (C2DBoxF window = ...) whose other fields stayed on x87: copying the object by value (member-wise copy ctor) fixed the whole frame map and the length.
- (tools) sd.py masks frame displacements, which also hides operand-order flips between two frame operands; use a frame-unmasked diff (wfA4 tools/rh.py) once the frame map is right.
- (0x00B77370) A local CGraphicFrame declared at the helper top (next to the first one) instead of right before its fetch fixed an x87 product order and one bookmark test/or site with identical behaviour: when count rulers (initialised locals, dead asserts) cannot reach a site, try the DECLARATION positions of the class-type locals (symbol population), re-sweeping any inline-split assert window after each.
- (0x00B77370) A cross-jumped pair of identical call tails where retail keeps two copies is a register-allocation fact (retail's constant piece spans the second path, so its pushes read `push ebp`); c2prio --trace --blocks shows the pre-RA block order and the const pieces' allowed sets -- check them before restructuring source.
- Dead asserts LOWER first-pass bookmark ids (their freed records are reused), trivial asserts at the row start raise them in 0x2000 steps per ~20: measure with the comparator trace (k/run.sh) rather than assuming a direction.
- (0x00BAA870, measured with tools/lk) A UNIFORM x87 operand-order flip across a whole section (matrix element first in retail, vector first in ours, except the x / +0 terms) = record PASS, not record count: fields first touched directly in the row body get early c2 records; +4/+8 fields first touched through an inline's `this` / reference get LATE-pass records (and the +0 field an early one). Hand-written matrix rows in the row body were the cause: the PDB inline helpers (PreTranslate after SetTranslateOnly(0,0,0), two-arg TransformPoint) gave retail's pattern at once (80 -> 42 hunks). No ruler / assert count can fix a pass difference.
- (0x00BAA870) Dead release asserts are a GLOBAL c2 record-id shift (identical bytes wherever they sit in the row; period ~158 asserts per 2048 ids here): sweep the whole period once (2 s per grade) to find the record window; then only the spelling changes relative order.
- (0x00BAA870) VC7.1 folds `x + 0.0f` and drops dead zero stores after SetTranslateOnly(0,0,0): a translation written without reading the old E4k can still be a PreTranslate / matrix-helper call (RenderBillboard 0x00B8B780 sibling idiom).
- (0x00BAA870, pass 4) An x87 product-order residue on a product of two NAMED locals (tex.Y * factor) flips when the factor variable is created BEFORE the reads of the other operand: weights computed INTO the factor variables and normalised in place (`float f = pow(...); ... f *= one_on_total;`) instead of separate weight / factor / distance locals fixed four sites at once (lk trace: factor id 449 -> 312, below the tex .Y ids 374..382). Look for the source shape that orders the records, not a ruler.
- (0x00BAA870) Measured product hash on a real trace: key = (32*f + 64*s + 48) mod 65536 with f the higher leaf id (mod 2048), s the other; flat descending sort of the sum terms. With it a wrong row order converts into an id WINDOW for one record block (here: one 32-id block earlier), which tells you at once that no global ruler (asserts / dead locals) can fix it.
- (0x00BAA870) FableWin /Od sizes of float-returning helpers (pow, GFFastOneOverSqrt, Normalise) are uniformly +1i/+3b over VC7.1 RTM: a compiler artefact, not a text difference.
- (0x00B751F0, pass 4) The bookmark test/or bit can be modelled exactly from ONE comparator trace: extract the second-sort operand keys (pairs (592,0x20040002) in k/*.json.rows, k/or2.py), split them into two per-site streams A/B (here steps 72 / 38 ids per setter), site right iff A mod 2048 < B mod 2048; asserts add the SAME amount to both streams, so a row is closable by a count only if some uniform shift satisfies every site (brute force in seconds, tools/b75model.py). If none does, stop sweeping counts: only a change of d = A1-B1 (live IL of the whole function) can close it.
- (0x00B751F0, pass 4) Named locals, declaration order, early-return vs nested-if inline texts, `default: break;`, by-value copy spellings and local renames all leave c2's record numbering of the bookmark sorts byte-for-byte identical (same sweep pattern, not even a shift): the FE normalises them. Only live-IL changes (inline header texts that CSE away, removed code) move the keys.
- (water rows, pass 4) `__assume(expr)` statements are live IL until late (unlike dead-arm asserts and dead locals): they move the bookmark d (second-sort A-B offset) by ~-1.5 per statement and fixed 0x00B77370's test/or sites 4-6 at k=60 -- a diagnostic that the missing retail fact is live IL with no code. Before proposing any device, check whether Lionhead's release ASSERT was `__assume(x)` (landed `__assume(0)` NODEFAULT rows).
- (0x00B751F0, matched) A bookmark test/or operand-order residue that dead asserts / scalar locals only SHIFT (the pass-4 A/B key model: uniform +16 per assert) moves with unused CLASS-typed locals whose inline ctor/dtor IL is expanded and folded away (CGraphicFrame: release chain): 5 unused frames at the row top closed all seven sites. Sweep k = 0..7 class-typed locals (frame / counted pointer types of the TU) before calling such a residue unreachable.
- (0x00BAA870, pass 5) A push / x87 interleave residue inside one call statement (retail `fld ; fld ; push 0 ; fmul`, ours `fld ; fld ; fmul ; push 0`) was the 81-tuple scheduling-region cut falling between the loads and the multiply: dump the regions (tools/sch.sh = wfB3 sched2/t15) and add one 0x269 PAREN tuple earlier in the region (a grouping paren INSIDE an arithmetic expression; parens around a whole call argument make no tuple).
- (0x00BAA870, pass 5) A late `mov ecx,[GPShaderRenderManager]` before a float-argument call was closed by an existing FableWin-evidenced helper text (C2DBoxF EXTENT_NAMED, 13i v 11i) that the draft never enabled: grep the overlay for unused opt-ins of every inline the statement expands before fitting parens.
- (0x00BAA870, pass 5) Normalise: the NORMALISE_LOCALS x/y/z copies put the factor first in the first scale product (`fst ; fmul st(2)`); the same Z,X,Y accumulation read from the members (new NORMALISE_SQUARED_ZXY) gives retail's `fstp ; fxch ; fmul [factor]` and keeps the squares order.
- (0x00BAA870, pass 5) c2's main record stream has GAPS (32-id blocks owned by another allocation, here 992..1055): when the product-key model says a record must sit inside a gap (side+0 in 1029..1031), no ruler can reach it -- only a change in what allocates the foreign blocks.
- (wfA4 successor-5, 0x00B77370) A bookmark LOAD-order flip at every expanded SetRenderState site of one setter run (first operand sort) closed with N dead asserts placed BEFORE the run (helper top): the statement COUNT moves the records (condition size irrelevant, `this != 0` folds); the window is narrow (78..94 here) and interacts with unused-frame rulers; asserts inside a multiply-expanded inline (PeekGraphic) move g instead.
