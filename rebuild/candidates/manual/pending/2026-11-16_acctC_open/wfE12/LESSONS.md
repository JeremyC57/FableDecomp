# wfE12 lessons (agentE12)
- Static-initializer rows (`_$E1`, 0x0121xxxx): find the table name in the Ego_r / FableWin `dynamic initializer for '<Class>::<Member>'' set, the member's access / const / bound in the Anniversary PDB LF_STMEMBER (llvm-pdbutil dump -types into a scratch file, then grep), and the element layout in struct_layouts_egor.tsv; the natural aggregate / constructor list then matches on the first or second grade.
- Pointers to member of a class only forward-declared at the member's declaration are 16 bytes (unspecified inheritance); a null one is {0,0,0,-1}; VC7.1 aligns them to 8 (a {PMF,PMF,CCharString} struct is 40 bytes). Declare the struct in a header included BEFORE the class's own header.
- Handler tables: map slot -> name from an enum in the Anniversary PDB (EGameEventType) or from the entry's literal (OPINION_REACTION_TYPE_X -> XUpdate / XIsRunnable), never by zipping retail address order with donor order (TLC reorders functions: 0x0062A180..0x0062BEF0).
- Allocator -> class: read the Alloc body's first `mov [esi], vtable` (follow a tail jump into the ctor), then COL (vtable-4) -> TypeDescriptor +8 name (tools/allocrtti.py).
- A literal passed to a `const CCharString&` parameter (implicit conversion through the defaulted-length ctor) emits `lea eax,[temp]` before the copy; an explicit CCharString("...") passes the ctor's returned eax (different bytes).
- q.py masks call targets: check `objdump -dr` of the row's obj (or vland RELOC_CONFLICT) when a callee could be inline vs out of line. An inline user-declared destructor gives direct member-destructor calls in $E1 and an out-of-line copy for the vector destructor iterator in $E2.
- (0x00C4F600) A data/this reload register rotation inside a few switch cases is the CODEGEN rotation (expression temps, c2prio_f.py --rotation), not the global colouring: count the rotation temps between the last block where both builds agree and the first wrong one; a state that resynchronises later (a busy register skipped) confines the hunks. Callee bodies, IsEqualGUID, /Oa and a named deferred flag do not move it.
- (0x00C4F600, c5) A memory parameter pushed as a call argument always takes a rotation temp (its load may later be deleted as redundant when a preceding `mov eax,[p]; test eax,eax; js` deferred-bit test already loaded it); that test load itself is not a rotation temp. c2prio_f.py's TEMP_EXIT args [esp+0x24]/[esp+0x28] identify push tuples (word 3 0x2004010d). One extra temp laid out before a block shifts every later reload by one register until a busy-register skip resynchronises.
- Registration tables (state-group / TC lists) pass strict headers by #including every engine/<Class>.h: the AI state-group headers compose once FABLE_RETAIL_CAISTATEGROUPBASE(+_MEMBERS) and FABLE_RETAIL_CINTELLIGENTPOINTER are on; missing statics come from an additive opt-in in default-path text, asserts pinned (0x0121F86F).
- (0x00C4F600, fourth pass) WF_RULES devices c (k unused named locals) and d (dead release asserts, even with &param in the dead arm) are byte-neutral for a CODEGEN-ROTATION residue (expression temps, c2prio --rotation): they re-key c2 record numbers / conditional-temporary bits, but the dead arm is deleted before code generation and the rotation counts temps in codegen order. Use them only for record-count ties (operand order, test/or order) or flags-word entry stores; measure the rotation first.
- (0x00C4F600) Diagnostic removal of the cases laid out between two divergent rotation points (listener NONE / ALLPARAMETERS) is a cheap way to prove which statements take rotation steps; an address-taken parameter does not make c2 CSE two loads of it across a branch.
- (0x00C4F600, c7) A one-step rotation residue across N look-alike switch cases can be confirmed cheaply by permuting the cases in source: if a permutation gives retail's registers but layout follows source, the missing fact is one rotation temp before the first case (VC7.1 neither moves case blocks nor cross-jumps a duplicated x87 case body into a fall-through).
- 0x00C4F600 (agentE12f): c2 copy-propagates any local copy of a by-value parameter (block, top, all uses), so a named copy never changes the parameter's pieces or the codegen rotation; do not spend grades on it.
- (0x00C4F600, agentE12g) A 2-reference split piece of a PARAMETER can never be coloured (spill = 2 per ref minus the parameter home-store charge, -4 measured with two entries); a residue that needs such a piece in a register (e.g. a pushed parameter with no rotation temp) has no closer in reference counts of that piece -- prove it with c2prio --trace before spending grades.
- (0x00C4F600, eighth pass) VC7.1 c2's temp assigner 0x10775acc skips the eax/ecx/edx rotation only for (a) a temp whose descriptor already holds a register, (b) opcode-1 copies from a REGISTER operand (kind 1), (c) opcode 0x12 on a parameter with a register link (+0x34); a push of a memory-resident parameter always rotates (line breaks / one-line ifs do not matter). tools/c41/c2prio_g.py prints each request (REQ) in --rotation.
- (0x00C4F600, ninth pass) Build a micro reproducer before spending row grades on a c2 allocation residue: a ~60-line TU with the row's case mix (here 12 long + 8 float cases, a memcmp case, the same tail) reproduced the row's exact tail bytes and rotation in 7 s per probe (probe/m3, tools/mrun.sh); float cases (`fnstsw ax` clobbering eax) are what turned a coloured parameter piece into `split, memory`. Varying the micro shows which source facts move the allocation; tail spellings that fold in the micro fold in the row.
- (0x00C4F600) An expression-temp rotation step can come from a pushed argument: an out-of-line helper call adds one (its argument temp) while the same helper forced inline is byte-identical; the thiscall object of a call never takes a rotation step (global / cast / static-member diagnostics all neutral).
- (0x00C4F600, tenth pass) In the micro reproducer the pushed parameter loses its register piece because of eax-clobbering x87 compare blocks (fnstsw ax) placed right before the tail in source order and the constant-threaded entries into the deferred-test block; moving those blocks or entries changes layout, so for a row whose case order equals its layout this is not a source lever -- check case-order freedom first before spending grades on spellings.
- (0x00C4F600, E12k) Before parking a near-miss with switch tables, compare the tables BY TARGET (obj dir32 relocs v retail words): q.py/fg.py show our table words as zeros. A temp-adding statement that fixes a rotation only helps if c2 can cross-jump its whole block away; check which instruction blocks the merge (here an id register piece shared with the switch head).
- (0x00C4F600, E12l) Forcing priority / spill (C2_FORCEPAIR + a +0x40 write, tools/c41/c2prio_h.py) on a 2-ref piece marked "forwarded, not listed" leaves the object unchanged: c2 may report a register (even one an interfering value holds) that never reaches code, so it is not a valid test of "what if this piece were coloured".
- (0x00C4F600, E12m) A switch case whose block retail cross-jumped into another case's tail (NONE -> EXCLUSIONPARAMETERS' `mov bl,1 ; jmp`) is NOT the same as writing that case as a fall-through into a shared `changed = true; break;`: the fall-through removes an IL block / entry edge and moves the whole global allocation (9204 -> 9504); keep separate case bodies and let c2 cross-jump them.
- (0x00C4F600, E12n) Before chasing 'retail pushed a tested parameter without a rotation temp', look for a matched sibling that tests the same bit and forwards the same parameter to a call and probe its rotation events; the EAX setters here all end in Commit() (no forwarding), so the model has no sibling evidence. A cross-jumped duplicate can only supply a missing rotation step if its temp lands on the CURRENT pointer register; a copy that must match a tail whose temp sat one register later always overshoots by one.
