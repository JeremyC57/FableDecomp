# Original-name recovery: evidence and limits

This report accompanies the address-level names audit, not a claim that every source identifier was recovered. The final accepted delta and exact current hashes are in `baseline_audit/added_since_claude.tsv` and `names_audit/accepted_delta_coverage.tsv`. The names audit covers every newly accepted address since Claude's commit `fbfaf9f90`, including early work before numbered rootbatch30. Historical payload variants and withdrawn rows are indexed separately; they must not be counted as additional completed functions.

## What was recovered

Donor PDB exports preserve original class, namespace, function, template and many member spellings. They often preserve decorated return/parameter types, constness, access and calling convention. The retail executable is a different build. Mapping a donor name to a retail address requires native callers, RTTI/hierarchy, literals, member accesses and relocation targets; a matching number or a propagated function label is insufficient. The recovered code contains native layout projections because donor STL container widths and editor-only interfaces differ.

Generated `_padding_` / `_pad*` layout records are not recovered original member names. They may be retained for layout evidence and must not be counted as named variables.

**Original local-variable names were not recovered.** Stack temporaries, loop variables, dependency-spy names, convenience globals and most native view/helper names are authored descriptions. `NOT_RECOVERED` in the per-function index is intentional. A class member proved by a PDB layout is a recovered variable name; it is not proof of an original local name or of the same offset in every build.

## Recovered member names and native layout mapping

`NEnginePrimitiveManagerRepeatedStaticMeshes::CAddMeshDesc` provides a particularly concrete example. Root194 checks all17 donor layout records, size104, and preserves original spellings: `MeshInfo`, `MaxScale`, `VectorNormals`, `ObjectCount`, `SubSections`, `BoundingBox`, `BoundingSphere`, `FadeDist`, `ObjectOffsets`, **`ObjectMatricies`** (original spelling), `EnginePrimitiveFlags`, `AlphaRef`, `AlphaMipBias`, `Persistent`, `EPFFlags`, `WindDelayArray`, `WindScaleFactor`. Donor offsets0,4,8,12,16,20,44,60,68,72,76,80,84,88,92,96,100 are retained in the native descriptor projection. The target's actual accessed fields and ABI are audited; unused descriptor members are not claimed to have independent dynamic coverage merely because the whole layout is represented.

For the particle managers, PDB members such as `VertexShadersBillboardSpritePointLights`, `VertexShadersCrossedSpritePointLights`, `VertexShaders3DFaceMeSpritePointLights`, their displacement handles, `PixelShader`, `PixelShaderStipple`, `PixelShaderDisplacement`, `VertexBuffer`, `IndexBuffer` and `ConstantBlock` are preserved. The line owner uses `VertexShadersLinePointLights` and `VertexShaderDisplacement`. Native12-byte arrays, versus donor16, place SpriteGroup VertexBuffer/IndexBuffer at60/94 hex and LineGroup at38/6C hex. Root196's26 layout records include unnamed padding records; **26 is not a count of recovered named variables**.

For primitive/scene work, original members include `EnginePrimitiveFlags`, `AlphaMipBias`, `FadeDistance`, `OcclusionLayerBitMask`, `GridCell`, `PreloadStat`, `RenderLayerMask`, `NextPrimitive`, `RefPrimitive`, `NextLayerMask`, `RefLayerMask`; scene/grid/map names are checked against `ghidra_out/struct_layouts_egor.tsv`. Native offset assertions verify the representation used by the compiled target. Iterator helper names and the decomposed native tree/vector views are authored, and are not asserted as the exact original source type definitions.

The underlying lifetime models were also reconciled: original `IVRefCount` storage is unsigned, while pointee Release/GetRefCount methods return signed long and Delete is const. Counted-pointer callback blocks have refcount0/callback4/data8; intelligent-pointer observer blocks have object0/refcount4. Original member spellings and these independently audited native offsets must remain distinct from convenient host-fixture storage.

## How to continue without propagating bad names

Read the final accepted-address index before assigning a completion status. Open the cited source variant and matching review; old payloads can preserve incorrect labels even when a later variant is accepted. Use exact decorated PDB signatures and native RTTI/call relationships before renaming a canonical owner. Keep unknown helpers, globals, enums and locals explicitly descriptive. Preserve older evidence and record a separate metadata/source correction rather than silently rewriting history.

The automated member-name index records spelling co-occurrences with exact donor layout lines. It does not prove every native offset. The automatic name-proof search can miss evidence already present in a manual audit; unresolved lookup categories mean manual mapping is still needed, not proof that the function can never be named. Pending worker RECOVERED_NAMES files are quoted claims with evidence links, not promoted to independently accepted results.
